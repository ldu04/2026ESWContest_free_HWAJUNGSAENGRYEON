# D1 리허설 드라이런 — 소프트웨어 완주 확인 (2026-08-30)

실제 런 전에 **소프트웨어가 732초를 끝까지 처리하는가**만 본다. 하드웨어는 쓰지 않았다.

## 입력 — 대본 B

점화점 **(0.02, −0.11) m** 에서 퍼지는 **원형** 전선, **1.100 mm/s**, 명목 20 cm 격자.
`gateway/mock_fw_serial.py` 는 직선 전선만 만들 수 있어 **방사형 옵션(`--origin`)을 추가**했다.
기본값은 그대로라 기존 동작·회귀는 불변이다.

    python gateway/mock_fw_serial.py --origin "0.02,-0.11" --speed 0.0011 \
           --p0-offset -0.14485 --warm-scale 0.09 --t-max 760 --fake 1 \
           --out results/dashboard/d1_scriptB.jsonl

`--p0-offset -0.14485` 의 근거: 온도 램프가 전선보다 **앞서** 임계를 밟는다.
`warm_scale·ln((peak−ambient)/(threshold−ambient)) = 0.09·ln(275/55) = 0.1449 m` = **131.7 초**.
이걸 보정하지 않으면 16개 사망이 전부 131초씩 이르다. 물리(램프 모양)는 그대로 두고
**전선 시작 위치만** 옮겨 임계 통과 시각을 설계값에 맞췄다.

결과: **사망 16/16, 설계값과 최대 1초 차.**

## ★ 발견 — 마지막 3개 노드는 사망이 확정되지 않는다

**16개가 죽었는데 DC(사망확정)는 13개다. 누락: id 11(601 s) · 14(631 s) · 15(732 s).**

원인은 결함이 아니라 **구조**다. 사망 확정에는 `K_CONFIRM = 3` 명의 관측자가 필요한데,
그 시점에는 살아 있는 노드가 그만큼 남아 있지 않다.

| 죽는 노드 | 그때 살아있던 격자 노드 | 관측자로 쓸 수 있는 수 |
|---|---|---|
| id 11 (601 s) | 11, 14, 15 | 자신 제외 **2** |
| id 14 (631 s) | 14, 15 | **1** |
| id 15 (732 s) | 15 | **0** |

**파라미터를 고치지 않았다.** `K_CONFIRM` 을 낮추면 이 숫자는 좋아지지만,
그건 4장에서 하지 않겠다고 쓴 일이다(결과가 나빠도 유리하게 바꾸지 않는다 — 기록만).

### 예측 등록 — 실물에서는 14/16 일 것이다

모의 생성기에는 **브리지가 없다.** 실물에서는 브리지(id 99)가 죽지 않고 관측자로 1표를 더 낸다:

|---|---|---|---|
| id 11 | 2표 | **3표** | 확정될 것 |
| id 14 | 1표 | 2표 | 미확정 |
| id 15 | 0표 | 1표 | 미확정 |
