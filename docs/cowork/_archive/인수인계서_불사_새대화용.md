## 2. 프로젝트 한 줄 정의

> **실패 패턴을 데이터로 쓰는 자가치유 산불 감시 메시.**
> 노드가 불에 타 죽는 것을 "고장"이 아니라 **측정값**으로 취급한다. 죽은 시각·위치를 모아 **화선의 진행 방향과 속도**를 역산한다.

**수학:** 노드 사망시각 = 불 도착시각. (x, y, t_death)에 **국소 평면 최소제곱 적합** → 도착시각장의 기울기 ∇T.
- **방향 = ∇T/|∇T|** → 튼튼함(정규화라 노이즈에 강함). **현재 2.1°**
- **속도 = 1/|∇T|** → **역수라 노이즈가 증폭됨. 여기가 남은 약점.**

**하드웨어:** Arduino-ESP32 + **painlessMesh**(`getNodeTime()`으로 메시 시간동기 → 클럭 드리프트 이미 처리됨) + DS18B20 온도센서 + WS2812 LED + 라즈베리파이 게이트웨이(Python, 시뮬 estimator 재사용). **16노드 ≈ 449,760원.** 부품 도착 대기 중(~1주).

## 4. 현재 상태

### 4-1. 시뮬레이터 — 거의 완성, 속도만 남음

**해결된 것:**
- **오탐 Type A = 측정 전 구간(통신두절 0.30까지) 0%.** 원래 0.20에서 생기던 breakpoint가 Fix A로 **소멸**했다.
- **방향 정확도 2.1°** (16노드 기준). 노드 밀도별: 9→4.32° / 12→2.9° / 16→2.12° / 25→1.23°. **12개 이상에서 안정 밴드.**
- **비화재 사망 누수 차단(#2e-1 → #2e-2 → Fix A):** 찬(COOL) 비화재 통과율 **86.4% → 0%**. 적대적 8개 주입 시 방향 오차 **15.74° → 2.70°**, 속도 오차 31.8% → 2.08%.
- 클럭 지터 300ms에서도 방향 2.13° → 안전.
- 272개 요약 셀 중 250개 불변, 변한 22개 전부 개선. 비용은 커버리지뿐(baseline에서는 0).

**미해결 = 유일하게 남은 약점: 속도/ETA.**
- S2a(바람) **29.9%** / S6(9노드) **34.5%** / S7(복합최악) **26%**.
- 지금 진행 중인 작업이 이것 → `구현지시서_2e3_속도_시간적추적.md`

**#2e-3 요약 (지시서 이미 전달 완료, Claude Code 착수 대기):**
- **Step 1 진단부터(코드 불변).** ①부호 포함 오차 분포 ②**환원불가 하한(floor)** — 실제 화선 속도는 시간에 따라 진짜 변하니까 단일 숫자로 요약하는 순간 못 넘는 바닥이 있음. floor가 오차의 70% 이상이면 **거기서 멈추고 "물리적 한계"로 정직하게 기록** ③오라클 절단으로 노이즈 원인 특정 ④지표를 **ETA 오차(초, 전방 30/60/100m, 부호 포함 + 위험측 예측 비율)** 로 재정의
- **Step 2 후보:** A **역수 제거** (화선 축좌표 s를 사망시각 t에 회귀 → 기울기가 곧 속도, 나눗셈 없음) ← 제일 먼저 / B 시간창 추적(시간가변 속도·가속도) / C **dT/dt 물리 역산** `v = L·(dT/dt)/(T−T_amb)` ← **단, 시뮬레이터 온도 생성식을 되돌리는 tautology 위험 있어서 L 미스매치 ±20/30/50% 시험 통과해야만 채택** / D 역분산 융합
- **E = 실패해도 건지는 산출물:** 검증된 **속도 신뢰구간**. 그러면 "ETA 4:12" 대신 **"ETA 4~6분(90% 구간)"** 으로 쓸 수 있음. 어느 것도 개선 못 내도 이것만 채택하고 종료하는 게 **정상적 성공**으로 규정해뒀음.
- **보너스:** 속도 추정치가 생기면 `dtdt_gate=False`로 잠가둔 Fix B(dT/dt 게이트)의 "속도 ≥0.8 m/s에서만 유효" 한계가 사라져 2차 방어선으로 승격 가능.
- **바람 융합은 뒤로 미뤘음.** 외부 데이터 필요(기상청 무료 API는 임상 아래 국지풍 대비 시공간 해상도가 너무 거침 / 풍향계 달면 BOM 증가), 노린 효과는 바람 조건의 방향 흔들림뿐, **그리고 탁상 데모로 증명 불가**(선풍기는 열 기둥을 흩뜨릴 뿐 통제된 바람 주도 화선을 못 만들고, "융합"을 증명하려면 그 바람을 측정해 estimator에 먹여야 함). → **발전방향 문단으로 기재.**

### 4-2. 보고서 PPT — 초안 완성 (19P)

`불사_개발완료보고서_초안.pptx` / 소스 `build_full_deck.js`.

**스타일 = "B+ (라이트 에디토리얼 + 노드 필드)"** — 사용자가 4개 표지안 중 B를 고르고 C의 노드 디자인 아이디어를 결합. 표지의 "불 진행 방향" 화살표·글씨는 **사용자 요청으로 제거**("살짝 짜치다").

ASH 6B6E6A · PAPER FBF9F4 · LINE E2DCD0 · TINT EEF3E6 · AMB FBEFE2 · 맑은 고딕 · LAYOUT_WIDE

### 5-3. 절대 금지 목록
- **속도는 "보수적/안전 마진"으로만 서술.** 정밀도 주장 금지.
- **의성 화재는 동기·삽화로만.** "우리가 있었으면 막았다" 같은 반사실 금지.
- **재라우팅 지연시간(100ms) 인용 금지** — 그건 시뮬 틱 값이지 실측이 아니다. 실측 전엔 쓰지 않는다.
- 시뮬 전용 이득을 실물 성능처럼 쓰지 않는다.
- 나쁜 결과·미스매치 실패 은폐 금지.

### 5-4. measure-first 규율 (Claude Code 지시서에 매번 넣을 것)
1. 시드 고정. 결과 좋아 보이게 파라미터 튜닝 금지 — 기록만.
2. 임계값은 **물리 또는 baseline 분포에서, 테스트 점수 보기 전에** 도출. 도출용/평가용 데이터 분리 명시.
3. 원본을 **항상 baseline으로 보존**하고 나란히 비교. 헤드라인 조용히 갈아치우기 금지.
4. **S1~S11 전체 재실행**으로 비열화 증명 + **세기0 회귀 동일성** + pytest.
5. **방향이 나빠지면 불채택** (방향이 우리 헤드라인).
6. **null 결과도 그대로 보고** — 내 가설이 반증돼도 그렇게 쓴다.

## 6. 여태 밟은 검증 체인 (왜 이 결론에 왔는지)

`#2c` 클럭지터 안전 확인 + **비화재 사망 오염 발견** → `#2d` 교차검증 3분기 설계(물리 근거: "불에 타 죽으려면 자기 온도가 올랐어야 한다") → `#2e-1` **오분류율 대신 '해악'을 측정** → **내 가설이 반증됨**(COOL이 잘 방어될 거라 예측했는데 실측 통과율 86.4% > HOT 72.5%, #2d가 막은 건 2.9%뿐) → 누수 경로를 `[D-030]` 관대 채택으로 특정(COOL 누수의 98.9%, residual 7.0s vs 게이트 2.0s, 관대 채택이 보호한 정당한 사망은 5992개 중 3개뿐) → `#2e-2` Fix A(엄격) vs Fix B(dT/dt) 나란히 측정 → **Fix A 채택**(새 파라미터 0개, 속도 의존 없음). Fix B는 `dtdt_gate=False`로 보존.

**보고서에서의 서사:** "발견 → 진단 → 해결"의 완결 구조로 슬라이드 13에 배치. 이게 공학 성숙도 어필 포인트다.

### Claude Code 쪽에서 스스로 신고한 이슈들 (전부 정직하게 처리됨)
- 오염률 정의가 정당한 화재사망을 과다 계상 → 88.3% → **74.4%**로 정정(컬럼 추가만).
- S4/S5/S6가 게이트 변경과 **동시에 30시드로 재실행**됨 → 표에 주석 명시.
