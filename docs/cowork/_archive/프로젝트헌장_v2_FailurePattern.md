# 프로젝트 헌장 (v2 · 확정) — Failure-Pattern-as-Data Self-Healing Mesh
### 제24회 임베디드SW경진대회 자유공모 / 예선 마감 2026-09-03

---

## 0. 한 줄 정체성

> **본체(아키텍처):** 재난 현장에서 **노드 파괴는 필연**이다. 우린 그것을 *막으려 하지 않고*, **노드들이 죽는 시공간 패턴을 재난 확산 동역학 데이터로 전환**하며, 파괴되는 와중에도 통신망은 **스스로 복구(자가치유)**한다.
> **데모 앵커:** 산불 최전선 — 순차로 타 죽는 노드들의 패턴에서 **불의 확산 속도·방향**을 읽고, 노드가 파괴돼도 남은 망이 계속 전송.

**핵심 문장(30초):**
"재난에선 센서가 파괴되는 걸 막을 수 없습니다. 기존 시스템은 그 파괴를 '막아야 할 손실'로 봅니다. 저희는 뒤집습니다 — **어디서 어떤 순서로 노드가 죽는지, 그 패턴이 곧 재난의 확산 지도**입니다. 그리고 노드가 파괴돼도 망은 스스로 복구해 데이터를 계속 내보냅니다."

**작품명 후보:** `PhoenixNet` · `불씨(BULSSI)` · `LastGasp`
> 팀명 규칙: 20Byte(한글 10자) 이내 / 띄어쓰기·특수문자·"테스트" 불가 / 영문 대문자 / 끝에 '팀' 불가.

## 1. 독창성은 "시나리오"가 아니라 "아키텍처"에 있다 (★ 흔들리지 말 것)

- 기존 모든 시스템의 패러다임: 노드/장비 파괴 = **손실·단절(불량)** → 막거나 무시.
- 우리 패러다임: 노드 파괴 = **시공간 데이터로 승격 + 망 자가치유.**

→ 그래서 **시나리오(산불)에서 억지로 새로움을 짜낼 필요 없음.** 산불 감시 자체는 드론·위성이 이미 함. 우리 독창성은 **"고장을 패턴 데이터로 쓰는 아키텍처"**이고, 이건 응용과 독립적으로 신선함.

**범위 감점 방지 3단 구조:**
```
[1단 플랫폼(넓게)]  재난 고장-패턴-데이터화 자가치유 메시 아키텍처
      │
[2단 앵커(진짜 하나)] 🔥 산불 최전선  ← 실제 대형 재난, 30초 시각적, 대중 공감
      │
[3단 확장(한 줄)]   실내 화재·가스누출·붕괴에 "같은 구조" 확장 가능 (발전가능성)
```
> ⚠️ 플랫폼·확장을 너무 빨리·많이 나열하면 "하나도 제대로 안 했는데?" 감점. **산불 하나를 완벽히 + "같은 구조 확장 가능" 한 줄.**

## 2. ★ 코어 업그레이드 — "Failure"가 아니라 "Failure *Pattern*"

**심사위원 최종 보스:** "노드 하나 죽는 순간은 정보량이 적잖아요. 그냥 온도(70→80→90→100)를 계속 보내면 되지, 왜 '죽음'을 써요?"

**방어 (이게 핵심):**
1. **개별 죽음은 정보가 적지만, 죽음의 *패턴*은 정보가 크다.** 어느 노드가 어떤 순서·위치·시각으로 죽는지(시공간 시퀀스)는 재난의 **확산 속도·방향·종류·남은 노드 생존시간**을 담는다. 개별 온도(로컬)로는 재구성하기 어려운 **전역 동역학.**
2. **필연성:** 재난에선 노드 파괴가 *피할 수 없다.* "안 죽게 만들면?"이 아니라 "막을 수 없는 파괴를 데이터로 전환"이 철학. (방열재로 막기 → 우린 활용하기.)
3. **규모·전력:** 초저가 대량 노드는 상시 스트리밍 불가 → 실패 이벤트가 실용적 sparse 신호.

→ "Failure as Event(약함)"를 **"Failure Pattern as Data(강함)"**로 승격시키는 게 상위권으로 가는 열쇠.

## 3. 시스템 아키텍처

```
[초저가 노드 ×12 (ESP32 + 온도센서 + 배터리)]
        │  평소 저전력 / 하트비트
        │  임계(≥80℃) 감지 → Last-Gasp 패킷(id, 좌표, 마지막값, t) 후 사망
        ▼
[자가치유 라우팅]  이웃 침묵 감지 + 교차검증 → 죽은 노드 우회 재라우팅(<300ms)
        │           죽음을 '손실'이 아니라 '1급 이벤트'로 승격
        ▼
[Sink(라즈베리파이)] → [Failure-Pattern 분석 + 대시보드]
        ├─ 자가치유 토폴로지 실시간
        └─ 죽음 시공간 패턴 → 확산 속도·방향 벡터 + 남은 노드 생존시간 예측 + (확장) 재난종류 추정
```

**4대 SW 모듈(우리 코드 = 프로젝트의 주인공):**
1. **Last-Gasp** — 임계 감지 → 임종 패킷.
2. **Failure-as-Event 자가치유 라우팅** — 죽음을 1급 이벤트로 처리(우리 차별점).
3. **★ Failure-Pattern 분석** — 죽음 시퀀스 → 확산 속도·방향·생존시간 예측(코어 가치).
4. **실시간 대시보드** — 토폴로지·자가치유·확산 지도.

## 4. 차별화 & 드론 방어

| | 기존 재난 WSN/Mesh | **우리** |
|---|---|---|
| 노드 파괴 | 막거나(방열) 무시 | **패턴 데이터로 승격** |
| 데이터 | 살아있는 값 스트림 | **죽음 시공간 패턴 = 전역 동역학** |
| 라우팅 | 죽으면 단순 우회 | 죽음을 1급 이벤트로 + 자가치유 |

**"드론으로 보면 되잖아요?" 방어 (경쟁 아니라 역할분담):**
> "드론·위성은 **상공 개요 레이어**입니다. 강풍·야간·수목 아래(지표화)·농연에선 초단위 지표 전선을 못 잡고, 드론이 현장 통신 백본이 돼주지도 못합니다. 저희는 지표에 뿌려져 **실시간 전선 좌표 + 소방대·기지국을 잇는 지상 통신/센싱 백본 레이어**입니다. 드론을 대체하는 게 아니라, 드론이 못 보는 지표의 빈자리를 채우는 **상보적** 아키텍처입니다."

## 5. 데모 설계 (6주 국소적 성공)

- ESP32 노드 12개 격자 배치.
- 순차 사망 트리거: 열원(헤어드라이어)으로 임계 유발 → Last-Gasp 발동(실기능), 또는 스위치(백업).
- 눈앞에 보이는 것: ① 불 전선이 격자를 가로지름(죽는 순서) → ② 죽은 자리 우회 **자가치유** → ③ 죽음 패턴에서 **확산 속도·방향 + 생존시간 예측** 실시간 갱신.
- 정량 지표: "노드 N개 사망에도 전달률 X%, 재라우팅 Y ms, 확산 속도·방향 추정 오차."
- (LED는 시연 시각화 보조 — 실기능 아님. 진짜 관제는 대시보드.)
