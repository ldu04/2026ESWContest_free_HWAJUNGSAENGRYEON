# 구현지시서 2.J — 실측 τ 방향 강건성 재검증 + 미탐지율 피크온도 스윕
### 「불사」 · τ 실측(11s/78.5s) 이후 두 개의 정직성 검증 · 전부 시뮬(열원 불필요)

> **왜 지금 이걸 하나:** H1 τ 실측에서 τ가 우리가 검증해둔 울타리({0,2,5,10}s)를 벗어났다(강제대류 11s, AC-on "정지" 78.5s). 그래서 **두 가지를 아직 실제로는 모른다**: (A) 실측 τ에서도 우리 왕관 보석인 **방향 2.1°가 버티나?** (B) 2.I-a의 "τ 크면 미탐지" 걱정이 **현실 불 피크온도에서도 그대로인가?** 둘 다 사용자(팀장)가 대화에서 직접 제기한 정당한 의심이고, "안 흔들린다"를 **측정으로** 답해야 한다. 드라이기 없이 돌아가는 순수 시뮬 작업.
>
> **역할:** 시뮬 구현·실행 = Claude Code / 사전등록 예측·해석·정직성 감사 = 나(Cowork) / 결과 판정·다음 수 = 사용자.
>
> **강령(필수 준수):** ① 측정 우선 — 예측이 틀리면 **틀렸다고 기록**하고 넘어간다(§5.6·P4a 전례). ② **자기채점 금지** — "시뮬 생성기를 그대로 뒤집어 맞추는" 동어반복(tautology)은 점수로 세지 않는다. ③ **체리피킹 금지** — 우리에게 유리한 피크/조건만 고르지 않고 **표면 전체**를 보고한다. ④ 결과가 우리 주장에 불리하게 나와도 **그대로** 올린다.

## 파트 A — 검증①: 실측 τ에서 방향(direction) 강건성

### A-0. 배경 (왜 방향이 구조적으로 강한가 — 하지만 아직 안 쟀다)
방향은 죽음시각들의 **기울기(gradient = 공간에 걸친 death time의 차이)**에서 나온다. τ가 모든 노드에 **균일한 상수 지연**만 준다면, 그건 모든 death time에 같은 값을 더하는 것 → 차이(기울기)에서 상수가 상쇄되어 방향은 원리적으로 불변이다.

**그러나** 지난 P4a 교훈(내가 틀렸던 건): **균일 τ도 곡선 전선(curved front)에서는 노드마다 온도상승률(dT/dt)이 달라, threshold 교차 지연이 노드별로 불균일해진다** → 기울기 오염 → 방향 열화. 작은 τ({0,2,5,10}s)에선 그 열화가 작아 2.1°가 버텼다. **τ=78.5s에서도 버티는지는 한 번도 안 쟀다.** 이 파트가 그걸 잰다.

### A-1. 사전등록 예측 (내가 지금 박아두는 것 — 틀리면 틀렸다고 기록)
- **예측 A1:** τ가 커질수록 방향오차는 **단조 증가**한다(P4a 메커니즘). 하지만 **붕괴(예: >10°)하지 않고**, τ=78.5s에서도 대략 **한 자릿수 도 이내**에 머문다 — 왜냐하면 오염은 "dT/dt 불균일"이라는 **2차 효과**일 뿐, 상수 지연 성분은 여전히 기울기에서 상쇄되기 때문.
- **예측 A2:** **노드별 지터 τ**(제조 편차)가 **균일 τ보다 방향을 더 많이** 망친다 — 지터는 상수 상쇄가 안 되는 진짜 랜덤 오염이므로.
- **정직성 경고:** 이건 어디까지나 예측이다. §5.6·P4a에서 내가 부호·방향을 두 번 틀렸다. **직관 믿지 말고 측정치를 그대로 보고하라.** A1이 깨지면(예: τ=78s에서 방향이 실제로 붕괴하면) 그건 프로젝트 코어에 대한 **진짜 경고**이므로 절대 숨기지 말 것.

### A-2. 실행 스펙
1. **기존 방향 estimator 재사용**: 평면 최소자승 적합(planar least-squares) → ∇T → direction = ∇T/|∇T|. 손대지 말 것.
2. **센서 지연 τ 주입**: 각 노드의 참 공기온도 시계열에 1차 지연(first-order lag)을 씌운 뒤 threshold 교차로 death time을 잡는다.
   `T_sensor += (T_air − T_sensor)·(dt/τ)` (τ→0이면 즉시=지연 없음).
   - death 판정 threshold는 **현재 시뮬이 쓰는 값 그대로**(바꾸지 말 것; 바꾸면 A와 B 사이 변수 오염).
3. **τ 스윕(두 계열):**
   - **균일 τ**: `{0, 2, 5, 10, 11, 20, 30, 50, 78.5, 100}` s. (실측 두 점 11, 78.5 반드시 포함; 100은 무풍 최악 추정 상한.)
   - **노드별 지터 τ**: 평균 μ ∈ `{11, 30, 78.5}` s, 각 노드 τ_i ~ μ·(1 + N(0, 0.3)) (30% 표준편차, 하한 0.5s 클립). 시드 5개 평균.
4. **전선 조건**: **곡선 전선을 반드시 포함**(직선 전선만 쓰면 P4a 효과가 숨어 결과가 낙관 편향된다). 기존 2.G/2.H에서 방향 열화를 봤던 그 조건을 재사용. 직선 전선도 대조군으로 같이(곡률 효과 분리용).
5. **출력:**
   - `τ vs 방향오차(도)` 곡선 — 균일/지터, 곡선/직선 각각. CSV + 그래프.
   - 각 τ에서 **몇 개 노드가 death를 아예 못 찍었나**(미탐지 노드 수)도 같이 기록 → 파트 B와 연결.
   - **판정선**: "방향오차 ≤ 5°"를 우리 실용 허용선으로 잡고, τ가 어디서 이 선을 넘는지 명시.

### A-3. 정직성 체크(제출 전 자문)
- [ ] threshold·전선·노드배치를 A에서 **바꾸지 않았나**(동어반복/변수오염 방지)?
- [ ] 실측 두 점(11, 78.5)이 스윕에 **들어갔나**?
- [ ] 예측 A1/A2와 **실제 결과가 어긋난 지점**을 본문에 그대로 적었나?
- [ ] 곡선 전선을 뺐거나 직선만 써서 결과를 좋게 만든 건 아닌가?

## 파트 B — 검증②: 미탐지율 × 불 피크온도 스윕

### B-0. 배경 (사용자가 옳게 짚은 완화 요인)
2.I-a의 "τ/펄스폭 > 1.2배부터 미탐지, 3.5배에서 100%"는 **어떤 특정 피크온도**를 가정하고 나온 숫자다. 사용자 지적: **불이 뜨거울수록(피크 높을수록) 고정 임계선(80℃)을 τ의 이른 구간에 밟으므로 굼뜬 센서도 탐지한다.**
1차 지연에서 임계 교차 시각 `t = −τ·ln(1−f)`, `f = (임계−상온)/(피크−상온)`. 피크 300℃·임계 80℃·상온 25℃ → f=0.2 → t=0.22τ. 피크 120℃면 f=0.58 → t=0.87τ. **뜨거운 불이 같은 선을 ~4배 빨리 밟는다.** 이게 미탐지 걱정을 실제로 갉는다 — **얼마나 갉는지 표면으로 재는 게 이 파트.**

### B-1. 사전등록 예측
- **예측 B1:** 피크온도↑ → 미탐지율↓ (단조). τ=78.5s라도 피크가 충분히 높으면(예: ≥300℃) 미탐지율이 크게 떨어진다.
- **예측 B2:** 하지만 **노드가 실제로 겪는 피크는 화염 온도(800~1200℃)가 아니라 warm_scale 감쇠로 낮아진 "센서 위치 공기온도"**다. 이게 낮으면(불이 멀리서 스쳐 지나가는 노드) 피크가 낮아 미탐지 걱정이 되살아난다. → **단일 피크로 "안전"이라 결론내면 안 된다. 노드마다 겪는 피크가 다르다.**

### B-2. 실행 스펙
1. **2.I-a 미탐지 시뮬 재사용**, 다만 **불 피크온도를 스윕 축으로 추가**: peak ∈ `{100, 150, 200, 300, 500}` ℃. (센서 위치에서의 유효 피크. 화염 자체 온도 아님.)
2. **τ 축**: `{11, 30, 50, 78.5, 100}` s.
3. **임계 80℃ 고정**(우리 death/탐지 임계와 일치. 바꾸지 말 것).
4. **펄스 폭**: 기존 2.I-a 값 사용(1.5 m/s에서 17.2s 등). 펄스 형태(상승-피크-냉각)도 2.I-a 것 그대로.
5. **출력:**
   - `(peak, τ) → 미탐지율(%)` **2D 표면(히트맵)**. CSV + 그림.
   - 각 셀에 "센서가 도달한 최고온도 / 임계 80℃" 마진도 함께.
   - **현실 운영점 오버레이**: warm_scale(=6m, 실측 후 갱신 예정) 감쇠를 반영해 **노드-불 거리별 유효 피크 분포**를 계산하고, 그 분포를 표면 위에 점으로 찍어 "실제로 우리 노드들이 표면의 어디에 떨어지나"를 보여라. **여기가 핵심** — 최적 피크 하나 골라 "안전" 하지 말고, **분포 전체**가 미탐지 위험 구역에 얼마나 걸치는지 보고.
6. **판정**: "미탐지율 ≤ 5%"를 실용선으로, 각 피크에서 그 선을 지키는 τ 상한을 표로.

### B-3. 정직성 체크
- [ ] 임계·펄스폭·펄스형태를 2.I-a에서 **안 바꿨나**?
- [ ] 유리한 피크(예: 500℃)만 강조하고 낮은 피크(100~150℃, 멀리 스치는 노드)를 **숨기지 않았나**?
- [ ] warm_scale 감쇠로 "센서 유효 피크가 화염온도보다 훨씬 낮다"는 걸 **명시**했나?
- [ ] "그러니 우린 안전"이 아니라 **"이 조건에선 안전/이 조건에선 위험"**으로 조건부 서술했나?

## 파트 C — 통합 해석 (Claude Code는 데이터만, 해석은 내가)
두 파트 끝나면 **원자료(CSV) + 그래프만** 올려라. 결론 문장은 내가 쓴다(사용자와 함께 판정). 다만 Claude Code가 실행 중 **예측과 어긋난 점**을 발견하면 그 자리에서 한 줄로 플래그.

**두 검증이 답할 최종 질문:**
- A: "실측 τ에서 방향 2.1°가 5° 안에 버티나?" → 버티면 **프로젝트 코어 안전 확정**. 무너지면 진짜 경고.
- B: "미탐지 걱정이 현실 피크에서 얼마나 완화되나, 그래도 남는 위험 노드(멀리 스치는·저피크)는 몇 %냐?" → 열전대(K형) 필요성의 **정량 근거**.

## 파트 D — Claude Code 복붙 블록

```
「불사」 τ 실측 후속 검증 2건. 둘 다 시뮬만(열원 불필요). 결과는 CSV+그래프 원자료로.
강령: (1)기존 estimator/threshold/전선/펄스 건드리지 말 것(변수오염·동어반복 방지)
      (2)우리에게 유리한 조건만 고르지 말 것 (3)예측과 어긋난 점은 그 자리서 플래그.

[검증A] 실측 τ 방향 강건성:
- 방향 estimator(평면최소자승→∇T→방향) 그대로. 각 노드 참 공기온도에 1차지연
  T_sensor += (T_air−T_sensor)*(dt/τ) 씌운 뒤 기존 threshold로 death time 산출.
- 균일τ 스윕: {0,2,5,10,11,20,30,50,78.5,100}s (실측 11,78.5 필수 포함).
- 노드별 지터τ: μ∈{11,30,78.5}, τ_i~μ*(1+N(0,0.3)) 하한0.5s클립, 시드5개 평균.
- 전선: 곡선 전선 반드시 포함(2.G/2.H서 방향열화 봤던 조건), 직선은 대조군.
- 출력: τ vs 방향오차(도) 곡선(균일/지터, 곡선/직선). 각 τ의 미탐지 노드수도.
  실용선 방향오차≤5°가 τ 어디서 깨지나 명시.

[검증B] 미탐지율 × 불 피크온도:
- 2.I-a 미탐지 시뮬 재사용. 피크온도 축 추가: peak∈{100,150,200,300,500}℃(센서위치 유효피크).
- τ축 {11,30,50,78.5,100}s. 임계 80℃ 고정. 펄스폭/형태는 2.I-a 그대로.
- 출력: (peak,τ)→미탐지율% 히트맵 + 각 셀의 도달최고온/80℃ 마진.
- ★현실 운영점: warm_scale=6m 감쇠로 노드-불 거리별 유효피크 분포 계산해 표면에 오버레이.
  최적 피크 하나로 '안전' 결론 금지 — 분포 전체가 위험구역에 얼마나 걸치나 보고.
- 실용선 미탐지율≤5% 지키는 τ상한을 피크별 표로.

A부터 주고, 내가 확인하면 B. 결론 문장은 쓰지 말고 데이터+그래프만(해석은 Cowork가).
```
