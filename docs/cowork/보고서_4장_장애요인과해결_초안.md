## 슬라이드 4-A. 「시뮬레이터 선(先)개발」 — 하드웨어 리스크의 분리

**라벨: `기술적 난이도 — 검증 가능한 개발 순서 설계`**

**문제.** 산불 센서망은 **실패해야 데이터가 나오는 시스템**이다. 노드를 실제로 태워야 알고리즘을 검증할 수 있는데, 1인 개발·6주 일정·예산 제약에서 그건 불가능하다.

**해결.** 물리 전선 전파와 노드 사망을 재현하는 시뮬레이터를 먼저 만들고, 알고리즘 전체를 거기서 검증한 뒤 실물로 이식했다. 하드웨어가 도착하기 전에 **추정기·판별 게이트·자가치유 라우팅이 모두 동작 검증을 마쳤다.**

**성과 수치.**

| 항목 | 값 |
|---|---|
| 시뮬 시나리오 | 직선·요동·타원(head/flank) × τ 다수준 × 노드밀도 다수준 |
| 자동 회귀 테스트 | 54건 (전부 통과, 결과 비트 단위 동일 유지) |
| 추정기 핵심 파일 | **불변(frozen)** — 실험은 전부 버전 분기로 |

> **차별 포인트:** 「추정기 파일을 얼리고 모든 개선을 버전 분기로 넣는다」는 규칙을 스스로 세워, **어떤 실험도 과거 결과를 훼손할 수 없게** 만들었다. 회귀가 매번 "최대차 0.000e+00"으로 확인된다.

## 슬라이드 4-B. ★「82° 오차의 3중 오진」 — 진짜 원인을 찾기까지

**라벨: `문제해결 능력 — 가설 수립·반증·재수립의 반복`**

이 슬라이드가 이 절의 중심이다. **하나의 증상을 두고 세 번 틀린 진단을 내렸고, 세 번 다 측정으로 기각했다.**

**증상.** 타원 화선의 **측면(flank)** 조건에서 방향 추정 오차가 **82~86°**. 90°가 무작위 추측의 한계이므로, 사실상 **아무 정보도 못 주는 상태**였다.

| 회차 | 가설 | 검정 방법 | 결과 |
|---|---|---|---|
| ① | **곡률** 때문이다 (전선이 굽어 국소 평면 근사가 깨짐) | 적합 창을 넓혀 곡률 영향 분리 | **기각** — 창을 넓히자 81.81°→5.63°로 급락. 같은 곡률의 다른 조건은 11°로 불변 |
| ② | **채점 방식**의 문제다 (국소 법선 vs 전역 축을 혼동한 인공물) | 채점 코드 직접 확인 | **기각** — 이미 국소 법선 기준이었다 |
| ③ | **표본 부족**이다 (창 안에 이웃이 모자람) | 표본 수·조건수 진단 | **부분 기각** — 표본이 13개 있는데도 실패하는 사례 존재 |
| **④** | **집계 가중치**가 원인이다 | 노드별 개별 오차와 가중치 분포 확인 | **★확정** |

**진짜 원인.** 추정기는 2단 구조다 — ①노드마다 국소 평면을 맞춰 각자 방향을 내고 ②그것들을 가중 합산한다. **그 가중치가 `1/|∇T|`, 즉 "불확실한 노드일수록 크게" 였다.**

| 증거 | 값 |
|---|---|
| corr(노드별 속도, 노드별 방향오차) | **+0.986** |
| 한 노드가 차지한 가중치 비중 | **86.4 %** |
| 그 노드의 개별 오차 | **85.21°** |
| 같은 사례의 개별 오차 **중앙값** | **1.35°** |

> **★한 줄 요약: 정답은 표본 안에 있었다. 집계가 그걸 버리고 최악의 노드 하나를 골랐다.**

**결정적 단서 — 우연한 통제군.** 같은 코드에서 **방향은 가중합(비강건), 속도는 중앙값(강건)**을 쓰고 있었다. 같은 입력·같은 퇴화 상황에서 **속도는 오차 0.86으로 살아남고 방향만 78° 틀렸다.** 입력이 같으므로 차이의 원인은 **집계 연산자뿐**이다.

**해결.** 오차 전파식에서 가중치를 다시 유도했다.

```
δφ ≈ δ⊥ / |∇T|      →   Var(φ) ∝ 1/|∇T|²      →   w = |∇T|²

기존 w = 1/|∇T| 와의 비 = |∇T|³   ← 세제곱. 부호가 반대였다.
```

## 슬라이드 4-C. ★「모르면 모른다고 말하는 시스템」

**라벨: `공학적 성숙도 — 실패 인지 및 자기 차단 설계`**

**문제.** 가중치를 고쳐도 **정보가 원래 없는 조건**은 남는다. 그때 시스템은 무엇을 해야 하는가?

**측정된 사실 (flank 희소 조건):**

| 집계 방식 | 출력 |
|---|---|
| 기존(legacy) | 85.05° — **자신 있게 틀림** |
| 균일 가중 | 84.90° — 자신 있게 틀림 |
| 중앙값 | 84.90° — 자신 있게 틀림 |
| **역분산(채택)** | **값 없음 (INSUFFICIENT)** |

**설계 결정: 폴백을 넣지 않는다.** 값을 못 내면 못 낸 채로 상위에 올린다.

> **근거:** 산불 대응에서 **"모른다"와 "정반대를 확신한다"의 비용은 대칭이 아니다.** 지휘부가 방향을 모르면 판단을 보류하지만, 90° 틀린 방향을 믿으면 대원을 화선 쪽으로 보낸다.

**실제 로그:**

```
grade = INSUFFICIENT   dir = None
reason: 유효 가중이 전부 0 (국소 적합 3개가 전부 분산 추정 불가)
(기존 방식이었다면 값을 냈을 것: True)  ← 그 값은 85.05°로 틀렸다
```

**"낼 수 있었지만 내지 않았고, 냈다면 틀렸을 것"**이 로그에 함께 남는다.

**진단량 `n_eff`(유효표본수) 도입.** `n_eff = (Σw)²/Σw²`. 표본이 13개여도 하나가 독식하면 1.33까지 떨어진다.

| 상태 | n_eff | 구분법 |
|---|---|---|
| 정상 | 12.7 ~ 13.0 | — |
| 가중치 독식 | 1.33 ~ 1.74 | 원표본 n은 큼 |
| 진짜 표본 굶주림 | 1.04 | 원표본 n 자체가 작음 |

**→ n_eff 하나로는 두 실패가 구분되지 않고, 원표본 수와 짝지어야 갈라진다.** 그래서 항상 쌍으로 출력한다.

### ★ 같은 원칙을 우리 계측 도구가 어겼다 — 침묵의 대가

이 절의 원칙은 **"모르면 모른다고 말한다"**이다. 그런데 τ 실측 세션에서 **정반대 구조를 가진 도구에 우리가 직접 당했다.**

센서 로거 펌웨어는 부팅 시점에 1-Wire 버스에서 센서를 찾지 못하면 오류를 한 줄 찍은 뒤 이렇게 동작했다:

```cpp
if (n == 0) { Serial.println("# ERROR..."); return; }   // ready = false
void loop() { if (!ready) { delay(1000); return; } }     // ← 이후 영구 침묵
```

센서를 교체하고 측정을 시작했더니 **출력이 아예 없었다.** −127℃(버스 무응답)도 85℃(변환 미완료)도 아닌 **무(無)**였다. 배선을 만져도, 커넥터를 다시 꽂아도 화면은 그대로였다 — **침묵은 "정상"과 구별되지 않으므로 무엇을 고쳤는지 알 수 없었다.**

수정은 단순했다. 1초마다 재탐색하며 `# devices=N` 상태를 계속 출력하도록 바꾸자, 배선을 만지는 즉시 화면이 반응했고 문제는 몇 분 만에 끝났다.

> **교훈이 알고리즘 설계와 정확히 같다.** 정보가 없을 때 시스템이 취할 수 있는 태도는 세 가지다 — ① 아무 값이나 낸다(자신 있게 틀림) ② 아무것도 안 한다(침묵) ③ **"모른다"는 것을 값으로 낸다.** 우리는 추정기에서 ③을 택했는데, 계측 도구는 ②였다. **②는 ①보다 낫지만 ③보다 못하다** — 침묵은 진단 정보를 주지 않기 때문이다. 이것이 INSUFFICIENT를 "출력 없음"이 아니라 **등급이 붙은 출력**으로 설계한 이유다.

## 슬라이드 4-D. 「하드웨어 괴리의 선점」 — 실물에서만 드러나는 것들

**라벨: `기술적 난이도 — 시뮬–실물 괴리 인지 및 사전 대응`**

**(1) 공통 시계 — 원리적 파탄을 사전 차단.**
서로 다른 노드의 사망 시각을 빼서 기울기를 만드는 알고리즘이므로 **시간축이 같아야 한다.** 초기 펌웨어는 `millis()`(보드 부팅 기준)를 썼는데, 이는 보드마다 원점이 달라 **뺄셈 자체가 무의미**해진다. 실물 이식 전에 발견해 메시 동기 시각(`getNodeTime()`)으로 교체했다.
또한 사망 시각을 **루트의 확정 시각**에서 **당사자 노드가 각인한 시각**으로 바꿨다 — 확정 시각에는 침묵 감지 지연과 투표 지연이 섞여 있었다.

**(2) 센서 열관성 τ — 실측이 시험 범위 밖에 있었다.**

| | 값 |
|---|---|
| 시뮬이 시험하던 범위 | τ ∈ {0, 2, 5, 10} s |
| **실측 범위 (유속에 따라)** | **11 ~ 92 s** |
| 제트 내부 (7.5mm 노즐·풍량10·3cm) | **21.5 s** (R² 0.9987~0.9994) |
| 실내 공기 (같은 시행의 이탈 곡선) | **92 s** (R² 0.9988) |

**→ 우리가 검증했다고 믿은 범위 밖에 실제 값이 있었다.**

**τ는 온도가 아니라 유속의 함수다 — 한 번의 시행 안에서 증명됐다.** 센서를 열풍 제트에 넣었다 빼는 단일 시행에서, 진입 곡선의 τ는 21.5초, 이탈 곡선의 τ는 92초로 **4.1배** 차이가 났다. 같은 센서, 같은 온도 범위, 연속된 같은 시행 — 바뀐 것은 **공기가 움직이느냐뿐**이었다. 별도의 대조 실험을 설계할 필요 없이 측정 자체가 대조군을 포함하고 있었다.

**모델 가정의 검증 — DS18B20은 순수 1차계가 아니다.** 단일 지수 적합의 잔차가 무작위가 아니라 덩어리로 뭉쳤고(`++-------------00++++++++++++++++++`), 도달률별로 τ를 뽑으면 63%→21.6 s, 86%→18.4 s, 95%→15.0 s로 흘러내렸다. 스테인리스 외피 + 충진재 + 다이의 복합 열구조 때문으로 보인다. 따라서 τ를 물리 상수가 아니라 **운용 기술자(operational descriptor)**로 제시하고, 모델과 무관한 값(60℃ 도달 30초, 95% 도달 45초)을 병기한다.

**(3) ★ 노드별 편차 σ_τ — 우리가 낸 숫자를 우리가 철회했다.**

우리는 한때 이 항목에 **σ_τ = 5.7%**라는 값을 적었다. 시뮬 가정 30%의 6분의 1이니 「취약」이 「양호」로 뒤집히는 좋은 결과였다. **그 숫자는 지금 이 문서에서 철회한다.** 측정이 그 값을 낼 자격이 없었기 때문이다.

**어떻게 드러났는가.** 센서 개체차를 보려면 개체 말고는 아무것도 변하지 않아야 한다. 그런데 우리 측정은 센서를 **한 개씩 순서대로** 갈아 끼우며 진행했고, 그 과정에서 조준 솜씨도 회차마다 나아졌다. 즉 **센서 번호 · 측정 순서 · 조준 품질 셋이 완전히 겹쳐 있었다.**

| 검정 | 결과 |
|---|---|
| τ와 **측정 순서**의 상관 | **−0.903** (같은 날 안에서는 −0.994) |
| 회차당 추세 | −1.07 s / 회 |
| n01을 3일 뒤 재측정 | 23.29 s → **17.16 s (−26.3%)** |
| 같은 세션 반복오차 | 0.94 s |

마지막 두 줄이 결정적이다. **같은 센서를 다시 재니 6.5배 큰 차이가 났다.** 개체차라고 보고했던 폭보다 같은 개체의 재측정 폭이 더 컸다는 뜻이다. 그렇다면 우리가 잰 것은 개체차가 아니다.

**왜 자체 검정을 통과했는가.** 우리는 위치 편차가 τ에 미치는 영향이 작다는 것(4-D (4))을 근거로 조준 변동을 무시했다. 그 판단 자체는 맞았다 — 하지만 그것은 **위치가 τ를 오염시키지 않는다**는 뜻이지 **순서가 τ를 오염시키지 않는다**는 뜻이 아니었다. 우리는 확인한 교란 하나로 확인하지 않은 교란 전체를 대신했다.

**대응 — 숫자를 고치지 않고 방법을 바꾼다.**

교란된 설계에서 나온 값은 보정으로 살릴 수 없다. 센서 개체와 순서를 분리하려면 순서를 무작위화하고 각 센서를 여러 시점에 반복해야 하는데, 손으로 프로브를 고정하는 현재 방식으로는 **위치 산포(32%)가 τ 산포(36%)와 맞먹어** 원리적으로 분리가 안 된다.

그래서 σ_τ를 **측정 대상에서 제외하고**, 같은 질문에 답하는 다른 값으로 대체한다:

> **리허설·본시행의 평면적합 잔차.** 이는 센서 개체차 · 시계 편차 · 조준 편차 · 라우팅 지연이 **모두 합쳐진 실운용 지터**이며, 우리가 실제로 알아야 하는 값이다. σ_τ 하나만 정확히 아는 것보다 이쪽이 결론에 더 가깝다.

**남는 결론.** 이 항목은 「취약」도 「양호」도 아닌 **「미측정」**이다. 다만 방향 추정이 *균일한* 지연에 면역이라는 것은 수식과 실측 양쪽에서 확인됐으므로(4-D (4)), 위험은 개체차가 **크다면** 그때 문제가 된다는 조건부로 남는다.

> **이 절을 남겨두는 이유.** 유리한 숫자를 스스로 기각한 기록이기 때문이다. 본 시스템의 INSUFFICIENT 게이트는 *근거가 부족할 때 답을 내지 않는* 기능이고, 이 절은 그 원칙을 저자 자신에게 적용한 사례다. 결과가 불리해도 규칙은 같아야 한다.

**(4) ★ 이론 카드가 계측에서 재현됐다 — 조준 오차는 절편에 흡수된다.**

우리의 핵심 주장은 **"균일한 지연은 기울기에서 상쇄되고 절편에만 흡수된다"**(∇T = n̂/s)이다. τ 측정 중 이 성질의 계측판(版)이 두 번 관측됐다.

| | 도달 온도(절편) | τ(기울기) |
|---|---|---|
| 조준을 개선했을 때 | +4.5 ℃ | +0.95 s |
| 젓가락이 이탈해 각도가 틀어졌을 때 | **−11.7 ℃ (−16%)** | **−0.35 s (−1.6%)** |
| 전 시행(6회) 회귀 | 61 ~ 77.5 ℃ (16.5℃ 폭) | 기울기 **−0.061 s/℃**, corr −0.30 |

**센서 위치가 흔들리면 도달 온도는 크게 변하지만 시상수는 거의 변하지 않는다.** 두 번째 행은 우연한 사고(고정 테이프 이탈)가 만든 자연 실험이었고, 조준 변수만 크게 흔들어준 덕에 가장 강한 증거가 됐다 — **감쇠비 10 : 1**.

이 성질 덕분에 실용적 결론이 하나 따라온다: **거리·정렬이 다소 흐트러져도 σ_τ 측정은 오염되지 않는다.** 실제로 위치 편차가 τ 분산에 기여한 몫은 전체의 **1.3%**에 그쳤다.

**대응과 그 한계.** 균일한 지연에 대한 면역은 수식과 실측 양쪽에서 확인됐다. 남는 것은 **노드별 편차**인데, 임계 온도를 낮춰 구제하려던 시도는 실패했고 **왜 실패할 수밖에 없는지**를 규명했다 —

> **단일 스칼라 임계는 방아쇠(trigger)와 판별자(discriminator)를 겸할 수 없다.** 임계를 낮추면 탐지는 빨라지지만 화재/비화재 변별력이 무너진다. 실제로 게이트를 고정하면 채택률 0, 게이트를 함께 낮추면 비화재 오염 89~100%였다. **온도 이외의 판별 축이 필요하다**는 결론.

**(5) 실물 파이프라인의 공백.** 시뮬에는 화재/비화재 판별이 있는데 **실물 경로에는 없었다.** 게이트웨이가 판별기를 아예 호출하지 않고 있었다. 판별 로직을 한 함수로 통합해 **시뮬과 실물이 같은 코드를 호출**하도록 고쳤다 — 그러지 않으면 시뮬 결과가 실물의 근거가 되지 못한다.

**(6) ★ 값 하나로는 원인을 못 찾는다 — 분산이 먼저 말했다.**

데모용 열원 조건을 정하려고 공기 온도를 쟀다. 예측은 190 ℃였는데 처음 두 번은 71 ℃와 133 ℃가 나왔다. **평균만 보면 "거리가 멀다"로 읽힌다.** 실제 원인은 거리가 아니라 조준이었고, 그 구분을 해준 것은 평균이 아니라 **분산**이었다.

| 회차 | 평균 | 분산(10초 폭) | 환산된 축이탈 | 그 지점의 온도 기울기 |
|---|---|---|---|---|
| 1 | 71.5 ℃ | 14.0 | 1.06 cm | −109 ℃/cm |
| 2 | 133.2 ℃ | 26.5 | 0.61 cm | −149 ℃/cm |
| 3 | **190.5 ℃** | **2.0** | **0 cm** | **−4 ℃/cm** |

제트 중심은 온도가 평평한 꼭대기라 센서가 흔들려도 값이 거의 안 변한다(−4 ℃/cm). 옆구리는 −149 ℃/cm까지 가팔라 **1.8 mm 떨림이 26 ℃ 흔들림으로 증폭된다.** 즉 **분산의 크기 자체가 "지금 비탈이냐 꼭대기냐"를 알려주는 신호**였다.

거리를 고쳤다면 온도는 올랐겠지만 분산은 안 줄었을 것이고, 우리는 잘못된 거리에서 잘못된 조건을 확정했을 것이다.

> **이것이 본 시스템의 `n_eff`·평면적합 잔차 진단과 같은 논리다.** 추정값 하나가 아니라 **그 추정이 얼마나 뭉쳐 있는지**를 같이 보아야 원인을 지목할 수 있다. 우리는 알고리즘에 넣은 원칙을 계측에서 다시 만났다.

**(8) ★ 왜 실내에서만 실험했는가 — 정지 공기를 요구하는 것은 시스템이 아니다.**

본 데모는 실내에서, 바람이 없는 조건에서만 수행했다. 산불을 다루는 시스템이 바람을 피해 실험했다는 것은 설명이 필요한 대목이므로 여기 명시한다.

**요구하는 주체가 다르다.**

| | 바람에 대한 성질 |
|---|---|
| 추정 알고리즘 | **면역** (아래 근거) |
| 노드 하드웨어 | 무관 |
| **대역 열원(열풍기)** | **취약** ← 여기만 문제다 |

**① 알고리즘이 면역인 근거 — 이 프로젝트의 중심 수식이다.**

사망 시각은 `t_j = a_j + d_j` (a = 화선 도달 시각, d = 센서 지연)이다. 방향과 속도는 t의 **공간 기울기**에서 나오고(`∇T = n̂/s`), 모든 노드에 같은 지연 `d`가 걸리면 그것은 **평면의 절편에만 흡수되어 기울기에서 사라진다.**

바람은 대류 열전달 계수 h를 바꿔 d를 바꾸지만, **노드 배열 규모에서 바람이 대체로 균일하다면 d는 모든 노드에서 같이 변한다.** 따라서 방향·속도는 그대로다. 위치마다 다른 돌풍은 노드별 랜덤 지터가 되고, 이는 2단 집계가 `n_eff`만큼 평균해 눌러낸다.

**더 근본적으로, 실제 산불에서 바람은 잡음이 아니라 신호다.** 화선을 미는 동력이 바람이고 우리는 화선의 움직임을 읽는다. 바람이 없으면 읽을 대상 자체가 줄어든다.

**② 그럼에도 실내여야 했던 이유 — 대역 열원의 한계.**

실제 화선은 폭이 수 미터에 온도 600~1000 ℃다. 우리 대역은 **지름 7.5 mm 제트를 4 cm 앞에 맞히는** 방식이고, 실측 조준 허용오차는 ±0.90 cm다.

| 옆바람 | 4 cm 구간에서 제트가 밀리는 양 |
|---|---|
| 1 m/s | 0.57 cm — 허용 안 |
| **2 m/s** | **1.14 cm — 허용 초과** |
| 3 m/s | 1.71 cm |

나뭇잎이 흔들리는 정도가 1.5~3 m/s다. **약한 바람만으로 겨냥이 빗나가 노드가 죽지 않는다.** 또한 이미 가열된 자리의 상승기류가 옆으로 흘러 이웃 노드를 순서 밖에서 죽일 수 있다.

**이 취약함은 전부 "불 대신 가는 제트를 쓴다"는 대역의 부작용이며, 실제 화선에는 '겨냥'이라는 개념 자체가 없다.**

**③ 역할 분담 — 하드웨어와 시뮬레이터가 각각 무엇을 증명하는가.**

```
하드웨어 데모   실물 경로가 끝까지 도는가
                (사망 판정 → 임종신호 → 메시 → 시각 각인 → 집계 → 대시보드)

시뮬레이터      물리 시나리오에서 추정이 성립하는가
                (바람 필드 · 곡률 · 노드 희소 · 비화재 해악)
```

바람 조건은 시뮬레이터에서 다룬다. 이때 **관측소 바람을 오라클로 쓰지 않고**, 관측소와 국소 미기후의 편차를 노이즈로 넣어 융합의 이득을 정직하게 측정했다. 하드웨어로 바람까지 재현하려면 풍동이 필요하고, 그것은 본 개발 범위 밖이다.

**④ 그래서 우리가 증명하지 않은 것.**

> **본 연구는 실물 하드웨어가 바람 속에서 동작함을 보이지 않았다.** 보인 것은 (ㄱ) 균일 지연에 대한 면역이 수식과 계측 양쪽에서 성립한다는 것, (ㄴ) 바람 조건의 추정 성능이 시뮬레이션에서 성립한다는 것, 두 가지다. 이 둘을 잇는 **실물 야외 시험은 후속 과제로 남는다.**

이 문단을 축약하지 않는다. 축약하면 "실내에서만 되는 시스템"으로 읽히거나, 반대로 검증하지 않은 것을 검증한 것처럼 읽힌다. **둘 다 사실이 아니다.**

**(7) 표준 상관식은 형태만 맞았다 — 이론을 그대로 쓸 수 없는 이유.**

열원 조건을 이론으로 대체할 수 있는지 검토했다. 결론은 **부분적으로만**이다.

거리별 공기 온도 4점을 적합하면 **지수감쇠가 아니라 교과서적 쌍곡감쇠**가 나온다.

```
f(x) = 3.12 / (x + 3.12)        R² = 0.9904
```

제약 없이 자유 적합했는데 노즐 지점에서 `f(0)=1`, 즉 **설정 온도가 그대로 나온다**는 별도 실측(설정 200·1 cm에서 199 ℃)과 일치했다. 형태는 이론이 맞혔다.

그러나 **크기는 맞히지 못했다.** Chen & Rodi 변밀도 자유제트 상관식으로 노즐 지름을 역산하면

| | |
|---|---|
| 예측 노즐 지름 | 8.9 mm |
| 실측 노즐 지름 | **7.5 mm** (+19%) |
| 역산한 감쇠상수 C | 6.23 (문헌 4.4~5.9) |
| 설정 이전 검정(400 → 100) | 예측 68.0 ℃ / 실측 73.5 ℃ (−11%) |

**기각으로 기록한다.** 사전에 허용폭을 정하지 않았으므로 통과로 셈하지 않는다.

원인 후보: 측정 구간이 `x/d ≈ 2.7~10.7`로 **잠재핵을 포함**하고, 강한 부력이 작용하며, 노즐이 매끈한 수축형이 아니라 관형이다. 흥미로운 것은 **축방향 감쇠가 느린 것과 제트 폭이 예측보다 48% 넓은 것이 서로 상쇄되지 않고 같은 방향을 가리킨다**는 점이다 — 기하학적 구멍 지름(7.5 mm)이 아니라 **유효 발원 지름(≈ 9 mm)**으로 보아야 한다는 가설과 일관된다. 확정은 아니다.

**→ 실무 결론: 데모 조건은 실측으로 정하고, 이론은 "왜 표준 상관식이 안 맞았는가"의 논의 재료로만 쓴다.**

## 슬라이드 4-E. ★「틀림을 관리하는 절차」 — 이 프로젝트의 진짜 산출물

**라벨: `공학적 성숙도 — 검증 방법론의 자체 구축`**

물리 예측을 **사전등록(pre-registration)**하고, 맞든 틀리든 **전부 기록**하는 규칙을 세웠다.

**기각된 예측 목록 (전부 문서에 남아 있음):**

| 예측 | 결과 |

| 속도가 방향보다 지터에 취약 | **기각** |

| 데모 조건 공기 온도 190 ℃ | **적중** — 실측 190.54 ℃ (오차 0.3%), 분산 예측 2~3에 실측 2.00 |

**★ 이 표에서 두 번째 줄이 가장 중요하다.** 나머지는 외부 이론이나 초기 직관을 기각한 것이지만, 그 줄은 **우리가 이미 문서와 발표자료에 실었던 유리한 숫자를 우리 손으로 내린 것**이다. 규칙이 자기 자신에게도 적용될 때만 규칙이다.

**★ 기각이 일정을 구한 사례.** 제트 반폭 기각(1.15 cm)은 곧바로 "체류 6초면 조준 허용오차가 ±0.58 cm뿐"이라는 계산으로 이어졌고, 체류를 8초로 늘려 ±0.90 cm를 확보했다. **이 예측을 검증하지 않았다면 본 촬영에서 노드 일부가 죽지 않아 평면적합이 깨졌을 것이고, 원인을 알기까지 재촬영을 반복했을 것이다.** 3분짜리 측정 하나가 촬영 일정을 지켰다.

**규칙이 실제로 작동한 증거.** 예측에 등급(수식 유도 / 유추 / 직관)을 붙이고 **직관 등급은 예측으로 발행 금지**하도록 바꾼 뒤, 처음 낸 수식 유도 등급 예측은 **4/4 적중**했다.

**수치 무결성 규칙.** 과거 문서에서 **서로 다른 조건의 값을 나눠 배율을 만든 오류**가 있었다. 이후 규칙을 명문화했다 — *비교값을 쓸 때는 분자와 분모의 조건을 둘 다 적는다 / 배율이 아니라 절대오차로 비교한다 / 원자료에서 취하고 기억에서 채우지 않는다.*

> **★심사 관점 한 줄:** 우리가 제출하는 것은 "잘 되는 시스템"이 아니라 **"어디까지 되고 어디부터 안 되는지 스스로 아는 시스템"**이다. 자율 재난 대응 장비에서 후자가 더 어렵고 더 중요하다.

## 슬라이드 4-G. ★「조용한 실패 4건」 — 브링업에서 나온 것들 [2026-08-30 추가]

**라벨: `공학 성숙도 — 실패를 소리 나게 만드는 설계`**

> 이 절의 주장은 "문제를 다 풀었다"가 아니다. **"정상처럼 보이는 실패를 어떻게 잡아냈나"** 다.
> 아래 4건은 전부 **화면에는 아무 이상이 없었다.** 그래서 이 절이 존재한다.

### (1) 규모 의존 상수 — 시뮬 값이 벤치에서 조용히 전멸

- **증상.** 게이트웨이가 정상 종료하는데 방향이 안 나온다. 오류도, 경고도 없다.
- **원인.** `dt_window` = 8.0 s. 시뮬은 10 m 간격 / 1.5 m/s(이웃 통과 6.67 s)에서 고른 값인데,
  벤치는 0.20 m / 0.0011 m/s(이웃 통과 181.8 s)다. **시간 규모 배율 R = 27.3×.**
  국소 최소제곱이 창 안에서 이웃을 하나도 못 찾아 **16/16 전멸**했다.
- **왜 어려웠나.** "표본 부족"과 "기하가 나쁨"이 같은 증상을 낸다. 둘을 가르려면 창을 스윕해
  실패 원인을 분해해야 했다. 그리고 **같은 병이 하나일 리 없었다** — 전수 감사에서 4건이 나왔다
  (`dt_window` · `residual_gate_s` · `alert_horizon` · `speed_true`).
- **해결.** 값을 고르지 않고 **물리에서 유도**한다. 하나의 물리량에서 전부 나온다.
  `dt_window = radio_range/v` · `alert_horizon = spacing/v` · `speed_true = v`.
  식으로 안 나오는 `residual_gate_s` 는 드라이런 잔차 분포의 median+3σ 로 뽑았다(**20.4 s**,
  전선 방향 8개 · 표본 48건).
- **재발 방지.** 시작 로그에 **유도식과 계산값**을 그대로 찍는다. 규모를 바꾸면 그 줄이 바뀐다.

### (2) `WARN_TEMP_C` — 사망확정이 **구조적으로** 불가능했다

- **증상.** 노드를 임계까지 올려도 대시보드에 아무 일도 안 일어난다.
- **원인.** 사망 임계를 시험용 40 ℃ 로 낮춰 굽는데 `WARN_TEMP_C` 는 60 ℃ 고정이었다.
  노드는 40 ℃ 에서 DYING→(300 ms)→DEAD 가 되어 **송신을 끊는다.**
  즉 이웃이 관측할 수 있는 온도의 상한이 40 ℃ 다. 그런데 사망 투표 조건은 `peakTemp ≥ 60`.
  → 투표가 영원히 성립하지 않고 K표가 안 차서 **DC 가 절대 안 나온다.**
  게이트웨이가 소비하는 유일한 타입이 DC 이므로, 화면에는 **아무 징후도 없다.**
- **왜 어려웠나.** 온도를 더 올리면 될 것 같지만 **아니다** — 노드가 임계에서 죽으면서
  송신을 끊으므로, 물리적으로 아무리 가열해도 이웃이 보는 최대 온도는 임계값이 상한이다.
  "값이 크다/작다"가 아니라 **두 상수 사이의 불변식**이 깨진 것이라 단독 점검으로는 안 보인다.
- **해결.** `WARN = THRESHOLD × 0.75` 로 유도(원설계 60/80 비율 보존, 기본값에서 비트 동일) +
  `static_assert(WARN < THRESHOLD)`.
- **재발 방지.** 컴파일 차단만으로는 부족하다 — **부팅 배너에 `warn_temp_c` 를 찍고**
  플래시 스크립트가 그 값을 읽어 `WARN_MISMATCH` / `WARN_GE_THRESHOLD` 로 FAIL 판정한다.
  구워진 실물이 자기가 무엇을 들고 있는지 말하게 만들었다.
- **★ 이 건은 시험을 돌리기 전에 정적 점검으로 잡았다.** 돌렸으면 "사망 감지가 안 된다"로만
  보였을 것이고, 원인은 안 보였을 것이다.

### (3) COM 번호로 굽기 — 브리지가 두 대가 되고 NODE_ID 가 중복

- **증상.** 메시는 정상으로 보인다. 좌표만 조용히 뒤섞인다.
- **원인.** "COM3 을 브리지로 굽는다"고 정해뒀는데, 그 사이 COM3 이 다른 보드가 되어 있었다.
  CP210x 는 재연결·리셋마다 COM 번호가 바뀌고, 일부 보드는 USB 시리얼이 `0001` 로 중복이라
  Windows 가 포트 경로로 번호를 재배정한다.
- **왜 어려웠나.** 잘못 구운 결과가 **작동한다.** 두 노드가 같은 id 로 같은 좌표를 주장해도
  게이트웨이는 예외 없이 돈다. 방향만 틀린다.
- **해결.** 굽기 대상을 **mid(painlessMesh nodeId, 칩 MAC 유래)** 로 강제한다(`-ExpectMid`).
  포트를 스캔해 배너 mid 로 대상을 정하는 `flash_by_mid.ps1` 을 만들었다.
- **재발 방지.** 굽기 후 전 포트의 `(id, mid)` 를 다시 읽어 **중복 검산 1줄**을 출력한다.
  실제로 이 가드가 이후 두 번 `MID_MISMATCH` 로 오굽기를 막았다.

### (4) 합류 직후 1초의 `nt` — 사망시각 규약(제약③)의 남은 구멍

- **증상.** 정상 HB 로 보인다. 아무 경고도 없다.
- **원인.** 노드가 메시에 합류한 뒤 시각 동기가 끝나기까지 약 1초가 걸리고,
  그 동안 `nt` 에 **메시 공통 시각이 아니라 자기 부팅 경과시간**이 실린다.
  실측 — 첫 HB `"ms":3000, "nt":3.000113`, 다음 HB `"ms":4000, "nt":782.857631`.
- **왜 어려웠나.** 이 창은 1초뿐이라 평시에는 절대 안 보인다.
  자가치유 복귀 시험(노드 재합류)을 하다가 로그를 한 줄씩 읽으며 우연히 발견했다.
- **해결.** **미해결.** 게이트웨이 차단을 아직 넣지 않았다.
- **재발 방지.** 지우지 않고 **미결로 표에 남겼다**(D-067). 합류 후 1초 안에 죽은 노드는
  `nt≈3` 을 사망시각으로 보고하고, 추정기는 그걸 정상값으로 받아 도착시간장을 오염시킨다.

### 이 4건이 만든 규율 — D-067

> **"실패는 침묵하지 않아야 한다."**
> 어떤 실패가 정상처럼 보이는 화면으로 끝날 수 있으면, **그것을 소리 나게 만드는 것**이
> 그 실패를 고치는 것과 같은 우선순위를 갖는다.

구체적 의무 4가지 — ① 유도할 수 있는 값은 고르지 않는다 ② 불변식은 컴파일 때 막고
**실물 배너에서 다시 보여준다** ③ 정상일 때도 나오는 로그는 눈이 미끄러지므로
시작 3줄·종료 2줄로 **요약을 따로** 낸다 ④ 아직 못 막은 구멍은 **표에 남긴다.**

## 슬라이드 4-H (선택). 「전원은 용량 문제가 아니었다」 — 브라운아웃 추적 [2026-08-30 추가]

**라벨: `공학 성숙도 — 원인을 바꾸지 않고 증거로 좁히기`**

- **증상.** 보드들이 무작위로 재부팅한다. `E BOD: Brownout detector was triggered`.
- **1차 오진.** JSON 버퍼 크기 불일치와 구펌웨어를 원인으로 지목했다. **둘 다 틀렸다.**
  사용자가 "TOPO 에 4대가 보인다는 건 비밀번호가 같다는 증명"이라며 앞선 가설도 기각했다.
  로그를 다시 읽고서야 `BOD` 줄이 보였다 — 원인이 아니라 **내가 안 본 것**이었다.
- **2차.** 급전을 HONOR 65W PD(5 V 3 A)로 바꾸자 90초 무결(BOD 0건).
  같은 조건에서 **HB 가 4대 전부 연속**이 됐다. 여기서 끝난 줄 알았다.
- **3차 — 진짜 조건.** 이후 175초 캡처에서 BOD 5회, 브리지 4회 재부팅.
  급전은 그대로였다. 달라진 것은 **사람이 보드를 손으로 쥐고 있었다는 것** 하나다.
  BOD 최초 발생 시각이 "센서를 잡아 달라"는 요청 직후였다.
- **결론.** 원인은 **충전기 용량이 아니라 기구적 고정과 케이블 스트레인 릴리프**다.
  용량만 키워도 접점이 흔들리면 똑같이 무너진다.
- **데모에 갖는 뜻.** 촬영 중 노드를 손으로 만지는 연출은 **그 자체가 브라운아웃 유발 조건**이다.
  가열은 보드를 쥐지 않고 열원을 센서에 접근시키는 방식으로 바꾼다.
  리허설의 "12분 BOD 0건" 확인도 **만지는 동작을 포함해서** 해야 한다 —
  만지지 않고 통과하는 것은 이 실패를 못 잡는다.
- **측정 설계 변경.** 손으로 쥐어 임계까지 올리는 사망 시험은 폐기하고,
  **t80 교정 3발에 합쳐** 열풍기로 실제 임계까지 올리며 사망 전파 시각을 함께 기록한다.
  실제 데모 조건과 같아지고, 브라운아웃 유발 조건도 제거된다.
