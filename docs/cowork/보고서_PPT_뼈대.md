### 1. 개발 개요  [3P]  〔독창성(동기·배경) + 활용성 도입〕
- **1-1 개발 배경·동기** 🟢 — "재난에선 노드 파괴가 필연" + **의성 동기 2~3문장**(1인칭, 사실 위주).
- **1-2 문제 정의** 🟢 — 위성·드론이 못 보는 **지표 화선 실시간 공백**(진화 지휘·대원 안전 직결).
- **1-3 목표** 🟢 — "고장 패턴을 데이터로 + 자가치유"로 그 공백을 지상에서 채운다.
- **1-4 소스코드·시연영상 링크** ⚪ — 제출 직전 삽입.
> 라벨 예: "본 작품의 **개발 동기·배경**:" / "기존 접근의 공백:"

### 2. 개발 환경  [2·3 합쳐 10P의 일부]  〔기술성("임베디드SW 기술 적용")〕
- **2-1 HW 구성** 🟢 — ESP32×16 + DS18B20 + 배터리(일부) + 라즈베리파이 게이트웨이 + WS2812.
- **2-2 SW 구성** 🟢 — 노드 펌웨어(C/C++·painlessMesh) / 게이트웨이(Python·추정기) / 웹 대시보드.
- **2-3 기능 설계도(아키텍처)** 🟢 — 노드→메시→루트→게이트웨이→대시보드 흐름도.
> 라벨: "**임베디드SW 기술 적용**: ESP32 펌웨어 + 자가치유 메시 프로토콜"

### 3. 개발 프로그램 설명  [핵심, 총 10P]  〔기술성·완성도 30 핵심 + 독창성〕
- **3-1 4대 모듈** 🟢 — ①임종신호 ②자가치유 라우팅 ③**오탐 방어(교차검증)** ④★도착시각 추정.
- **3-2 ★ 도착시각 추정 알고리즘** 🟢 — 죽은 (좌표,시각)→기울기→방향·속도·ETA. 흐름도·의사코드.
- **3-3 오탐 방어(헤드라인)** 🟢 — 통신두절 vs 진짜 파괴 구분(다중이웃+온도 교차검증). **stock 메시가 못 하는 계층.**
- **3-4 파일 구성·함수별 기능** 🟢 — sim/firmware/gateway 구조.
- **3-5 기술적 차별성** 🟢 — "stock vs ours" 비교(연결성만 vs 벡터·ETA).
> 라벨: "**기술적 완성도·구현 여부**: (정량지표 표)" / "**기술적 난이도**: 시계동기·오탐 방어"

### 4. 개발 중 장애요인·해결  [〃]  〔기술성(난이도·문제해결·공학 성숙도)〕 ★차별점
- **4-1 시뮬 선(先)개발** 🟢 — HW 없이 알고리즘 검증(리스크↓).
- **4-2 측정 정직화** 🟢 — 에러바 수선(#2b): 낙관치 교정 → "방향 신뢰·속도 보수적".
- **4-3 하드웨어 괴리 선점** 🟢 — **★시계 동기** 위험 인식 + painlessMesh 동기로 대응, 시뮬 지터로 정량화(#2c).
- **4-4 오탐/비화재 사망** 🟡 — 교차검증으로 방어(#2c·실물 검증).
> 여기가 **연구노트·괴리분석**이 빛나는 자리 = "자기 시스템 한계를 아는 팀" 성숙도 점수.

### 5. 결과물 차별성·우수성  [5·6 합쳐 5P의 일부]  〔독창성(차별성) + 기술성(정량)〕
- **5-1 차별성 표(4축)** 🟢 — 온도스트리밍/Dryad/stock/드론·위성 vs 우리.
- **5-2 정량 성능** 🟡 — 전달률·재라우팅 실측·추정오차·오탐률(실물).
- **5-3 강건성 곡선·작동 한계선** 🟢 — 스트레스 결과(방향 견고·속도 보수).
> 라벨: "**기존·유사제품과의 차별성**:"

### 6. 파급력·기대효과  [5P]  〔활용성 20〕
- **6-1 수요자·의사결정** 🟢 — 지휘부(자원배치) + 대원(대피).
- **6-2 배포 시나리오** 🟢 — 고위험 구역 사전 배치(초저가 촘촘).
- **6-3 시장성·비용** 🟢 — 소모형 저가 논리, 예방 투자 vs 산불 피해.
- **6-4 발전 가능성** 🟢 — 실내화재·가스·붕괴·홍수로 확장(한 줄).
> 라벨: "**기대효과·파급성**:" / "**추후 발전 가능성**:"
