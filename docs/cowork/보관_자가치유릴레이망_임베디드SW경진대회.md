# 보관: 자가치유 릴레이망 (Self-Healing Relay Mesh)
### 임베디드SW경진대회 브레인스토밍 — 이번엔 접지만, 아이디어는 살아있음

> **접은 이유는 아이디어가 나빠서가 아니라 "이번 팀 상황(전자 2-1 수료, vision/신호 강점, 맡기고-검증 방식)이랑 궁합이 안 맞아서"임.**
> 네트워킹/프로토콜 강한 멤버가 생기거나 기간 여유가 있으면 부활 1순위.

---

## 1. 컨셉
아주 작고 값싼 노드를 **수로 압도**하듯 많이 뿌려서 서로 릴레이로 연결. 노드가 파괴돼도 남은 노드들이 **자동으로 경로를 재구성(자가치유)**해서 통신이 끊기지 않음. 핵심 서사: "부서져도 수가 많아 지속 연결." (재난 통신망, 전장·미개척지 탐사 등)

## 2. 왜 강한 아이디어인가
- **SW가 100% 주인공** — 하드웨어는 값싼 노드, 가치는 전부 라우팅/자가치유 로직에 있음. 임베디드SW 대회 성격에 정면으로 부합.
- **데모가 극적** — 노드를 실제로 뽑는 시연이 시각적으로 강렬.
- **팀 자산 재활용** — 기존 sender/receiver UDP 파이프라인이 그대로 기반이 됨.
- 심사 상한(완벽 실행 시)이 요리와 사실상 동점(≈64/90)이었음. 특히 기술성·완성도에서 요리보다 우위.

## 3. 데모 설계 (이미 구체화해둔 것)
1. ESP32 / LoRa / nRF24 노드 **8~10개** 배치 (풀비전 수천 노드의 축소판 — 개념 증명엔 충분)
2. 출발지 노드가 여러 홉 건너 목적지로 데이터 전송
3. 대시보드/LED로 **현재 활성 경로**를 실시간 시각화
4. 전송 도중 **노드 하나를 물리적으로 제거**(전원 차단) → 네트워크가 손실을 감지하고 **경로 자동 재구성**, 데이터는 계속 흐름
5. 정량 지표: **"노드 N개를 죽여도 전달률 100%, 재라우팅 Y초"**

## 4. 독창성 급소 (★ 이게 이 아이디어의 생사)
- **기성 라이브러리(ESP-MESH 등)를 그대로 쓰면 독창성 사망.** 심사위원 질문: "이거 기존 메시 라이브러리랑 뭐가 달라요?" → 답 못 하면 독창성·기술성 동반 폭락.
- 반드시 **우리만의 라우팅/자가치유 로직**이 있어야 함. 예: 극단적 중복성으로 "수로 압도", 대량 노드 손실 시 우아한 성능 저하(graceful degradation).
- 방어 장치: 우리 알고리즘 문서화 + **"우리 프로토콜 vs 기본 라이브러리" 비교실험 수치**.

### ★ 독창성 보강 아이디어 (팀장, 7/16 추가) — "죽는 노드의 행동"
기존 메시(ESP-MESH 등)와 차별화할 핵심 후보. 노드가 죽을 때 그냥 사라지는 게 아니라 **"죽음 특유의 행동"**을 하게 설계:
- **마지막 신호탄(final beacon):** 전원/연결이 끊기기 직전 마지막 힘으로 "나 죽는다 + 마지막으로 본 이웃 정보"를 방송 → 주변 노드가 재라우팅을 *사전*에 준비(사후 감지보다 빠름).
- **죽은 노드를 수동 랜드마크로 재활용:** 통신 불능이어도 물리적 위치는 남으므로, 살아있는 노드들이 "죽은 지점"을 지도/경로 정보로 활용(장애물·위험구역 표식).
- **에너지·자원 회수 개념:** ("몸에 흡수" 아이디어의 현실화 버전) 죽은 노드의 잔여 에너지나 부품을 이웃이 활용 — HW 난도 높아 개념/발전방향용.
> 이 "죽음 행동"이 실제로 **"우리 프로토콜 vs 기본 라이브러리"의 차별점**이 됨. 부활 시 이걸 핵심 셀링포인트로.
> (주의: "몸에 흡수시킨다"의 물리적 버전은 6주·현재 기술로 무리 → 개념/서사용으로만.)

## 5. "활용도 피벗으로 단점 커버?" — 분석 결과: 반창고지 치료 아님
- 참신한 응용을 붙이면 **독창성**은 응용의 신박함으로 어느 정도 방어됨.
- **그러나** 기성 라이브러리+응용만 새로 하면 약점이 **기술성·완성도(30점)로 이사** — "기술적 기여가 뭐냐"에서 깎임.
- 게다가 자가치유(회복탄력성)는 **"노드가 죽는 상황"에서만 빛남.** 응용이 그 회복탄력성을 진짜로 요구하지 않으면 세일즈포인트가 장식이 됨.
- → 활용도 피벗은 **회복탄력성이 핵심인 응용에서만** 유효. 아래 후보 참고.

## 6. 회복탄력성이 "진짜 핵심"이 되는 응용 후보 (부활 시 검토)
- 재난지 임시 통신망 (기지국 붕괴 시)
- 소방관 실내 통신·위치 (건물 내부 GPS/통신 두절 환경)
- 산악/산불 현장 안전망
- 초밀집 환경(축제·콘서트) 통신
- 축사·농장 초저가 광역 센서망

## 7. 실현 리스크 (이번에 접은 직접 원인)
- **독창성이 "발명"에 걸림** — 새 분산 라우팅 알고리즘은 사실상 연구급. AI가 제안해도 **네트워킹 지식 없이는 옳은지/새로운지 검증하기 어려움.** (요리는 검증이 vision/신호 홈그라운드라 정반대)
- 노드 10개 분산 펌웨어 디버깅 = 네트워킹 경험 없으면 난도 높음.
- 풀비전(수천 노드)과 데모(10노드)의 **스케일 괴리**가 커서 "말문 막히는" 질문 리스크.

## 8. 부활 조건
- 펌웨어·네트워킹·분산시스템에 강한 팀원 합류, **또는**
- 기간이 넉넉한 프로젝트(6주 초과), **그리고**
- 기성 라이브러리를 넘는 **자체 프로토콜 아이디어**가 확보될 때
