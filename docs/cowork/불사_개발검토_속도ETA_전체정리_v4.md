# 「불사」 / 화중생련 — 속도·ETA 추정의 진단·재구성·정직한 구간화
### 개발 검토 문서 **v4** · 2026-07-30 스냅샷 (Step 2.F까지 반영)
_실패를 데이터로 쓰는 자가치유 산불 감시 메시에서, 마지막 약점(속도/ETA)을 하드웨어 없이 정면으로 다룬 전 과정._

> **이 판(v4)이 v3와 다른 점.** 사용자 피드백대로 **용어 해설 방식을 완전히 바꿨다.** 이전엔 이미 뻔한 것에 비유를 붙이고 정작 벽이 되는 용어(나이퀴스트, 자유도 0 등)는 비유로 얼버무렸다. v4에서는 — **깊이·수식은 그대로 두고, 잘 안 쓰이는 용어가 나오면 그 자리 괄호에 개념 정의를 붙인다(“이런 뜻이다”). 과잉 설명은 허용하되 설명 부족은 금지** — 용어를 정의 없이 지나치지 않는다. (이 규칙은 §0에 강령으로 명문화했고 대화에서도 동일하게 적용한다.)
>
> **읽는 법.** 급하면 1장(개요)만. 곱씹으려면 5장을 순서대로. 처음 보는 용어는 나오는 그 자리에서 정의를 붙여뒀으니 막히지 않고 끝까지 읽을 수 있다. 숫자는 전부 실제 측정값이고, **내 가설이 반증된 대목도 그대로** 적었다(§5.6이 그 정점).

## 0. 강령 — 소통·작업 규칙

**소통 규칙 (v4에서 확정):**
1. **“이해 우선” 전제.** 목표는 사용자가 **깊이 이해하되 용어 때문에 막히지 않는 것.**
   - (a) 실제 메커니즘·엄밀함은 **그대로 유지**한다(쉬운 요약으로 대체하지 않는다).
   - (b) 잘 안 쓰이는 용어가 나오면 **그 자리 괄호에 개념 정의**를 붙인다(“*이런 뜻이다*”). 큰 비유로 개념을 대체하지 않는다(비유는 정의를 붙인 뒤 보조로만).
   - (c) **과잉 설명은 허용, 설명 부족은 절대 불가.** 벽이 될 수 있는 용어를 정의 없이 지나치지 않는다.
   - (d) 이 규칙은 문서뿐 아니라 **대화(chat)에도 동일 적용.**
2. **억빠(무근거 띄우기) 금지.** 필요 없으면 객관적으로 “필요 없다”고 말한다.
3. **틀리면 즉시 인정**하고, 반증된 가설은 숨기지 않고 기록한다(실제 사례가 이 문서에 그대로 있다, §5.6).
4. 소요 시간을 과대추정하지 않는다.

**작업 규율 — measure-first**(*결과=테스트 점수를 보기 전에 물리·기준선에서 파라미터를 정하고, 나쁜 결과도 그대로 기록하는 규율*):
1. 시드 고정, 결과 좋아 보이게 파라미터 튜닝 금지 — 기록만.
2. 임계값·파라미터는 물리 또는 baseline(*S1 = 바람·돌풍·노이즈가 없는 기준 시나리오*) 분포에서, 테스트 점수를 보기 전에 도출. 도출용(S1)/평가용(S2~S11) 데이터 분리.
3. 원본을 항상 baseline으로 보존하고 나란히 비교.
4. 방향이 나빠지면 그 방법은 불채택(방향이 우리 헤드라인).
5. null 결과(가설이 반증돼도)도 그대로 보고.

## 1. 개요 (한 페이지 요약)

**무엇을 만드는가.** 산불 감시용 무선 센서 **메시**(*mesh = 노드들이 서로 무선으로 연결돼 정보를 릴레이하는 그물망 네트워크*). 각 **노드**(*node = 온도를 재고 통신하는 개별 센서 장치*)는 온도를 재고 서로 통신한다. 불이 번지면 노드가 하나씩 타 죽는데, 우리는 그 **죽음을 “고장”이 아니라 “측정값”으로** 쓴다. 죽은 시각과 위치를 모으면 **화선**(*fire front = 불이 번져나가는 최전선의 선*)의 진행 방향과 속도를 역산할 수 있다.

**핵심 수학.** 노드가 죽은 시각 = 불이 그 자리에 도착한 시각. (x, y, 죽은시각) 점들에 기울어진 판 하나를 끼워 맞추면(**평면 최소제곱 적합** = *흩어진 점들로부터, 점들과의 수직거리 제곱합이 가장 작아지는 평면 하나를 찾는 계산*), 그 판의 기울기가 불의 방향·속도를 준다.
- **방향 = ∇T/|∇T|** (∇T = *그 평면이 어느 방향으로 얼마나 가파르게 기울었는지를 나타내는 벡터, ‘그래디언트’*; /|∇T| = *그 벡터를 자기 크기로 나눠 크기 1의 방향만 남기는 것, ‘정규화’*). 정규화라 노이즈에 **튼튼함. 현재 2.1°** (16노드).
- **속도 = 1/|∇T|** (**역수** = *어떤 수 x에 대해 1/x*). 나눗셈이라 작은 오차가 증폭됨. **여기가 남은 유일한 약점.**

**이 작업(#2e-3)의 결론을 미리:**
1. **방향은 자랑할 수준(2.1°), 속도 점 추정은 원리적 한계가 있다** — 측정으로 확정.
2. 속도 오차를 분해: **바람 곡률(모델 한계) + 돌풍의 나이퀴스트 한계(진짜 물리) + 희소 노드의 자유도 0(구조 한계).** “물리적 한계”라 부를 자격이 있는 건 **돌풍의 일부(41~61%)뿐**, 나머지는 방법 탓.
3. 역수를 없애는 재구성(방법 A)은 **부분 성공** — 방향은 완벽 보존, 속도 편향은 15~26%만 감소. **기본값 승격 안 하고 병행 보존.**
4. 그래서 속도를 거짓 점 숫자가 아니라 **정직한 구간(밴드)**으로 판다: “ETA 4:12”가 아니라 **“ETA 0.7~1.7분(90% 구간)”**. 시뮬 안에서 커버리지 89~100%로 작동.
5. **밴드는 공짜가 아니다.** 밴드의 편향 보정이 시뮬 파라미터(warm_scale)에 의존 → **강건성 게이트(Step 2.F)** 결과 **밴드를 1.43배 넓혀야(E3x)** “warm_scale ±50% 틀려도 안전” 주장이 가능. 실물 단측 신뢰도 **~91%**.

**한 문장으로:** _속도 점 추정의 한계를 측정으로 확정하고, 거짓 정밀도 대신 검증된 구간으로 전환했으며, 그 구간이 어떤 전제 위에 서 있고 얼마나 넓혀야 그 전제 없이도 버티는지까지 밝혔다._

## 2. 배경과 문제 정의

### 2.1 왜 “실패를 데이터로” 인가 — 관점의 독창성

**자가치유 메시**(*self-healing mesh = 노드가 죽으면 남은 노드들이 자동으로 통신 경로를 다시 잇는 그물망*)는 이미 표준 기술이다(ESP-MESH, Zigbee, Thread, painlessMesh). **그러니 “자가치유를 우리만 한다”는 거짓이다.** 독창성은 기술이 아니라 **관점과 조합**:

> 보통의 메시는 노드가 왜 죽었는지 **구별할 이유가 없다** — 그냥 우회하면 되니까. 우리는 **죽음 자체를 신호로 쓰기 때문에** 그 구별이 필수가 된다.

**세계 최초 같은 주장은 하지 않는다.**

### 2.2 수학적 뼈대 — 도착시각장과 평면 적합

**도착시각장**(*arrival-time field = 각 위치에 불이 몇 초에 도착했는지를 위치의 함수로 나타낸 값들의 지도*): 노드 i가 죽은 시각 t_i가 곧 그 위치 (x_i, y_i)에서의 불 도착시각이다.

화선이 방향 **û**로 등속 v로 곧게 전진하면, 도착시각은 위치에 대해 **평면**을 이룬다:
```
T(x, y) ≈ a·x + b·y + c   (기울기 벡터 ∇T = (a, b))
```
흩어진 (x_i, y_i, t_i) 점들에 이 평면을 최소제곱으로 맞추면 ∇T가 나온다.
- 불이 다가오는 방향 = ∇T 방향.
- **속도 = 1/|∇T|** (기울기가 가파를수록 = 단위거리당 도착시각 차가 클수록 = 느림).

### 2.3 방향과 속도의 비대칭 — 이 프로젝트의 중심 긴장

같은 ∇T에서 나오는데 **방향은 튼튼하고 속도는 약하다.** 순전히 연산 구조 탓:
- 방향은 `∇T/|∇T|` — 정규화(크기로 나눠 방향만). ∇T에 노이즈가 실려도 방향은 잘 안 흔들린다.
- 속도는 `1/|∇T|` — 역수(나눗셈). |∇T|가 조금만 틀려도 역수는 크게 튄다.

그래서 처음부터 **방향 = 자랑거리, 속도 = 숙제**였고, 모든 결정에서 **“방향이 나빠지면 그 방법은 버린다”**가 통과 조건이 됐다.

### 2.4 하드웨어·시스템 개요

Arduino-ESP32 + **painlessMesh**(*ESP32용 메시 통신 라이브러리*; `getNodeTime()`으로 메시 전체 시간동기 → 노드마다 시계 어긋남은 이미 처리) + DS18B20 온도센서 + WS2812 LED + 라즈베리파이 게이트웨이. **16노드 약 449,760원.** 부품 도착 대기(~1주). **현재까지 모든 결과는 시뮬레이터**에서 나온 것이고, 이 구분은 문서 전체에서 엄격히 지킨다.

## 3. 방법론 — 왜 정직성이 무기인가

차별점은 **정직성**이다. 과장은 우리에게만 유독 비싸다 — 심사에서 한 번 뽑히면 신뢰 전체가 무너진다. 그래서 §0의 measure-first를 매 단계 지켰고, **그 규율이 실제로 여러 번 가설을 잡아냈다**(4·6장·§5.6).

## 4. 여기까지 온 검증 체인 (#2e-3 이전 요약)

속도 문제 전에, **오탐**(*false positive = 실제로는 아닌데 화재 사망으로 잘못 판정하는 것*)과 비화재 사망 오염을 먼저 정리했다.

- **#2c:** 클럭 지터(*clock jitter = 노드마다 내부 시계가 조금씩 어긋나 흔들리는 것*) 300ms에서도 방향 2.13°로 안전 확인. + **비화재 사망 오염** 발견 — 불이 아니라 배터리·고장으로 죽은 노드를 화재 사망으로 세면 화선 계산이 오염된다.
- **#2d:** “불에 타 죽으려면 자기 온도가 올랐어야 한다”는 물리로 **교차검증 3분기**(*세 갈래 판정 규칙*) 설계. ① 실제 수신 최고온도 rep_peak(*god-view 정답이 아니라 메시가 실제로 수신한 온도의 최고값*) ≥ 60℃면 무조건 화재 ② 자기도 이웃도 춥다 → 제외 ③ 자기는 춥고 이웃은 뜨겁다 → 잔차(*추정과 실제의 차이*) 일관성 검사(2.0s 게이트).
- **#2e-1:** 오분류율 대신 **실제 ‘해악’을 측정**하자 **가설이 반증**됐다 — 찬(COOL) 비화재 사망이 잘 막힐 거라 봤는데 실측 통과율 86.4%로 오히려 더 높았다.
- **#2e-2 → Fix A:** 엄격판(Fix A) vs dT/dt 게이트판(Fix B) 나란히 측정 → **Fix A 채택**(새 파라미터 0개). COOL 비화재 통과율 **86.4% → 0%**.

**측정으로 확정된 헤드라인:** 오탐 Type A(*살아있는데 죽었다 오판 — 통신두절을 사망으로 착각*) **측정 전 구간 0%**, 방향 **2.1°**(16노드; 밀도별 9→4.32° / 12→2.9° / 16→2.12° / 25→1.23°, **12개 이상 안정**). **유일하게 남은 약점 = 속도/ETA** → #2e-3 시작.

## 5. #2e-3 — 마지막 약점(속도/ETA) 정면 공략

작업을 **Step 1(진단) → 2.0(floor 정당성 감사) → 2.A(역수 제거) → 2.E(정직한 구간) → 2.F(강건성 게이트)**로 나눴다. “고치기 전에 먼저 잰다”가 원칙.

### 5.1 Step 1 — 진단 (추정기 불변, 측정만)

**동기.** 속도 오차가 S2a(바람) 29.9%, S6(9노드) 34.5%, S7(복합최악) 26%인데 **어디서 오는지 모르는 상태.** 고치기 전에 분해한다.

**1a · 부호 포함 오차 → 전부 양(+), 계통 상향 편향.**

| 시나리오 | 평균 % | 판정 |
|---|---|---|
| S1(기준) | −0.10 | 결정론 |
| S2a 바람 5/10/20° | +7.75 / +16.31 / +29.80 | 편향 지배 |
| S2b 돌풍 20/40% | +7.21 / +19.90 | 산포/편향 |
| S6 9노드 | +34.55 | 순수 편향 |
| S7 복합최악 | +24.99 | 편향 지배 |

부호가 예외 없이 +. `속도 = 1/|∇T|`의 **역수 서명**이다 — **Jensen 부등식**(*볼록함수 f에서 “평균의 함수값 ≤ 함수값의 평균”, 즉 f(E[X]) ≤ E[f(X)]. 여기서 f가 1/x(볼록)라, |∇T|에 평균 0인 노이즈가 실려도 그 역수의 평균은 참값의 역수보다 커진다*)으로 속도가 위로 치우친다. 즉 **“왜 속도가 항상 빠르게 나오나”의 정체가 이 나눗셈**이다.

**1b · 환원 불가 하한(floor).** **floor**(*아무리 좋은 방법을 써도 못 내려가는 오차의 바닥값*) = “실제 화선 속도가 시간에 따라 진짜 변하니, 단일 숫자로 요약하는 순간 못 넘는 바닥.” **단, 이 floor의 정의에 결함이 있었고 2.0에서 드러난다.**

**1c · 오라클 절단**(*oracle ablation = 시뮬레이터가 아는 ‘정답’ 정보를 하나씩 일부러 제거·주입해가며, 각 노이즈원이 오차에 얼마나 기여하는지 분리하는 실험*) **→ 지배 입력은 사망시각 노이즈.** 그리고 **9노드 붕괴의 정체 = 자유도 0**(아래 상자)을 규명. 경고 하나 — 표본을 전역으로 합치면 S1이 0.10→8.64%로 악화 → 뒤의 방법 A는 역수만 없애고 로버스트(*이상치·노이즈에 잘 안 흔들리는 성질*) 집계는 유지해야 한다.

> ### 📦 “희소 노드의 자유도 0”이 뭔 소리인가 (★벽 용어)
> **자유도**(*degrees of freedom, DOF = 데이터 점의 개수 − 구하려는 미지수의 개수. 즉 답을 정하는 데 꼭 필요한 최소한을 넘어서 “남는” 측정치의 수*)가 핵심이다. 이 남는 여분이 있어야 측정 오차를 서로 견주어 걸러낼 수 있다.
>
> 우리는 기울어진 평면 `T = a·x + b·y + c`를 맞추는데 미지수가 **a·b·c 세 개**다. 그런데 9노드 그물에서는 한 노드의 국소 이웃이 3개뿐이라, 국소 적합에 요구하는 최소 이웃 수(min_samples=3)에 딱 걸린다. 데이터 점 3개, 미지수 3개 → **자유도 = 3 − 3 = 0.**
>
> 이러면 평면이 세 점을 *정확히* 통과하지만(잔차 0), 그 완벽함은 **가짜**다 — 여분이 0이라 세 점에 실린 측정 오차가 **감쇠 없이 그대로** 기울기에 박히고, 속도(=1/|∇T|)의 역수가 그걸 또 증폭한다. (미지수 n개짜리 맞춤에 점이 딱 n개면 늘 이렇게 된다. 점 2개로 직선 하나를 그으면 항상 정확히 지나가지만 그 두 점이 틀렸는지는 알 길이 없는 것과 같은 원리.) 그래서 노드가 촘촘해야(12개+) 안정된다.

**1d · ★ 최대 수확 — ETA에 속도와 무관한 −6.4초 상수 편향.** 노드는 자기 온도가 임계(*마지막 보고를 내는 기준 온도, 80℃*)에 닿을 때 마지막 보고를 낸다. 그 순간 화선은 아직
```
d = warm_scale · ln((peak−ambient)/(threshold−ambient)) = 6·ln5 = 9.657 m 앞
```
에 있다 (**warm_scale** = *불의 열이 화선 앞쪽으로 감쇠하며 미치는 거리 척도. 온도가 화선에서 거리 d만큼 떨어질수록 exp(−d/warm_scale)로 줄어드는 그 warm_scale. 클수록 열이 멀리까지 미친다. 시뮬에선 6m*; ln = 자연로그) → 1.5 m/s에서 **선행 6.438초**. 즉 노드가 “마지막!”이라 외칠 때 불은 아직 9.7m 앞이라, “죽은 시각 = 불 도착”으로 보면 항상 **6.4초 이르게** 잡힌다. 방향·속도엔 영향 없고 ETA(도착예측)만 통째로 당겨진다. **다행히 이르게 = 조기경보 = 안전한 쪽.**

**Step 1 결론:** 오차 주범은 ① 사망시각 노이즈가 역수를 통과하며 만드는 상향 편향(속도) + ② 임계온도 보고가 만드는 −6.4초 상수 선행(ETA). **권고 CONTINUE.** 기록 D-037.
> **여기서 사용자가 결정적 조건을 걸었다:** “그 floor가 정말 물리적 한계인지, 방법이 틀린 걸 자연법칙인 척하는 건 아닌지 검토하라.” → Step 2.0.

### 5.2 Step 2.0 — floor 정당성 감사: “물리인가, 방법인가”

**동기.** “floor = 물리적 한계”라는 서술은 **반대 방향의 과장**이 될 수 있다 — 고칠 수 있는 약점을 자연법칙인 척 변명하는 것. 의심할 증거가 이미 있었다: **S2a(정상 바람)는 참 속도가 시간에 안 변하는데(std 0%) floor가 0이 아니었다.** (**std** = *표준편차, 값들이 평균 주위로 흩어진 정도*.)

**감사 설계:** 하나로 뭉친 floor를 갈래별로 쪼개고, 오직 진짜 물리인 갈래만 “물리적 한계”라 부를 자격을 준다.

**★ 자기 정정 1 — floor를 잰 코드가 배포판과 다른 추정기였다.** floor는 `global_fit=True`(*전 노드에 평면을 딱 하나만 맞추는 방식*)로 쟀는데, 실제 배포판은 “국소 적합 + per-node 중앙값”(*노드마다 자기 주변만으로 따로 맞춘 뒤, 그 값들의 중앙값 = 순서상 가운데 값으로 대표시키는 방식. 평균보다 튀는 값에 강함*)이다. 분자(관측)와 분모(floor)가 **다른 자로 잰** 셈. 같은 배포판으로 다시 재니:

| 시나리오 | 관측 | floor(배포판) | 비중 | (D-037 보고) |
|---|---|---|---|---|
| S2a 10° | 16.33 | 3.87 | 23.7% | (12.9%) |
| S2a 20° | 29.92 | 11.69 | 39.1% | (20.9%) |
| S2b 20% | 9.04 | 4.58 | 50.7% | (67.2%) |
| S2b 40% | 16.73 | 12.79 | 76.5% | (80.6%) |
| S6 9노드 | 34.55 | 0.00 | 0.0% | (0.0%) |
| S7 | 22.63 | 8.25 | 36.4% | (35.3%) |

**★ 자기 정정 2 — 돌풍 floor의 35~38%는 허수.** 등속 추정치를 명목 상수(1.5)가 아니라 **관측창 평균 참속도**(*그 관측 구간 동안의 진짜 속도의 평균*)에 견주면 floor가 준다(S2b40% 19.54→12.79 등). 순간순간과 비교하면 억울하고, 코스 평균과 견주는 게 공정한 채점이다. 바람만 있는 S2a는 참속도가 상수라 이 허수(F_metric)가 0.

**정본 floor 장부 (기준 = 관측창 평균 참속도):**

| 시나리오 | Step1 보고 | +정의보정 | −허수제거 | → 정본 floor | 그중 곡률(F_spatial) |
|---|---|---|---|---|---|
| S2a 5/10/20° | 1.11/2.10/6.24 | −0/+1.77/+5.45 | 0 | **1.11/3.87/11.69** | 전부(곡률) |
| S2b 20/40% | 8.19/17.57 | +1.36/+1.97 | −4.96/−6.74 | **4.58/12.79** | 0/0 |
| S7 | 9.17 | +3.82 | −4.74 | **8.25** | 3.87 |
| S1·S4·S6 | 0 | 0 | 0 | **0** | 0 |

**floor를 네 갈래로 최종 분해 (각 정의):**
- **F_metric** = *채점 기준을 잘못 잡아(순간참값 대비) 생긴 허수 오차.* → 제거. 물리도 방법도 아님.
- **F_spatial(곡률)** = *바람이 화선을 휘게 만드는데 우리는 곧은 평면으로 근사해서 생기는 모델형 오차.* 더 나은 모델로 줄일 수 있음 = **방법 탓.**
- **F_temporal(등속 가정)** = *속도가 시간에 변하는데 하나로 요약해서 생기는 오차.* 시간창 추적(방법 B)이 회수 가능 = **방법 탓.**
- **F_sampling(나이퀴스트)** = 아래 상자. **오직 이것만 진짜 물리.**

> ### 📦 “돌풍의 나이퀴스트”가 뭔 소리인가 (★벽 용어)
> 돌풍 속도는 여러 빠르기의 흔들림(사인파)이 겹친 것이다. **나이퀴스트 한계**(*Nyquist limit = 어떤 변화를 일정 간격으로 띄엄띄엄 측정할 때, ‘측정 간격의 2배보다 짧은 주기로 흔들리는 성분은 측정값에 정보가 안 남아 원리적으로 복원 불가능하다’는 신호처리의 기본 정리*)가 여기 걸린다. 두 번 재는 사이에 흔들림이 한 번 넘게 왔다 가버리면, 그게 있었다는 흔적조차 안 남기 때문이다.
>
> 우리 시스템에서 “측정”은 **노드가 죽는 사건**이다. 노드 간격 10m, 불 속도 1.5m/s면 노드는 약 **6.67초에 하나씩** 죽는다(= 화선 위치를 6.67초마다 한 번 찍는 셈. 이 간격을 *사망 케이던스*라 한다: Δt = 간격/속도 = 10/1.5 = 6.67s). 나이퀴스트에 따라 우리가 볼 수 있는 최소 주기는 2 × 6.67 = **13.3초.** 그런데 돌풍의 흔들림 성분 중 **주기 11.4초짜리**는 13.3초보다 빨라서 두 죽음 사이에 왔다 가버린다 → 정보가 애초에 안 담겨 어떤 알고리즘으로도 복원 불가 = **환원 불가능한 오차 바닥.**
>
> **한 가지 더:** 이 한계선은 고정이 아니다 — 불이 느려지면 노드가 더 뜸하게 죽어(케이던스가 길어져) 더 못 본다. 그래서 경계 주파수가 순간속도에 따라 움직인다(돌풍 40%에서 사망 케이던스 4.19~18.00초로 출렁). 이걸 반영한 정확값이 아래 표의 F_sampling이다.

**돌풍 시간항 분해 (기준 = 순간참값):**

| 시나리오 | 등속 총오차 | F_temporal(B가 회수) | **F_sampling(★물리)** | F_residual(관측가능·미회수) | **물리 비중** |
|---|---|---|---|---|---|
| S2b 20% | 15.46 | 2.65 | **6.62** | 6.20 | **42.8%** |
| S2b 40% | 38.71 | 6.62 | **23.71** | 8.38 | **61.2%** |
| S7 | 15.83 | 1.48 | **6.52** | 7.83 | **41.2%** |

물리 floor를 **ETA 초로 환산**(우리가 실제로 파는 것): 100m에서 20% 돌풍 **4.4초**, 40% 돌풍 **15.8초**.

**한 줄 판정:** **돌풍 floor 중 실제 물리는 41~61%, 나머지 39~59%는 방법(채점착오+곡률+등속가정).** 70% 미충족 → 멈추지 않음. **S6 9노드 34.55%는 floor 0% = 100% 방법 → A의 1순위 표적.** S2a 20° 개선 여지는 D-037 추정보다 작음(방법 몫 79.1%→60.9%, 정직 하향). 기록 D-038.
> **사용자의 원래 의심이 옳았다:** 오직 돌풍만 진짜 물리 floor를 가지며, 그마저 67~81%가 아니라 **41~61%**였다. S2a 곡률·S6 희소는 **100% 방법.**

### 5.3 Step 2.A — 역수 제거 (속도 재구성)

**설계.** 방향 **û**는 기존 결과 재사용(2.1°, 손대지 않음). 각 사망 노드의 축좌표 `s_i = p_i·û`(*화선 진행 축에 노드 위치를 투영한 값*)를 사망시각 `t_i`에 **회귀**(*regression = 점들의 추세를 가장 잘 나타내는 직선을 찾는 것*)한 기울기가 곧 속도 — **나눗셈 없음.** 회귀도 로버스트 방식(Theil–Sen/Huber = *튀는 값에 덜 휘둘리도록 설계된 회귀*), 하이퍼파라미터(*사람이 미리 정하는 설정값*) 기본값(스윕 = *값을 이리저리 바꿔 최적을 찾는 것* 금지).

**★ 방향 비열화 — 완전 통과.** 전 12 시나리오 최대 차이 **0.000e+00°**(비트 단위로 동일). 방향 계산에 원 결과만 쓰도록 **구조적으로 차단**하고 실측 재확인. 불채택 사유 없음.

**속도 결과 (기준 = F_sampling 물리):**

| 시나리오 | F_samp(물리) | base | A | 상대 감소 | 판정 |
|---|---|---|---|---|---|
| S1 | ≈0 | −0.10 | −0.10 | 0% | ✅ |
| S2a 5/10/20° | ≈0 | +7.75/+16.31/+29.80 | +5.70/+13.94/+24.78 | −26/−15/−17% | ❌ 미달 |
| S2b 20/40% | 6.62/23.71 | +4.60/+14.17 | +4.50/+14.60 | −2%/+3%악화 | 돌풍 한계 |
| S4 20/40% | ≈0 | +0.69/+1.92 | +0.51/+0.86 | −26/−55% | ✅ |
| S6 9노드 | ≈0 | +34.55 | +25.48 | −26% | ❌ 미달 |
| S6 12/25노드 | ≈0 | +0.56/+0.09 | +0.58/+0.09 | ~0 | ✅ |
| S7 | 6.52 | +21.88 | +18.70 | −15% | 돌풍 한계 |

**★ 정직 보고 — 가설 3개가 반증됐다.**
1. **+ 편향이 사라지지 않았다.** 12개 전부 여전히 +. “역수가 주범”은 편향의 **15~26%만** 설명.
2. **9노드는 물리 하한(≈0)에 도달 못 함**(25.48% 잔존). 자유도 0 문제는 역수를 없앤다고 안 풀린다 — û가 같은 3점에서 나와 애초에 재료가 부족하기 때문.
3. **1/cos δ**(*추정 축과 참 방향이 δ만큼 어긋나면 투영 거리가 짧아져 속도가 1/cos δ배 부풀려진다는 가설*)**도 기각.** 예측 0.2~2.4% vs 실측 13.9~25.5%.
4. **잔여 기제는 규명 못 함. 지어내지 않고 그대로 적는다.** 후보(화선과 거의 평행한 노드 쌍이 중앙값을 끌어올림)는 임계 도입 = 새 파라미터 = 스윕 위험이라 손대지 않음.

**권고(과장 없이): A를 기본값 승격하지 말고 병행 보존.** ① 이득 작고 작동 한계선(9노드 여전히 25%대 → “12노드+” 서사) 하나도 못 움직임 ② 돌풍 소폭 악화 ③ 잔여 기제 미규명. **이 단계의 진짜 가치는 “속도 점 추정으로는 여기까지”라는 경계 확정** → 2.E가 본체. 기록 D-039.

### 5.4 Step 2.E — 거짓 점 숫자 대신 정직한 구간(밴드)

> ### 📦 “밴드”가 대체 무슨 구조이고, 왜 가짜 점보다 나은가 (★벽 개념)
> **밴드**(*band / interval = 하나의 숫자 대신 “정답이 이 범위 안에 있다”고 주는 구간 추정치*).
>
> **1단계 — 점 추정의 문제.** 지금까진 “불이 67초 뒤 도착”이라고 숫자 하나를 뱉는다. 그런데 이 숫자가 **정해진 방향으로 틀린다**는 걸 측정으로 안다(−6.4초 상수 + 속도 과대 → 항상 좀 이르게). 즉 점 하나는 **자신 있게 거짓말**을 한다.
>
> **2단계 — 순진한 밴드(E1/E2)와 왜 실패했나.** 발상: 노드마다 속도 추정이 조금씩 다르니 그 흩어진 정도로 구간을 만들자. **실패했다(커버리지 0~34%).** 이유 — 문제의 편향은 **모든 노드가 똑같이 공유(공통 모드)**한다. 동네 사람 시계가 다 같이 10분 빠르면, 서로 비교(내부 산포)해서는 그 공통 10분을 절대 못 찾는다. E1/E2가 딱 이것 — 밴드는 좁은데 통째로 엉뚱한 자리에 놓였다.
>
> **3단계 — E3, 해결책.** 공통 편향은 안에서 안 보이니 **밖에서(정답을 아는 S1에서) 재서 보정**한다. S1을 여러 번 돌려 “예측 ETA vs 진짜 ETA” 오차 분포를 거리별로 기록 → “100m에서는 보통 −48.7초에서 −6.3초만큼 이르게 나온다”는 **보정 항**을 얻는다. E3 = 원래 점 추정에 이 측정된 보정 범위를 더해 **구간**으로 만든 것.
>
> **4단계 — 왜 가짜 점보다 나은가.** 점은 자신 있게 틀린다. 밴드는 “진짜 값은 이 안 어딘가이고, **실제로 90% 확률로 이 안에 들어옴을 내가 확인했다**”고 말한다. 밴드의 가치는 **정밀함이 아니라 신뢰성**이다 — “불은 이 시각보다 일찍 오지 않는다”에 기대 대피 결정을 내릴 수 있고, 그 말이 측정상 실제로 지켜진다.
>
> **5단계 — 대가.** 그 보정을 **시뮬(S1)에서 배웠으니 시뮬의 warm_scale에 의존**한다 → 그래서 강건성 게이트(2.F)가 필요하다.

**커버리지 표 (명목 90%, 평가 전부 S2~S11):** (**커버리지** = *“90% 구간”이라 선언한 구간 안에 실제 참값이 들어온 비율. 선언과 실제가 맞으면 정직한 구간*.)

| 시나리오 (30/60/100m) | E2 커버 | **E3 커버** | E3 밴드(초, 100m) | ★위험측 |
|---|---|---|---|---|
| S1 | 0/0/0% | **100/100/100%** | 41.7~99.5 | 0/0/0% |
| S2a 20° | 1.6/8.1/13.6% | **85.0/87.4/89.1%** | 26.9~89.1 | 1.0/0.8/2.0% |
| S2b 40% | 19.8/25.8/34.3% | **88.9/86.9/93.1%** | 35.4~109.1 | 5.1/4.6/1.4% |
| S6 9노드 | 0/0/0% | **100/100/100%** | 34.6~87.1 | 0/0/0% |
| S7 최악 | 7.0/15.4/21.7% | **93.2/90.8/88.8%** | 35.2~98.7 | 0.4/0.2/0% |

**E3: 33개 셀 중 28개 ≥90%, 미달 5개도 85~89.1%.**

> ### 📦 “커버리지가 작동한다”는 게 노이즈를 그 %만큼 줄였다는 뜻인가 (★벽 개념)
> **아니다. 전혀 다른 개념이다.** 커버리지 = **“우리가 그린 구간 안에 진짜 답이 실제로 들어온 비율”.** “90% 구간”이라 말하고 실제로 89% 들어오면 → **정직한(잘 보정된) 밴드.** 34%만 들어오면(E2) → **거짓말하는 밴드**(90%라 해놓고 3번에 1번밖에 안 맞음). 일기예보관이 “비 올 확률 90%”라 한 날 중 실제로 90%쯤 비가 와야 정직하다고 하는 것과 같다. **오차(밴드 폭)를 몇 % 줄였다는 얘기가 전혀 아니다** — 폭은 그대로 두거나 넓히면서, 그 폭 안에 답이 약속대로 들어오느냐만 본다.

**위험측 초과율.** **breach_early**(*참 도착시각이 밴드의 가장 이른 끝보다 더 일렀던 = 불이 최조기 예측보다 먼저 온 비율. 안전상 위험한 실패*)를 ★위험으로 정의. **E3 최악 5.1% → 단측 신뢰도 ~95%**(단, 이건 **시뮬 캘리브레이션이 완벽할 때** — 실물 기준은 2.F에서 ~91%로 내려간다). (**단측 신뢰도** = *“불은 이 시각보다 일찍 오지 않는다” 같은 한쪽 방향 주장이 지켜지는 비율*.) E2는 최악 2.1%로 더 좋아 보이지만 중앙 커버리지가 붕괴한 못 쓰는 밴드라 그 낮은 수치는 오배치의 부산물 — **쓸 수 있는 건 E3뿐.**

**★ 부수 발견 — 런타임(*실제 작동 중*) 관측량은 참 오차를 예측 못 한다.** 노드별 산포/IQR(*값들을 크기순 정렬했을 때 가운데 50% 구간의 폭*)/잔차 RMS(*잔차 제곱평균의 제곱근, 전형적 잔차 크기*)/노드 수 어느 것도 참 오차를 못 따라간다. **결정적 반례: S6 9노드는 오차 최대(34.55%)인데 산포 최소(32.87%)** — 자유도 0이라 국소 적합이 ‘정확히’ 맞아 산포가 오히려 작아진다. → **시스템은 자기가 얼마나 틀렸는지 자기 내부 신호로는 알 수 없다.** 그래서 보정을 밖(S1)에서 가져와야 하고, 그게 warm_scale 의존 문제를 낳는다.

**도출/평가 분리:** 밴드 배율 k는 S1에서 k=1일 때 커버리지 100% → k=1 확정. 편향 항도 S1에서만 도출(30m [−19.42,−6.34]/60m [−31.96,−6.33]/100m [−48.67,−6.31]s). 커버리지는 전부 S2~S11에서 평가. 기록 D-040.
> **⚠ 이 시점의 경고:** E3의 편향 항이 시뮬 warm_scale에서 나온 값이라 **커버리지 89~100%는 “시뮬 캘리브레이션이 맞을 때”**의 값이다. 실물 유효는 아직 증명 안 됨 → **강건성 게이트(2.F)가 필요.**

### 5.5 Step 2.F — 강건성 게이트 (E3 실물 주장의 전제) ✅완료

> ### 📦 “강건성 게이트”가 뭔데 왜 꼭 먼저 통과해야 하나 (★벽 개념)
> **강건성 게이트**(*robustness gate = 시스템이 가정한 값이 실제와 다를 때도 성능이 무너지지 않는지 일부러 틀린 값을 넣어 시험하는 관문. ‘게이트’ = 통과해야만 다음 주장을 할 수 있는 검문소*).
>
> E3의 보정은 **시뮬의 warm_scale(6m)을 정답으로 놓고** 배웠다. 그런데 **실물의 warm_scale은 연료·습도·바람에 따라 달라지고 우리가 정확히 모른다.** 그래서 warm_scale을 일부러 ±20/30/50% 틀리게 준 세계에서 밴드가 약속을 지키는지(진짜 답이 여전히 구간 안에 드나? 위험한 쪽으로 새지 않나?) 시험한다.
>
> **왜 꼭 먼저(선적용)?** 그냥 배포했다가 실물 warm_scale이 다르면 밴드가 **조용히, 그것도 위험한 방향으로** 깨진다(“불이 예상보다 늦게 온다”고 잘못 말함). 우리가 warm_scale을 모른다는 사실 자체가 위험원이므로, **“우리의 무지에도 밴드가 버티는가”를 통과하기 전엔 “실물에서 된다”고 말할 자격이 없다.**

**판정: (B) — 팽창 밴드 E3x 채택.** (**E3x / 팽창** = *inflation = 밴드를 일정 배율로 넓혀 캘리브레이션 오차에도 버티게 만든 버전*.)

| | E3 (고정 편향항) | **E3x (팽창)** |
|---|---|---|
| 최악 ★위험측 | **100.0%** (S4 40% @30m, warm_scale×0.5) | **8.7%** |
| 커버리지 (도출조건 → 미스매치 평균) | 93.3% → 81.4% (−11.8%p) | 전 배율 **95~100%** |
| 100m 밴드 폭 | 63.4s | **90.9s (1.43배)** |

**E3 단독은 게이트 통과 실패** — warm_scale을 절반(×0.5)으로 주면 위험측이 **40~48%로 완전히 무너진다.** 팽창 밴드 E3x가 8.7%로 잡으므로 **“warm_scale ±50%까지 강건”** 주장이 가능하되, **범위(±50%)를 반드시 병기**해야 한다.

**★ 비대칭 보고 — 내 가설이 반증됐다.**

| | ★위험측 | 보수초과(헛걸음) |
|---|---|---|
| warm_scale 과소(0.5~0.8×) | **16.4%** | 0.5% |
| warm_scale 과대(1.2~1.5×) | 0.0% | 20.2% |

나는 “warm_scale이 크면 위험”이라 예측했는데 정반대였다(상세는 §5.6). 위험한 건 **warm_scale 과소**(*보정을 참값보다 너무 많이 해서 밴드가 늦게 놓임 → 시간 있는 줄 아는 함정*). 실물 이관 때 **warm_scale을 낮게 잡지 말고 실측**하는 게 중요하다는 뜻.

**2차 민감도.** 클럭 지터 0~300ms·온도 지터 0.5s에서는 커버리지 −1.5~−4.5%p, 위험측 ≤2.7% → warm_scale(−11.8%p, 최대 100%)보다 **한 자릿수 작다.** → **1차 위험은 warm_scale 하나, 노이즈 모델은 2차.** 실물 이관(#4)에서 **warm_scale 실측이 최우선.**

**보고서 서술 자격 (확정):**
- ✅ 허용: **“ETA 구간은 선언된 warm_scale ±50% 범위 안에서 유효하며, 그 대가로 구간이 1.43배 넓다.”** 단측 “불은 이 시각보다 일찍 오지 않는다” = E3x 기준 **≥91.3%.**
- ❌ 금지: E3(비팽창) 수치를 실물 대비 주장에 쓰기 / warm_scale 범위를 생략한 채 “실물 유효”라 쓰기.

기록: D-041, STRESS_REPORT §1g에 (5)게이트 절 신설·(6)발표 표기를 E3x로 교정, PROGRESS 최상단. 검증 pytest 10/10, estimator/engine/fire.py 불변, 산출물 `summary_2e3_F_{warmscale_gate,noise_sensitivity}.csv`.

### 5.6 메타 검토 — 왜 전략 담당(나)은 warm_scale 위험 방향을 틀렸고, Claude Code는 지시문을 받자마자 맞췄나

_사용자가 문서에 남기라고 명시한 항목. 이 협업 구조에서 반복될 수 있는 실패 유형이라 기록한다._

**무슨 일이었나.** 2.F 지시서에서 나는 “warm_scale이 실제로 더 크면 선행거리 d가 커져 E3가 **과소보정** → **위험측**”이라 못 박았다. Claude Code는 지시문을 받자마자, 착수 전에 “예측이 반대”라며 정정 예측을 코드 docstring(*코드 안에 적어두는 설명문*)에 적었고, 측정이 그걸 확정했다. 실제 위험한 쪽은 **warm_scale 과소**(위험측 16.4%)였다.

**세 걸음 중 두 걸음은 맞고 마지막 하나를 건너뛰었다.** (여기서 **보정** = *원래 추정이 틀린 만큼 되밀어 참값에 맞추는 것*; **과소보정** = 덜 밀어줌, **과대보정** = 너무 많이 밀어줌.)
1. `d = warm_scale·ln(...)` 이므로 warm_scale ↑ → 선행거리 d ↑. _(맞음)_
2. E3 보정은 W0(*시뮬의 warm_scale 기준값 6m*)에서 배웠으니, 실제 warm_scale이 더 크면 실제 d가 더 커서 E3가 **과소보정**한다. _(맞음)_
3. ❌ 여기서 “과소보정 → 위험”으로 **건너뛰었다.** 이게 오류.

**건너뛴 마지막 걸음 = 부호를 ‘안전축’까지 끝까지 미는 것.**
- 원래 사망시각 기반 추정은 불이 **실제보다 이르게** 도착하는 것처럼 본다(노드가 죽을 때 불은 아직 d 앞, 진짜 도착은 d/v만큼 뒤).
- **과소보정**(덜 밀었다) → 추정이 여전히 이른 쪽 → 밴드가 참값보다 이르다 → “불이 빨리 온다”고 말함 → **조기경보 = 안전**(헛걸음일 뿐).
- warm_scale이 **작으면** 실제 d가 작아 **과대보정**(너무 밀었다) → 밴드가 참값보다 **늦다** → “아직 시간 있다”고 안심 → **위험.**

즉 위험한 쪽은 **과대보정(=warm_scale 과소)**이지 내가 지목한 과소보정이 아니다.

**내 실수의 정체 = ‘부족’이라는 단어에 위험을 잘못 붙였다.** “과소보정 = 불충분 = 나쁨 = 위험”이라는 직관 지름길을 탔다. 하지만 이 시스템의 무보정 기본값은 애초에 안전한 쪽(이르게)이라, “덜 보정”은 “안전 마진이 줄 뿐 여전히 안전”이고, 선을 넘는 건 “참값을 지나쳐 너무 많이 보정한” 과대보정이다. **위험은 ‘보정이 모자라서’가 아니라 ‘보정이 참값을 넘어가서’ 생긴다.**

**왜 Claude Code는 맞췄나 — 정보가 아니라 고도(altitude).** 걔가 더 알아서가 아니라, 곧 **실제 측정 코드를 쓸 참**이라 `band_low = estimate − correction` 같은 걸 구체적 숫자로 계산할 수밖에 없었다 → 부호가 끝까지 따라온다. 나는 전략 고도에서 “어차피 측정될 테니” 부호 한 줄의 엄밀도를 낮게 잡고 직관 지름길을 허용했다(“측정으로 확인” 헤지는 달았지만 **틀린 방향으로 못 박은 문장**을 남겼다).

**일반화된 교훈(강령 반영).** **방향·부호를 담은 예측은 직관으로 내지 말고 끝까지 밀거나, 아니면 못 박지 말고 “두 방향 후보 + 측정으로 결정”으로 남긴다.** 특히 ‘부족·약함·작음’이 ‘그래서 나쁨/위험’으로 유혹할 때 경계 — 기본값이 이미 안전한 쪽이면 ‘부족’은 안전이고 위험은 ‘지나침’에서 온다. 안전 결론은 항상 **원인 → 잔차가 참값 기준 어디 놓이나 → 이르냐/늦냐 → 안전/위험**의 전 사슬을 통과시킨 뒤에만 쓴다.

## 6. 종합 결론 — 시뮬 아크의 완결 서사

> **방향은 자랑(2.1°). 속도 점 추정에는 원리적 한계가 있고, 그 정체를 물리(돌풍 나이퀴스트)·모델(바람 곡률)·구조(희소 자유도 0)로 분해했다. 그래서 거짓 점 숫자 대신 검증된 구간을 판다. 그 구간은 시뮬 캘리브레이션이라는 전제 위에 있었는데, 강건성 게이트로 시험하니 그냥은 통과 못 하고 1.43배 넓혀야(E3x) warm_scale ±50% 오차에도 버텼다. 정직한 대가를 치른 뒤의 실물 주장은 “불은 이 시각보다 일찍 오지 않는다(선언된 warm_scale ±50% 범위, 단측 ~91%)”이다.**

이 서사의 힘은 **성숙도**다. “속도를 완벽히 맞췄다”보다 “한계를 재고, 정직한 구간으로 바꾸고, 그 구간의 전제와 필요한 여유폭까지 밝혔다”가 심사에서 훨씬 방어하기 쉽고 정직성 정체성과 정확히 맞는다. 그리고 이 성숙도는 **협업 구조 자체**에서도 나왔다(§5.6) — 전략 담당이 부호를 직관으로 건너뛰어 틀렸을 때 실행자가 잡아냈고, **틀린 예측을 지우지 않고 기록하는 규율**이 결과의 신뢰성을 떠받친다.

**측정으로 확정된 것:** 오탐 Type A 0% · 방향 2.1°(12개+ 안정) · 비화재 누수 86.4%→0% · 속도/ETA를 warm_scale ±50%까지 강건한 커버리지 95~100% 밴드로 구간화 · 그리고 **가설이 여러 번 반증되고 그때마다 정정한 이력** 자체.

**아직 아닌 것:** 밴드의 실물 **수치** 확정(하드웨어 warm_scale 실측 후) · 속도 점 추정 정밀도(구간으로만) · 하드웨어 실측 지표 전반.

## 부록 A. 용어 사전 (용어 → 정의)

| 용어 | 정의 |
|---|---|
| 메시(mesh) | 노드들이 서로 무선으로 연결돼 정보를 릴레이하는 그물망 네트워크 |
| 자가치유 | 노드가 죽으면 남은 노드가 자동으로 통신 경로를 다시 잇는 것 |
| 화선(fire front) | 불이 번져나가는 최전선의 선 |
| 도착시각장 | 각 위치에 불이 몇 초에 도착했는지를 위치의 함수로 나타낸 지도 |
| 평면 최소제곱 적합 | 점들과의 수직거리 제곱합이 최소가 되는 평면 하나를 찾는 계산 |
| ∇T(그래디언트) | 그 평면이 어느 방향으로 얼마나 가파르게 기울었는지 나타내는 벡터 |
| 정규화 | 벡터를 자기 크기로 나눠 크기 1의 방향만 남기는 것 |
| 역수 | 어떤 수 x에 대해 1/x |
| Jensen 부등식 | 볼록함수에서 f(E[X]) ≤ E[f(X)]. 1/x가 볼록이라 노이즈가 평균0이어도 속도가 위로 쏠림 |
| warm_scale | 불의 열이 화선 앞으로 감쇠하며 미치는 거리 척도(온도 ∝ exp(−거리/warm_scale)). 클수록 멀리 미침 |
| floor | 아무리 좋은 방법을 써도 못 내려가는 오차의 바닥값 |
| F_metric | 채점 기준을 잘못 잡아 생긴 허수 오차(→제거) |
| F_spatial(곡률) | 휜 화선을 곧은 평면으로 근사해 생기는 모델형 오차(줄일 수 있음) |
| F_temporal | 시간에 변하는 속도를 하나로 요약해 생기는 오차(방법 B가 회수) |
| F_sampling | 나이퀴스트 한계로 원리상 못 보는 몫(★유일한 진짜 물리) |
| 나이퀴스트 한계 | 측정 간격의 2배보다 짧은 주기의 흔들림은 정보가 안 담겨 복원 불가 |
| 자유도(DOF) | 데이터 점 수 − 미지수 수. 남는 여분이 있어야 오차를 걸러냄. 0이면 노이즈가 그대로 통과 |
| 로버스트(회귀) | 이상치·튀는 값에 덜 휘둘리도록 설계된 성질(Theil–Sen/Huber 등) |
| per-node 중앙값 | 노드마다 값을 낸 뒤 그 중앙값(가운데 값)으로 대표. 평균보다 튀는 값에 강함 |
| 오라클 절단 | 시뮬 정답 정보를 하나씩 빼거나 넣어 각 노이즈원의 기여를 분리하는 실험 |
| 밴드 | 숫자 하나 대신 “정답이 이 범위 안” 구간 추정치 |
| 커버리지 | 선언한 구간 안에 참값이 실제로 들어온 비율(정직성 점수). 오차 감소 아님 |
| breach_early(위험측) | 참 도착이 밴드 이른끝보다 더 이름 = 불이 최조기 예측보다 먼저 옴 |
| 단측 신뢰도 | “이 시각보다 일찍 오지 않는다” 한쪽 주장이 지켜지는 비율 |
| 강건성 게이트 | 가정값(warm_scale)을 일부러 틀리게 줘도 밴드가 버티나 시험하는 관문 |
| E3x(팽창 밴드) | 캘리브레이션 오차에도 버티게 밴드를 배율로 넓힌 버전(1.43배) |
| tautology | 시뮬 온도식을 그대로 되돌려 추정 → 시뮬만 잘 맞고 실물서 무너지는 자기채점 함정 |
| measure-first | 테스트 점수 보기 전에 물리·기준선에서 파라미터 정하고 나쁜 결과도 기록 |
| rep_peak | 정답(god-view)이 아니라 메시가 실제 수신한 최고온도만 씀(치팅 방지) |
