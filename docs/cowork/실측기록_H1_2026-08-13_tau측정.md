## 핵심 발견

### ① τ는 온도가 아니라 유속의 함수 — 한 시행 안에서 직접 확인
```
제트 안 (풍량10, 3cm)   τ = 22.3 ~ 23.3 s
실내 (이탈 후)          τ = 92.4 ~ 96.1 s
                        ─────────────────
                        비율 4.1 배
```
같은 센서, 같은 순간, 같은 온도 범위. 바뀐 것은 공기 유속뿐.
→ **시뮬 시험 범위 {0~10s} 밖에 실제가 있었다**는 §4-④ 주장의 직접 근거.

### ② 조준 오차는 절편(T∞)으로 흡수되고 기울기(τ)는 살아남는다
r2→r3에서 조준을 개선하자 평탄값이 **+4.5℃** 올랐으나 τ는 **+0.95s (4.2%)**만 변동.
모델 무관 지표는 거의 불변: 50℃ 도달 17.6→17.5 s.

> **이론과의 대응:** ∇T = n̂/s 에서 균일 지연이 절편에만 흡수되고 기울기에 면역인 것과 구조적으로 동일. 측정 기법 자체가 같은 성질을 보였다.

**측정 기법의 바닥 오차 = 0.67 s (2.9%)** — 시뮬 가정 σ_τ=30%보다 한 자릿수 작다.

### ③ DS18B20은 순수 1차계가 아니다
1차 지수 적합의 잔차가 덩어리로 뭉침: `++-------------00++++++++++++++++++`
도달률별 τ가 흘러내림: 63%→21.6s, 86%→18.4s, 95%→15.0s.
원인 추정: 스테인리스 외피 + 충진재 + 다이의 복합 열구조.

> **보고서 처리:** τ를 물리 상수가 아닌 **운용 기술자(operational descriptor)**로 제시하고, 모델 무관 값(60℃ 도달 30초, 95% 도달 45초)을 병기. "모델 가정을 검증했다"가 오히려 점수.

### ④ 양자화가 평탄을 위장한다
r2에서 "5줄 연속 69.0"으로 판정해 이탈했으나, 실제로는 0.5℃ 눈금 아래로 계속 상승 중이었음 (적합 T∞=72.78 > 관측 69.0).
→ **판정 기준을 "투입 후 90초 고정"으로 변경.** 사람의 판단을 제거해 회차 조건을 균일화.


## 로거 펌웨어 결함 — 세션 중 발견·수정

### 증상
n01→n02 교체 후 **출력이 완전히 없음** (샘플 0개). −127도 아니고 무출력.

### 원인 (TauLog.ino)
```cpp
if (n == 0) { Serial.println("# ERROR..."); return; }   // ready = false
void loop() { if (!ready) { delay(1000); return; } }     // ← 영원히 침묵
```
부팅 시점에 센서를 못 찾으면 **에러 한 줄 뒤 영구 침묵.** 배선을 고쳐도 재부팅 전엔 피드백이 없어 원인 추적 불가.

**두 번째 함정:** `setup()`에서 1-Wire 주소를 캐시. 실행 중 교체하면 옛 주소로 읽어 −127.

### 수정
| 전 | 후 |
|---|---|
| 미검출 시 영구 침묵 | 1초마다 재탐색 + `# devices=N` 계속 출력 |
| 재부팅해야 재인식 | 발견 즉시 `beginSensor()` 자동 시작 |
| −127도 그대로 기록 | 경고 후 재탐색 모드 복귀 |

원본 `TauLog.ino.bak` 보존. 플래시 277,692 B (21%).
**결과: 측정 중 센서 교체 시 리셋 불필요.**

### ★ 보고서 활용 — §4-④ 파이프라인 공백과 같은 계열
> 우리 알고리즘의 설계 원칙은 **"모르면 모른다고 말한다"**(INSUFFICIENT 게이트)인데,
> 정작 우리 계측 도구는 **"모를 때 조용히 멈추는"** 반대 구조였다.
> 침묵은 정상과 구별되지 않는다 — 이것이 우리가 알고리즘에서 침묵 대신 등급 출력을 택한 이유와 정확히 같은 교훈이다.

이 삽화는 §4-③(「모르면 모른다고 말하는 시스템」)의 **실물 계측 버전**으로 한 줄 인용 가치가 있음.

### ⚠ 펌웨어 변경에 따른 비교가능성 검증 필요
n01_r2·r3는 **구 펌웨어**, n02 이후는 **신 펌웨어**로 측정됨.
1초 주기 상태 출력이 추가되었으므로 **샘플레이트·분해능이 유지되는지 반드시 확인**:
```
목표: 약 10.0 Hz, 0.5℃ 눈금(9비트)
```
n01_r4(신 펌웨어)를 r3(구 펌웨어)와 비교하면 **드리프트 검정 + 펌웨어 영향 검정**을 동시에 수행.

## 데모 설계에 미치는 결론 (τ=23.3s 기준, 시작 24℃)

| 공기 온도 | 60℃ 도달(사망) | 125℃ 도달(파손) | 안전 여유 |
|---|---|---|---|
| 73.5℃ (현재) | 30.3 s | 도달 불가 | ∞ |
| 100℃ | 15.0 s | 도달 불가 | ∞ |
| **150℃** | **7.8 s** | 37.7 s | **29.8 s** |
| **200℃** | **5.3 s** | 19.9 s | **14.6 s** |
| 250℃ | 4.0 s | 13.8 s | 9.8 s |
| 400℃ | 2.3 s | 7.3 s | 4.9 s |

**결론: 데모 공기 온도는 150~200℃ 구간.**
- 100℃로는 노드 하나 죽이는 데 15~30초 → 데모 성립 불가
- 250℃ 이상은 사망~파손 여유가 10초 아래 → 열풍기가 잠깐 머물면 센서 파손
- **τ는 온도 무관(유속의 함수)이므로 100℃에서 측정한 σ_τ는 150~200℃ 데모에 그대로 유효** → 오늘 데이터 전량 유효

## 열전대 모듈의 용도 (세션 중 확정)
DS18B20이 125℃에서 죽으므로 **데모 온도(150~200℃)의 공기 온도를 확인할 수단이 없다.** K형 열전대가 그 자리를 메운다.

1. **데모 온도에서 실제 공기 온도 측정** — 설정 100℃ → 3cm 실측 73.5℃였듯, 감쇠율을 알아야 위 표의 어느 행인지 확정
2. **계단 입력 검증** — τ<1초라 공기 온도 변화를 거의 그대로 관측. 현재는 "투입이 계단"이 가정 상태
3. **열풍기 드리프트 감시** — 제트에 상주시키면 위 미해결 항목이 직접 판별됨
4. **거리별 온도 지도** — "몇 cm 안이면 노드가 죽는가" = 데모에서 화재의 공간 범위

**확인 필요:** 노출 비드형(τ≈0, 기준기로 적합) vs 스테인리스 봉형(자체 τ 보정 필요)
