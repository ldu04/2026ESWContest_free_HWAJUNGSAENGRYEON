# 블록 1 — G0 + τ  (2시간)  ★ 오늘의 전부

**G0와 τ는 같은 시험이다.** 노드를 제트에 넣고 온도 곡선을 기록하면
곡선에서 τ가 나오고, 로그에서 사망 판정 여부가 나온다. 두 번 할 일이 아니다.

## 1-A. 안전 시험 — 설정 200에서 반복 (센서 안 죽는다)

4cm 거리에서 설정별 공기온도:

| 설정 | 공기온도 | 센서 |
|---|---|---|
| 100 | 64.1 ℃ | 생존 |
| 150 | 87.8 ℃ | 생존 |
| **200** | **110.2 ℃** | **생존 — 반복 시험용** |
| 250 | 131.5 ℃ | 파손 위험 |
| 400 | 190.3 ℃ | 파손 (데모 조건) |

**설정 200 · 4cm는 125℃에 절대 도달하지 않는다.** 여기서 마음껏 반복한다.
사망 임계 60℃는 넘으므로 G0 시험이 성립한다.

```
① 노드 1개에 DS18B20 연결, 시리얼 열기
② 설정 200 · 풍량 10 · 4cm · 3분 예열
③ 노드를 제트에 넣고 90초 기록
④ 확인:  온도가 오르다 60℃ 부근에서 사망 판정 로그가 찍히는가
```

**통과 기준: 사망 판정 로그 한 줄.** 온도가 오르는 것만으로는 통과가 아니다.

**막히면 의심 순서**
1. 임계값 설정이 60이 맞는가
2. **판정 함수가 실물 경로에서 호출되는가** — §4에서 이미 한 번 나온 결함이다.
   시뮬에서는 불리고 실물에서는 안 불렸다. 재발 여부를 먼저 본다
3. 1-Wire 읽기가 loop에서 도는가

> **G0가 막히면 오늘은 여기만 한다.** 나머지 블록을 다 버려도 된다.
> 사망 판정이 안 되면 메시도 집계도 대시보드도 볼 이유가 없다.

## 1-B. τ 추출 (1-A의 곡선에서 그냥 나온다)

90초 곡선을 `T(t) = T∞ - (T∞-T0)·exp(-t/τ)` 로 맞춘다.

**사전등록 예측**
```
설정 200 / 4cm 에서   τ = 20 ~ 25 초
```

## 1-C. 데모 조건 확인 1회 (설정 400)

```
설정 400 · 4cm · 제트에 넣고 15초 뒤 반드시 빼낸다
```

**15초는 협상 대상이 아니다.** τ가 20~25초라면 125℃ 도달이 18~23초다.
15초에서 센서는 약 85℃, 안전 여유 안이다.

**사전등록 예측**
```
τ = 20초  → 사망 4.6초
τ = 24초  → 사망 5.4초
τ = 25초  → 사망 5.7초
```

**사망 시각이 4.5 ~ 6.0초 안에 들어오면 통과.**
이 값이 곧 데모 체류 8초의 근거가 된다.

# 블록 4 — G2 시각 동기  (2시간)  ★ 조용히 틀리는 유일한 관문

```
① 게이트웨이에서 브로드캐스트 1회 발사
② 각 노드가 각인한 수신 시각을 모아 비교
```

**통과 기준: 노드 간 편차 < 0.5초**

**왜 0.5초인가** — 사망 시각 지터가 0.3초다.
시계 편차가 그보다 크면 지터가 아니라 시계가 결과를 지배한다.

막히면 의심: `millis()` 기반으로 되돌아갔는지. 초기 펌웨어의 원리적 파탄이 이것이었다.

> **이 관문을 건너뛰지 말 것.** 시계가 어긋나도 시스템은 아무 오류 없이
> 그럴듯한 방향을 출력한다. 촬영을 다 마친 뒤 발견하면 전부 다시 찍는다.
