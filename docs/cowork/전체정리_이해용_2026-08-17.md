# 불사(不死) — 지금까지의 전부를 한 번에 이해하기
### 2026-08-17. 실무 용어 + 풀어쓴 설명 병기. 이 문서 하나로 이틀간의 측정·결정·철회를 전부 복원할 수 있게 쓴다.

---

# 0. 이 프로젝트가 뭘 하는 물건인가 — 30초 버전

```
싼 센서 노드를 숲에 뿌린다 → 산불이 오면 노드가 타 죽는다
→ "언제, 어디의 노드가 죽었나"의 패턴에서
→ 불이 오는 방향·속도·도착예정시각을 역산한다
```

남들은 살아있는 노드가 온도를 스트리밍하게 한다. 우리는 **죽음 자체를 데이터로** 쓴다.
노드가 죽는 건 고장이 아니라 **가장 확실한 화재 신호**다. 이게 프로젝트 이름이 불사인 이유다 —
노드는 죽지만 정보는 죽지 않는다.

# 1. 용어 사전 — 이 문서에 나오는 말 전부

| 용어 | 실무 정의 | 풀어서 |
|---|---|---|
| **τ (타우, 열시상수)** | 센서가 주변 온도 변화의 63%를 따라잡는 데 걸리는 시간 | 센서를 뜨거운 데 넣어도 온도계 눈금은 바로 안 올라간다. 그 "굼뜬 정도"를 초로 나타낸 것. 우리 센서는 약 20초 |
| **t80** | 계단 입력 후 센서가 80℃를 넘기까지의 시간 | "불에 넣고 나서 몇 초 만에 사망 판정이 나나". **우리 설계의 유일한 앵커** |
| **계단 입력 (step input)** | 조건을 순간적으로 바꾸는 것 | 센서를 상온에서 뜨거운 바람 속으로 한 번에 옮기는 동작 |
| **점근값 (T∞, Tinf)** | 무한히 기다리면 도달할 최종 온도 | 곡선이 평평해지는 높이. 실제로는 2분쯤이면 거의 도달 |
| **평탄값 (plateau)** | 관측된 안정 구간의 온도 | 점근값의 관측 버전. 아직 오르는 중이면 점근값보다 낮게 읽힘 |
| **브래킷 (bracket)** | 기준 측정을 처음과 끝에 두 번 하는 설계 | 처음과 끝이 다르면 그 사이에 뭔가 흘렀다는 뜻. 드리프트 검출기 |
| **드리프트 (drift)** | 측정 중 조건이 천천히 흘러가는 것 | 방이 데워진다든지, 기계가 달궈진다든지 |
| **교란 (confounding)** | 두 변수가 같이 움직여서 뭐가 원인인지 구분 불가능한 상태 | 센서를 순서대로 갈아끼우면 "센서 차이"와 "순서 효과"가 분리 안 됨. σ_τ를 철회한 이유 |
| **분산 분해** | 관측된 흩어짐을 원인별 몫으로 쪼개는 것 | "총 오차 10℃ 중 조준이 몇, 기계가 몇, 센서가 몇" |
| **사전등록 (pre-registration)** | 측정 전에 예측과 합격 기준을 적어 봉인 | 데이터를 본 뒤 기준을 옮기는 자기기만을 원천 차단하는 규율 |
| **계단→사망 사슬** | 설정온도→출구→공기→센서→사망시각의 추정 사슬 | 고리마다 오차가 있어 다섯 번 흔들렸다. 지금은 폐기하고 끝값(t80)만 잰다 |
| **평면적합 (plane fit)** | 사망시각들을 (x,y) 위의 평면으로 맞추는 것 | 직선 화선이 일정 속도로 오면 사망시각은 정확히 평면이 된다. 평면의 기울기 = 방향·속도 |
| **잔차 (residual)** | 적합에서 남는 오차 | 잔차가 크면 "한 평면으로 설명 안 되는 무언가"가 있다는 신호 |
| **∇T (기울기, gradient)** | 사망시각의 공간 변화율 | 어느 방향으로 사망이 늦어지는가 = 불이 오는 방향의 반대 |
| **2단 집계** | ①노드별 국소 평면적합 ②신뢰도 가중 벡터합 | 전체를 한 평면으로 안 맞추고, 동네별로 맞춘 뒤 합친다. 곡선 화선에서도 작동하는 이유 |
| **w = \|∇T\|²** | 국소 기울기 크기의 제곱을 가중치로 | 기울기가 또렷한 동네의 의견을 더 세게 반영 |
| **n_eff** | 실효 표본 수 | "실질적으로 몇 개의 독립 의견이 모였나". 낮으면 소수 의견이 지배 중이라는 경고 |
| **INSUFFICIENT 게이트** | 근거 부족 시 답을 내지 않는 기능 | 틀린 답 대신 "모른다"를 출력. 이 프로젝트의 핵심 철학 |
| **임종신호 (Last-Gasp, LG)** | 노드가 죽기 직전 보내는 마지막 송신 | "나 여기서 죽는다. 시각은 이거다." 이 신호의 존재=화재 증거, 부재≠비화재 증거 |
| **메시 (mesh)** | 노드끼리 서로 중계해주는 무선망 | 중앙 안테나 없이 옆 노드를 거쳐거쳐 게이트웨이까지 전달. painlessMesh 라이브러리 사용 |
| **게이트웨이** | 임종신호를 모아 계산하는 수집기 | 노트북(개발) → 라즈베리파이(최종). 좌표 결합·집계·대시보드 담당 |
| **DS18B20** | 노드에 붙는 방수 온도센서 | 1개 1천원대. **125℃ 넘으면 죽는다**(부품 자체가). 사망 임계는 80℃ |
| **MAX6675 + K열전대** | 고온용 온도계 (0~1024℃) | DS18B20이 못 재는 뜨거운 공기를 재는 용도. **역할 완수, 예비로 빠짐** |
| **9비트/12비트 해상도** | DS18B20의 변환 정밀도 설정 | 9비트=0.5℃ 눈금·변환 94ms, 12비트=0.06℃·750ms. **속도가 중요해서 9비트 통일** |
| **충돌 제트 (impinging jet)** | 면에 수직으로 부딪히는 바람 | 비스듬히 스치는 것과 열전달이 다르다. 기하가 바뀌면 t80도 바뀌는 이유 |
| **쌍곡 감쇠** | 온도가 거리에 1/(x+c)로 떨어지는 형태 | 자유제트의 교과서 형태. 지수감쇠(e^-x/L)와 다르다 — 4점을 재고 나서야 구분됨 |

# 2. 이론의 심장 — 왜 이 방식이 성립하는가

## 2-1. 사망시각 평면

불이 직선 전선으로 일정 속도 s로 온다고 하자. 위치 (x,y)의 노드가 죽는 시각은

```
t(x,y) = (n̂·(x,y)) / s + 상수        n̂ = 전선의 진행 방향
```

**완전한 평면**이다. 평면의 기울기 벡터가 ∇T = n̂/s — 방향과 속도가 둘 다 여기서 나온다.

## 2-2. ★ 균일 지연 면역 — 이 프로젝트의 가장 강한 카드

노드가 실제로 기록하는 사망시각은 `t_j = a_j + d_j` (a=불 도달, d=센서 지연).

**모든 노드의 d가 같다면, d는 평면의 높이만 올릴 뿐 기울기를 못 건드린다.**
방향·속도는 기울기에서 나오므로 **센서가 굼떠도(τ가 커도) 답이 안 틀린다.**

이틀간의 계측에서 이 성질이 실물로 두 번 재현됐다:
- 조준을 개선하자 도달온도는 +4.5℃ 변했는데 τ는 4.2%만 변함
- 테이프가 떨어져 각도가 틀어진 사고에서 절편만 −16%, 기울기는 −1.6% (감쇠비 10:1)

## 2-3. 왜 2단인가

곡선 화선(예: 한 점에서 방사형으로 번짐)은 한 평면으로 설명이 안 된다 — 전역 적합 잔차가 51초씩 나온다.
그런데 **어느 노드의 동네(이웃 3~4개)만 보면 국소적으로는 거의 평면**이다.

```
1단   노드마다 자기 동네로 작은 평면을 맞춘다  → 국소 기울기 16개
2단   기울기들을 w=|∇T|² 가중으로 벡터합       → 전체 방향
      속도는 중앙값(robust median)             → 이상치에 강함
```

시뮬 재현: 전역 잔차 51.2초짜리 방사 패턴을 2단은 **0.28° 오차**로 복원.
(정직 주석: 이웃 수를 4→8로 바꾸면 0.28~1.28°로 흔들린다. 명세값 4를 쓰되 폭을 병기)

## 2-4. INSUFFICIENT — 모르면 모른다고 말한다

노드가 부족하거나(자유도<1) 잔차가 크면 시스템이 **답을 내지 않는다.**
자신 있게 틀리는 것(뱀형 경로에서 90.00° 출력)보다 침묵이 낫고, 침묵보다 "모른다" 선언이 낫다.
이 원칙은 §4 보고서에서 우리 자신에게도 적용됐다(σ_τ 자기 철회).

# 3. 계측 이틀 — 무엇을 재서 무엇을 알았나 (시간순)

## 3-1. 왜 재기 시작했나

시뮬레이터는 τ를 0~10초로 가정하고 검증했다. **실측하니 11~92초.** 검증한 범위 밖에 실제가 있었다.
그래서 데모 조건을 가정이 아니라 실측으로 정하기로 했다.

## 3-2. 발견 ① — τ는 온도가 아니라 유속의 함수

같은 센서, 같은 시행 안에서:

```
제트 안 (바람 있음)   τ ≈ 20~22 초
제트 밖 (정지 공기)   τ ≈ 92 초        → 4.1배
```

바뀐 건 공기가 움직이느냐뿐. 물리적으로 τ = mc/(hA)이고 h(열전달계수)가 풍속에 달렸기 때문.
**실용 결과: 회차 사이 센서 냉각은 부채질하면 5분 → 90초.**

## 3-3. 발견 ② — 거리별 온도는 지수가 아니라 쌍곡으로 떨어진다

설정 400에서 거리 8/5/3/2cm의 평탄값 132/165/224/251℃를 적합:

```
f(x) = 3.12/(x + 3.12)     R² = 0.9904
```

- 3점만 있을 때는 지수감쇠가 이겼는데 **4번째 점이 그 결론을 뒤집었다** (모델 선택은 점 개수에 취약)
- 이 곡선은 노즐(x=0)에서 설정온도가 그대로 나온다는 별도 실측과 자동으로 일치했다
- 교과서 상관식(Chen&Rodi)은 **형태는 맞혔지만 크기는 19% 틀렸다** — 노즐 지름 역산 8.9mm vs 실측 7.5mm. **기각으로 기록**

## 3-4. 발견 ③ — 분산이 평균보다 먼저 원인을 말한다

데모 조건(400·4cm)을 조준해 가는 과정:

| 회차 | 평균 | 흩어짐(SPREAD) | 실제 상태 |
|---|---|---|---|
| 1 | 71℃ | 14.0 | 축에서 1.06cm 벗어남 |
| 2 | 133℃ | 26.5 | 0.61cm 벗어남 |
| 3 | **190.5℃** | **2.0** | 명중 |

제트 중심은 온도 언덕의 **평평한 꼭대기**라 흔들려도 값이 안 변한다(기울기 −4℃/cm).
옆구리는 −149℃/cm라 1.8mm 떨림이 26℃ 출렁임으로 증폭된다.
**→ SPREAD가 크면 "옆구리에 서 있다"는 신호.** 평균만 봤으면 거리를 고치는 오진을 했을 것.
이건 우리 시스템의 n_eff·잔차 진단과 같은 논리라 §4의 좋은 소재.

## 3-5. 발견 ④ — 제트는 생각보다 넓다 (예측 기각)

r=1cm 옆에서 재니 예측 79℃ 대신 **124℃**. 반폭(절반 온도가 되는 반지름) 0.78 → **1.15cm (+48%)**.

- 살상 반경(공기 60℃ 이상) = 1.75cm → **격자 20cm 대비 5.7배 여유. 이웃 오폭 없음**
- 그러나 조준 허용오차 계산이 바뀌어 **체류 6초 대본이 무너짐** → 리허설 전에 잡았다

## 3-6. 철회 ① — σ_τ = 5.7%

"센서 개체차 5.7%"를 보고서·PPT에 실었다가 **우리 손으로 내렸다.**

- 센서를 한 개씩 **순서대로** 갈아끼움 → 센서 번호=측정 순서=조준 숙련도가 완전히 겹침 (τ와 순서의 상관 −0.903)
- 같은 센서를 3일 뒤 다시 재니 −26.3% — **보고한 개체차보다 재측정 차이가 6.5배 컸다**
- 손 고정 방식으로는 위치 산포(32%)가 τ 산포(36%)와 맞먹어 원리적으로 분리 불가
- **대체: 개체차 지표는 D1/D2 리허설의 평면적합 잔차로** (실운용 지터가 우리가 진짜 알아야 할 값)

## 3-7. 철회 ② — "센서가 공기보다 10% 낮게 읽는다"

R1(첫 τ 측정)의 평탄이 모델보다 8% 낮아서 "프로브 전도 손실"이라고 설명했는데,
조준을 제대로 잡은 R5에서 **비 0.990** — 센서는 공기를 거의 그대로 읽는다. **낮았던 건 조준이었다.**
그럴듯한 물리 설명을 확인 없이 붙였던 것. 기각으로 기록.

## 3-8. 임계는 60이 아니라 80℃였다

펌웨어를 열어보니 사망 임계 `TEMP_THRESHOLD_C = 80.0f`. 우리가 내내 쓰던 60℃는 교차검증용 참고값(WARN).
**데모가 편해진다는 이유로 임계를 60으로 낮추지 않았다** — 임계는 시스템이고, 체류시간은 무대장치다.
바꿔도 되는 건 무대장치뿐.

## 3-9. t80 실측 — 설계의 앵커

계단 입력 후 80℃ 통과까지:

```
프로브 단독 (좋은 조준)    10.31 / 11.25 / 10.35 초   중앙값 10.8
노드에 장착 (책 슬라이더)   16.5 / 14.4 초
```

노드 장착에서 느려진 건 높이·차폐가 바뀌었기 때문. **어차피 데모 기하(판+수직조사)가 또 다르므로
지금 절대값은 안 쫓는다.** 당일 교정이 그날 값을 정한다.

# 4. 설계 헌장 — 숫자가 그만 바뀌게 만든 구조

## 4-1. 왜 체류시간이 6→8→12→18→규칙으로 네 번 바뀌었나

각각 이유는 있었다(임계 발견, τ 실측, 제트폭 실측, 점근 실측). 근본 원인은:

```
설정온도 → 출구온도 → 공기온도 → 센서온도 → 사망시각
   (진위?)   (감쇠모델)  (조준·제트폭)   (τ)
```

**다섯 고리 사슬로 추정하고 있었다. 고리가 실측될 때마다 끝값이 흔들렸다.**
해결: 사슬을 버리고 **끝값(t80)을 직접 잰다.** "설정 400이 진짜 400이냐"는 이 구조에선
답할 필요가 없는 질문이 된다 — 라벨이 뭐든 재현만 되면 된다.

## 4-2. 네 칸 구조

```
동결(FROZEN)   임계 80℃ · 격자 20cm · 대본 구조 · 참값 각도 → 어떤 측정에도 불변
앵커(ANCHOR)   t80 하나. 실측만. τ·공기온도는 보고서 서술용
규칙(RULE)     체류 = round(1.7 × t80중앙값)
               상한 = min(22초, 점근값이 120℃에 닿는 시각) — 점근<120℃면 상한 없음
손잡이(KNOB)   거리 하나. 발동 조건도 하나(1.7×t80이 상한 초과일 때만)
```

계수 1.7의 근거: 관측 최악 조준(t80 12.3초)에도 1.46배 여유, 몬테카를로(조준산포 0.4cm)에서 노드 미사망 <2%.

## 4-3. 당일 교정 — 모델 대신 절차

촬영 직전 실제 노드 1개로 **3펄스**: 계단 입력 → DYING 로그의 t80 자동 출력 → 냉각 → 반복.
중앙값을 규칙에 넣으면 그날의 체류시간이 나온다. **방 온도·기계 상태·그날의 조준을
모델로 보정하지 않고 절차로 흡수한다.** 산포 3초 이상이면 고정 점검, 그래도 실패면 그날 안 찍는다.

## 4-4. 행동강령 (4+2계명)

```
① 시뮬레이터 동결 (estimator/engine/fire.py 수정 금지)
② 라벨 규약 유지 (tau_<유형>_d<거리>_T<온도>_s<풍량>_n<ID>_r<회차>)
③ 측정 프로토콜을 임의로 바꾸지 않는다
④ 측정 전에 정한 기준을 데이터를 본 뒤 옮기지 않는다
⑤ 판정 기준의 입력은 실측만 — 가정이 입력이면 그건 기준이 아니라 예측
```

# 5. 데모 설계 — 확정된 것

## 5-1. 열원과 대본

```
열원      설정 400 · 풍량 10 · 거리는 실물 기준(라벨 4cm) · 실내 촬영
체류      당일 교정으로 결정 (현 책 슬라이더 기준이면 25초, 판 기하에선 다시 잼)
격자      20cm · 4×4 · 원점 십자
```

**실내인 이유**: 우리 시스템이 아니라 **대역 열원**이 바람에 약해서다. 옆바람 2m/s면 7.5mm 제트가
1.14cm 밀려 조준 허용을 넘는다. 실제 화선(폭 수 m, 600~1000℃)에는 '겨냥' 개념 자체가 없다.
알고리즘은 균일 바람에 면역(§2-2), 돌풍은 집계가 흡수, 바람 시나리오는 시뮬 담당. §4-D(8)에 서술 완료.

## 5-2. 시나리오 3종

| | 실행 | 참값 | 증명하는 것 |
|---|---|---|---|
| **A 직선** | n01→n16 번호순, 균일 체류 | **75.96°** (=atan2(4,1), 체류와 무관) | 파이프라인 + 정확도 |
| **B 방사** | 점화점 (2,−11)에서 반경 순서 | **55.67°** | 전역 평면 잔차 37~51초 ↔ 2단은 복원. **2단 구조의 존재 이유** |
| **C 희소** | 한 행만 죽임 | — | INSUFFICIENT 자기차단 |
| D 뱀형(선택) | 지그재그 | (오답 90° 유도) | 잔차 진단이 잡아내는 모습 |

**뱀형을 실수로 쓰면 안 되는 이유**: 지그재그는 x성분이 상쇄돼 평면이 깨지는데도
추정기가 90.00°를 자신 있게 출력한다. 일부러 한 번 찍으면 이상탐지 시연 소재가 된다.

## 5-3. 조준 보조

조준 산포 실측 ≈ 0.4cm (두 독립 방법 일치: R2−R3 차이 환산 0.39, R1 이탈 역산 0.36).
몬테카를로: 산포 0.4→0.2cm로 줄이면 방향 오차 ±0.70°→±0.11°, 노드 미사망 1.8%→0%.
**대책은 평균이 아니라 산포를 겨냥**: 노드 자리 마킹 + 노즐 스탠드오프(다리) — 눈 겨냥을 "물건 놓기"로 대체.
