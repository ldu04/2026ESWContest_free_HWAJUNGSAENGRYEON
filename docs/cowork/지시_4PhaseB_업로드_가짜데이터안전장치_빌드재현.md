# 지시 — #4 Phase B 업로드 · 가짜데이터 안전장치 · 빌드 재현성
### 「불사」 · node.ino 컴파일 성공(D-025 해소) 이후 다음 수

> **판정:** A(FAKE_TEMP_RAMP=1) 유지로 업로드. **단, 세 가지 조건을 붙인다.** WS2812는 이번엔 건너뛴다(하드웨어 여건).
>
> **왜 조건이 필요한가:** FAKE_TEMP_RAMP는 **센서를 무시하고 펌웨어가 만든 가짜 온도를 펌웨어가 다시 읽는 구조**다. 이걸로 죽음이 찍혀도 그건 **상태기계(ALIVE→DYING→DEAD 전이)가 작동한다**는 증거일 뿐, **감지가 된다**는 증거가 아니다. 우리가 시뮬 단계에서 계속 경계해온 **동어반복(tautology, 자기가 만든 것을 자기가 맞히는 자기채점)의 하드웨어판**이다. 검증 범위를 명시하지 않으면 나중에 "노드 죽음 실증됨"으로 뭉뚱그려질 위험이 크다.

---

## 작업 1 — A로 업로드 (FAKE_TEMP_RAMP=1 유지)

그대로 업로드해서 아래를 확인한다:
- 부팅 → 하트비트 송신 시작
- ~4초 후 램프 시작 → ~7초에 80℃ 돌파
- **상태 전이 ALIVE → DYING → DEAD가 시리얼에 순서대로 찍히는가**
- **Last-Gasp(임종 신호)가 DEAD 직전에 실제로 나가는가**
- 이후 보고가 멈추는가(죽은 노드가 조용해지는가)
- 시리얼 CSV 포맷이 게이트웨이/estimator가 먹을 형태인가

**이 단계에서 검증되는 것 = 상태기계·Last-Gasp·시리얼 파이프라인. 검증되지 않는 것 = 센서→감지 경로, τ 상호작용.**

---

## 작업 2 — ★가짜 데이터 안전장치 (이게 이번 지시의 핵심)

**문제:** FAKE_TEMP_RAMP 플래그를 1로 둔 채 실제 시연 촬영을 하면, **가짜 데이터를 진짜 탐지처럼 보여주는 사고**가 된다. 플래그 하나 안 바꿔서 벌어지기 딱 좋은 실수이고, 우리 프로젝트가 절대 저지르면 안 되는 종류다. 사후에 원자료만 봐도 구분되도록 흔적을 남긴다.

**구현 요구:**

1. **부팅 배너** — `FAKE_TEMP_RAMP=1`일 때 시리얼에 눈에 띄게 경고 출력:
   ```
   ****************************************************
   *** WARNING: FAKE_TEMP_RAMP=1                    ***
   *** SYNTHETIC TEMPERATURE - NOT REAL SENSOR DATA ***
   ****************************************************
   ```
   (0일 때는 `[REAL SENSOR MODE] DS18B20 on GPIO4` 같은 정상 배너)

2. **로그 줄마다 플래그 컬럼** — CSV 각 줄에 `fake` 컬럼 추가(1/0). 예: `millis,temp_C,state,fake`.
   *이유: 나중에 CSV만 남아도 이게 실측인지 합성인지 영구히 구분된다. 배너는 로그 앞부분이 잘리면 사라지지만 컬럼은 모든 줄에 남는다.*

3. **(선택, 여유 있으면) LED 구분** — 나중에 WS2812를 달았을 때, fake 모드면 부팅 시 보라색 1회 깜빡 같은 식으로 육안 구분. 영상 촬영 중에도 눈으로 알 수 있게.

**주의:** 이 안전장치는 fake 모드를 불편하게 만들려는 게 아니라, **fake와 real이 절대 섞이지 않게** 하려는 것이다. fake 모드 자체는 개발 중 얼마든지 써도 된다.

## 작업 3 — 기록 (검증 범위 명시)

PROGRESS/DECISIONS에 남길 때 **범위를 반드시 한정**해서 적는다:

> **#4 Phase B (부분 완료):** node.ino 실보드 업로드·구동 확인. 검증 범위 = **상태 전이(ALIVE/DYING/DEAD)·Last-Gasp 송신·시리얼 CSV 파이프라인**. 온도원은 FAKE_TEMP_RAMP(합성 램프 12℃/s)이므로 **센서→감지 경로 및 τ 상호작용은 미검증**. 실센서 검증(FAKE_TEMP_RAMP=0 + 열원)은 별도 항목으로 남김.

**추가로 적어둘 것:** 합성 램프는 12℃/s로 ~7초에 임계를 넘는데, 이는 우리 시뮬 펄스(피크까지 수~수십 초)보다 훨씬 빨라 **τ가 개입할 여지가 없는 조건**이다. 즉 "이 조건에서 잘 됨"은 D-047의 τ 문제와 **무관**하다.

## 작업 4 — 빌드 재현성 파일 (환경 새로 잡으면 똑같이 재발할 함정들)

이번에 겪은 4가지는 **다른 PC에서 빌드하거나 라이브러리가 자동 갱신되면 그대로 재발**한다. 대회 제출 직전에 이걸 다시 겪으면 치명적이므로, 채팅 기록이 아니라 **저장소 안 파일**(예: `firmware/BUILD.md`)에 버전까지 못박아 남긴다.

| 함정 | 해결 | 비고 |
|---|---|---|
| painlessMesh 이름이 인덱스에 없음 | 실제 등록명 = **`Painless Mesh`**(공백 포함) | 이름 자체가 함정 |
| ArduinoJson 7.4.3 자동설치 → `StaticJsonDocument` 없음 | **6.21.5로 고정** | ★painlessMesh가 7로 되돌리므로 **재설치 후 다시 고정 필요** — 이 사실 자체를 적을 것 |
| `AsyncTCP.h` 없음 | **Async TCP 3.5.0** 별도 설치 | painlessMesh 의존성 목록 누락. 구 AsyncTCP 1.1.x는 **코어 3.x 비호환** |
| 한글 경로 툴체인 파손 | 스케치북을 `C:\Users\Public\esp32\sketchbook\`로 | 영문 경로 필수 |

**추가로 기록:** ESP32 코어 버전(3.3.11), 빌드 성공 시 플래시 978KB(74%)·RAM 48.8KB(14%) — 나중에 코드가 커졌을 때 여유 판단 기준이 된다.

**가능하면 재현 스크립트도** — `arduino-cli lib install "ArduinoJson@6.21.5"` 같은 명령 나열이면 충분. 사람이 순서대로 치기만 하면 되게.

## 작업 5 — WS2812는 이번엔 건너뜀

시리얼 로그로 상태 전이가 전부 보이므로 지금 단계에선 손해 없음. 나중에 배선할 때를 위한 메모만 남긴다:

- 배선: GND→GND / VCC→VIN(USB 5V) / DIN→GPIO5. **DIN/DOUT 방향 있음**(화살표가 시작되는 쪽이 DIN).
- **알아둘 것:** WS2812는 5V 로직 신호를 기대하는데 ESP32는 3.3V로 내보낸다. LED 1~2개는 대개 그냥 되지만, **여러 개 물렸을 때 색이 튀거나 안 켜지면 배선 실수가 아니라 이 전압 차 문제일 수 있다.** 그때는 데이터선 직렬저항(300~470Ω)이나 레벨시프터로 해결. 미리 대비할 필요는 없고, 증상이 나오면 이 원인부터 의심할 것.
