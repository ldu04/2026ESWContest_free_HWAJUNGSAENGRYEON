## 1. 게이트 — 기각. 그리고 왜 틀렸는지

### 1-1. 결정

**INSUFFICIENT 기반 앵커 게이트는 채택하지 않는다.** 선택효과를 제거한 쌍대 비교에서 head +30.52 s, flank +17.90/+24.03 s로 악화했고, 거리 정규화 후에도 head에서 지표가 2배 가까이 나빠졌다. **사전등록한 정지 조건이 발동했으므로 규칙대로 멈춘다.** 결과를 보고 규칙을 고치지 않는다.

`sim/eta_paths.py`의 게이트 경로는 **삭제하지 말고 비활성 상태로 보존**한다(재현·기록 목적). 기본값은 무게이트.

### 1-2. ★ 실패의 원인 — 다른 목적으로 만든 기준을 옮겨 쓴 것

`INSUFFICIENT`(DOF<1)는 원래 **방향 집계용 기준**이다. invvar 가중은 노드마다 `δφ̂`(자기 분산 추정)가 필요하고, 그걸 못 내는 노드는 가중 0이 된다.

**그런데 "자기 분산을 추정하지 못한다"와 "그 추정치가 나쁘다"는 다른 말이다.**

n_j = 3인 국소 적합은 세 점을 지나는 평면이 유일하게 결정되므로 **잔차가 0이고 분산 추정이 불가능**하다. 하지만 잡음이 작으면 그 평면의 기울기는 **충분히 좋을 수 있다.** 앵커 선택에 필요한 것은 분산 추정치가 아니라 **쓸 만한 기울기와 가까운 거리**인데, 우리는 분산 추정 가능 여부로 걸렀다. **기준을 잘못 옮겨 심었다.**

### 1-3. ★ 더 중요한 발견 — ETA는 사실상 기울기를 별로 안 쓴다

`corr(|ETA 오차|, 앵커거리) = 0.99 ~ 1.00`.

**ETA 오차가 앵커거리 하나로 거의 완전히 설명된다.** 식을 다시 보면 당연하다.

```
ETA(p) = t_{j*} + ∇T_{j*} · (p − pos_{j*})
                   └────────┬────────┘
              거리가 0이면 이 항도 0
```

- **앵커가 가까우면** ∇T가 엉터리여도 ETA ≈ t_{j\*} 로 정확하다
- **∇T의 품질이 드러나는 것은 앵커가 멀 때뿐인데**, 그 영역은 이미 국소 평면 가정(A1)이 깨진 영역이다

**→ 즉 ETA는 구조적으로 "최근접 사망 이벤트의 최근접이웃 조회 + 작은 선형 보정"이다.** 기울기 추정기의 성과라기보다 **관측 밀도의 함수**에 가깝다.

**이 사실이 게이트를 죽였다.** 퇴화 노드를 빼면 앵커가 멀어지고(flank +11.5 m), 거리는 오차를 거의 1:1로 키운다. **퇴화한 ∇T가 주는 해악보다 거리가 주는 해악이 크다.**

### 1-4. 요구 — 기록만, 새 설계는 하지 말 것

다음을 `DECISIONS`에 남긴다. **구현하지 않는다.**

```
D-0xx  ETA 앵커 게이트 기각
  - 쌍대 비교 악화: head +30.52 / flank +17.90·+24.03 / line −0.89~−2.63
  - 거리 정규화 후에도 head +0.16~+0.30 (거리로 설명되지 않는 악화)
  - 원인: DOF<1은 방향 집계용 기준이며 앵커 적격성 기준이 아니다
  - corr(|ETA오차|, 앵커거리) = 0.99~1.00
  - 향후 설계 방향(미구현): 앵커 적격성을
      (i) 함의 속도 s_j = 1/|∇T_j| 가 물리적 속도 밴드 안  AND
      (ii) 앵커거리 ≤ 상한
    으로 두는 것. DOF 기준이 아니라 물리 기준.
    ★이건 새 설계이므로 유도부터 다시 밟아야 하고, 마감 내 추진하지 않는다.
```

## 2. ★ 모순은 게이트 없이 라벨로 푼다 (즉시 구현)

게이트를 안 쓰면 원래 문제가 남는다 — **방향은 `None`인데 ETA는 숫자를 낸다.**

**해결: 막지 말고 표시한다.** §1-3에서 봤듯 그 ETA는 실제로 **가까운 앵커에서는 정확하다.** 막으면 정확한 값을 버리는 것이고, 안 막으면 사용자가 신뢰도를 모른다. **답은 값을 주되 신뢰도를 함께 주는 것이다.**

ETA 출력에 다음 필드를 붙인다.

| 필드 | 내용 | 근거 |
|---|---|---|
| `anchor_dist_m` | 앵커까지 거리 | **오차의 지배 변수(corr 0.99~1.00).** 이게 없으면 사용자는 오차 규모를 짐작할 수 없다 |
| `anchor_grade` | 앵커 노드의 등급 (OK / INSUFFICIENT) | 방향이 침묵하는 근거를 ETA 옆에 노출 |
| `dir_grade` | 그 구역 방향 추정의 등급 | **방향 None + ETA 숫자**라는 상태가 화면에 그대로 보이게 |

**대시보드 표기 규칙:** `anchor_grade = INSUFFICIENT`이거나 `dir_grade = INSUFFICIENT`면 ETA를 **경고 색으로** 표시하고 "방향 추정 불가 구역" 문구를 함께 낸다. **값은 지우지 않는다.**

> **이 설계가 게이트보다 나은 이유:** 게이트는 정확한 근거리 ETA까지 함께 버렸다(head에서 8,090건이 치환되며 MAE 21→52). 라벨은 아무것도 버리지 않고 판단 근거만 늘린다. **정보를 줄이는 방어보다 정보를 늘리는 방어가 낫다** — Last-Gasp를 양성 증거 축으로만 쓴 것과 같은 원리다.

## 3. 명세 정정 2건 — 즉시 반영

### 3-1. §3-2 ① 앵커 노드 자기 포함

```
현재 명세:  S_j = { i : i ∈ 무선이웃(j) ∧ |tᵢ − t_j| ≤ dt_window }
코드 실제:  S_j = {j} ∪ { i : i ∈ 이웃(j) ∧ |tᵢ − t_j| ≤ dt_window }
            → n_j = 1 + (적격 이웃 수)
```

명세를 코드에 맞춰 고친다. **DOF = n_j − 3 은 그대로지만 n_j의 셈이 1 다르다**는 점을 본문에 명시할 것(실측 n_j 평균 7.5 = 자기 1 + 이웃 6.5).

### 3-2. ★ §3-2 ② 통신 품질이 이웃 집합을 바꾸지 않는다 — 내 서술이 틀렸다

명세에 이렇게 썼다:

> "무선 이웃 — 메시에서 실제로 링크가 성립한 노드… 링크가 끊기면 A6이 조용히 깨진다… **통신 품질이 추정 정확도의 입력 변수다.**"

**코드는 그렇지 않다.** `_build_links()`는 `math.dist(a,b) ≤ radio_range_m`의 **정적 기하 원판 그래프**이고, `apply_dropouts`는 `self._active`만 건드리며 `self.neighbors`를 바꾸지 않는다.

**정정 후 서술:**

```
S_j 는 세 조건의 교집합이다.
  (i)   정적 기하 이웃  — dist ≤ radio_range_m. ★두절과 무관하게 불변
  (ii)  시간 창        — |tᵢ − t_j| ≤ dt_window
  (iii) 확정된 사망     — 침묵 감지·판별을 통과한 이벤트만 존재

통신 품질은 (iii)을 통해서만 표본에 들어온다. (i)은 바뀌지 않는다.
```

### 3-3. ★ 그리고 이건 명세 오류인 동시에 시뮬–실물 괴리다 (신설 절 요구)

내 서술은 **코드에 대해서는 틀렸지만 실물에 대해서는 맞다.** 실제 painlessMesh에서 링크는 뜨고 지고, 노드의 이웃 집합은 시시각각 변한다. **시뮬은 그걸 모델링하지 않는다.**

**→ 이건 낙관 방향의 괴리다.** 시뮬은 두절이 나도 모든 노드에게 항상 완전한 기하 이웃 집합을 준다. 실물에서는 그렇지 않으므로 **실물의 n_j는 시뮬보다 작을 수 있고, DOF·잔차검정·표본 굶주림이 전부 시뮬보다 나쁜 쪽으로 간다.**

명세 §10(알려진 한계)에 **10-8 신설**로 다음을 넣는다.

```
10-8. 이웃 집합의 정적 가정 (시뮬–실물 괴리, 낙관 방향)
  시뮬의 이웃 집합은 거리 기반 정적 그래프이며 링크 두절에 반응하지 않는다.
  실물 메시에서는 이웃 집합이 동적이므로, 실물의 n_j 는 시뮬보다 작아질 수 있다.
  영향: DOF 감소 → 잔차검정 무력화, A6(창 내 이웃 충분) 조기 위반.
  이 괴리는 P3(영구 두절 모델)이 미구현이라 정량화되지 않았다.
  ★실물 데모에서 노드별 실제 이웃 수를 로깅해 이 괴리의 크기를 측정할 것.
```

**★마지막 줄이 실행 항목이다:** 실물 펌웨어에서 **각 노드의 실시간 이웃 수를 주기적으로 로깅**하도록 추가할 것. 데모 때 이 값이 시뮬 가정(기하 이웃 수)과 얼마나 다른지가 곧 이 괴리의 실측치가 된다. 비용이 거의 없고, **하드웨어 괴리 분석의 정량 근거**가 된다.

### 3-4. §3-3 퇴화 배제 — 일치하나 단서 추가

`eps=1e-6`, 2단 배제 없음은 legacy 기준으로 일치한다. **기본값이 invvar가 된 뒤에는 DOF<1에 가중 0이 걸린다**는 단서를 명세에 추가할 것. 두 문장이 서로 다른 시점을 기술하고 있으므로 시점을 명시해야 한다.

## 4. 계속 진행할 것 — 2O §2 · §3

정지 지시는 게이트에 한정된다. 다음 둘은 그대로 진행한다.

**§2 — P1−P2 런타임 신뢰도 신호.** 2O §2 전문 그대로. `|P1−P2|` 출력 추가, 임계 30 s 3단 등급, **AGREE인데 MAE가 큰 칸이 있는지**의 교차표 검증이 핵심.

> **추가 요구:** §2의 교차표에 **앵커거리를 함께 넣을 것.** §1-3에서 ETA 오차가 앵커거리로 거의 설명된다는 게 밝혀졌으므로, `|P1−P2|`가 앵커거리와 **독립적인 정보를 주는지**가 이 신호의 값어치를 결정한다.
> - `|P1−P2|`가 앵커거리의 함수에 불과하면 → 새 정보 없음. 그냥 앵커거리를 쓰면 된다.
> - 앵커거리를 통제하고도 `|P1−P2|`가 오차를 설명하면 → **진짜 독립 신호.** 이 경우에만 가치가 있다.
>
> **부분상관 또는 앵커거리 구간별 층화**로 판정할 것.

**§3 — 예측 재정식화.** 2O §3-4 전문 그대로. `R = rms(ETA_지터 − ETA_균일) / std(dᵢ)`, 예측 R ≈ 1, 반증 R ≈ 1/√n_j. **n_j 실측 평균 7.5 → 반증선 0.365**를 쓸 것(13이 아니다).
