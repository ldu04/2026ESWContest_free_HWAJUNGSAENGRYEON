## 1. §2 — 신호 실격을 수용. 왜 구조적으로 실패했는지

### 1-1. 판정 수용

`AGREE` 9,843건이 MAE 1,714 s. **`|P1−P2|` 단독은 신뢰도 신호로 쓸 수 없다.** 기각한다.

**★이건 검증 기준이 제대로 작동한 사례다.** 2O §2-3-(3)에 "AGREE인데 MAE가 큰 칸이 있는지가 핵심 — 있으면 위험한 쪽으로 눈이 먼 것이므로 쓸 수 없다"고 미리 박아뒀고, 정확히 그 칸이 나와서 죽었다. **기준을 먼저 쓰고 나중에 적용하는 순서가 아이디어를 살려두지 않았다.**

### 1-2. ★ 구조적 원인 — 두 경로가 너무 많이 공유한다

| P1 | P2 | |
|---|---|---|
| 앵커 노드 j\* | **동일** | ← 공유 |
| 앵커 시각 t_{j\*} | **동일** | ← 공유 |
| 방향 (앵커 노드의) | **동일** | ← 공유 |
| 속도 크기 | 앵커의 \|∇T\| / per-node 중앙값 | ← **여기만 다름** |

**`|P1−P2|`는 속도 크기에 대한 불일치만 잰다.** 앵커가 틀렸거나 방향이 틀렸으면 **두 경로가 똑같이 틀리므로 차이는 0에 가깝다.** 지배적 오차 모드에 대해 구조적으로 눈이 멀어 있다.

> **★일반 원리로 기록할 것:**
> **불일치 신호는 두 추정기가 실제로 다른 성분에 대해서만 민감하다.** 입력 4개 중 3개를 공유하는 두 경로는 나머지 1개밖에 못 본다.
> **→ 런타임 신뢰도 신호를 설계할 때는 두 경로가 최대한 적게 공유하도록 만들어야 한다.** 편의상 이미 있는 두 경로를 가져다 쓰면(우리가 한 것) 대개 공유가 너무 많다.

## 2. ★ 잭나이프 신뢰도 — 공유를 끊은 재설계 (신규, 사전등록)

### 2-1. 착안

§1-2에서 나온 원리를 그대로 적용한다. **앵커를 공유하지 않는 두 추정치를 만든다.**

```
ETA_k(p) = t_{j_k} + ∇T_{j_k} · (p − pos_{j_k})     j_k = p에서 k번째 가까운 노드

jack_spread(p) = std( ETA_1, ETA_2, ETA_3 )     ← k=1,2,3
```

**세 추정치는 앵커도 시각도 기울기도 전부 다르다.** 공유하는 것은 원자료뿐이다. 통계학의 잭나이프(jackknife, 표본 하나씩 빼며 추정치의 흔들림을 보는 재표집 기법)와 같은 논리다.

### 2-2. 왜 이건 다를 수 있나 [식 유도]

**결합 진술 먼저(강령 §B-2).** §1의 `corr(|ETA오차|, 앵커거리) = 0.99~1.00`은 **오차가 거리에 비례한다**는 뜻이고, 비례상수는 국소 기울기 오차다. 잭나이프 산포는 **서로 다른 노드의 기울기가 얼마나 어긋나는지**를 재므로, **바로 그 비례상수를 추정한다.**

**→ 즉 `anchor_dist`가 오차의 "거리 성분"을 주고 `jack_spread`가 "기울기 품질 성분"을 준다. 둘은 곱해져서 오차가 된다.** 이론상 서로를 대체하지 않는다.

### 2-3. 사전등록 예측과 **기각 조건**

```
예측 P1: jack_spread 는 anchor_dist 를 통제한 뒤에도 |ETA오차|를 유의하게 설명한다
         (부분상관 |r_partial| ≥ 0.3)

예측 P2: anchor_dist × jack_spread 의 곱이 |ETA오차|와
         둘 중 어느 하나보다 높은 상관을 갖는다
```

**★기각 조건 (측정 전 고정, 결과 보고 바꾸지 않는다):**

```
부분상관 |r_partial| < 0.3          →  기각. anchor_dist 로 충분하다는 뜻.
"낮은 jack_spread인데 큰 오차" 구간이 존재  →  즉시 기각 (§1-1과 같은 이유)
```

**기각되면 `jack_spread`를 넣지 않고 `anchor_dist` 하나로 간다.** 그것도 충분히 좋은 결과다 — 이미 corr 0.99인 지표가 있다는 뜻이므로.

### 2-4. 구현 제약

`sim/eta_paths.py`에 함수 하나 추가. `estimator.py` 불변. **30줄 넘어가면 멈추고 보고할 것.**

## 3. ★ 게이트를 "표시 장치"로 쓰는 건 — 먼저 독립성부터 검정

### 3-1. 관찰의 값어치는 인정

- BROKEN의 **98.7 %**가 게이트 삭제 대상
- 삭제 집합 MAE **1,714~3,358 s** vs 유지 집합 **~28 s** — **60배 이상 분리**
- **치환(substitution)과 표시(labeling)는 다른 조치**이고 정지 조건은 치환에만 걸린다 — 이 구분은 정확하다

### 3-2. ★ 그러나 §2를 죽인 것과 같은 함정을 확인해야 한다

`|P1−P2|`는 **이미 아는 변수의 대리(proxy)**여서 죽었다. 게이트 라벨도 같은 의심을 받아야 한다.

**의심:** 게이트 삭제 대상 = 유효 앵커가 없는 구역 = 표본이 희소한 구역 = **앵커가 먼 구역**. 그런데 §1에서 `corr(|ETA오차|, 앵커거리) = 0.99~1.00`이다. **그렇다면 게이트 라벨의 예측력이 전부 앵커거리로 설명될 수 있다.**

그 경우 라벨은 새 정보가 아니라 **거리의 이산화(discretization)**일 뿐이고, 이미 2P §2에서 넣기로 한 `anchor_dist_m` 하나로 같은 일을 **연속 척도로 더 잘** 할 수 있다.

### 3-3. 요구 검정

```
① 앵커거리 구간별 층화(stratify)  — 예: 0-50 / 50-100 / 100-150 / 150-200 / 200+ m
   각 구간 안에서 "게이트 삭제 대상 여부"별 MAE를 비교한다.

   같은 거리 구간 안에서도 삭제 대상이 더 나쁘다  →  라벨은 독립 정보. 채택.
   같은 거리 구간 안에서 차이가 사라진다          →  거리의 대리. 기각, anchor_dist만 쓴다.

② 부분상관: corr(게이트라벨, |ETA오차| | anchor_dist)
```

**★이 검정을 통과하기 전에는 라벨을 채택하지 않는다.** 사후에 드러난 관찰이므로 사전등록이 필요하다는 지적은 정확했고, 위 ①②가 그 사전등록이다.

## 4. ★ §3 재정식화도 반증 — 그런데 더 나은 법칙이 보인다

### 4-1. 반증 수용

`R = 13.06`. 예측(≈1) 0/9, 반증선(≈0.277) 0/9. **양쪽 다 틀렸다.** 앵커 항이 지배할 것이라는 내 가설은 죽었다.

### 4-2. ★ 남은 것 — R이 **왜 그렇게 안정적인가**가 진짜 단서

τ가 11 → 78.5로 **7배** 변하고 화선 모양도 바뀌는데 R은 **11.1 ~ 14.4**에 머문다. 이건 우연이 아니라 **R에서 무언가가 소거되고 있다**는 신호다.

**유도 (결합 진술 먼저 — 강령 §B-2):**

지터가 각 사망시각에 σ_d의 산포를 준다. 이때

```
① 앵커 항        :  Δd_{j*}           ~  σ_d              (계수 1)
② 기울기 항      :  Δ∇T_{j*}·(p−pos)  ~  (σ_d / (h·√n_j)) · L
                       └───┬───┘
              간격 h 위에서 n_j 점으로 적합한 기울기의 오차
```

②에서 **σ_d가 분자에 그대로 있다.** 따라서

```
R  =  rms(ΔETA) / σ_d  ≈  L / ( h · √n_j )        (② 지배 시)
```

**★σ_d가 소거된다.** 그래서 τ가 7배 변해도 R이 안 변한다 — **관측된 안정성이 이 식에서 직접 나온다.**

### 4-3. 사전등록 예측 [식 유도] — R은 기하량이지 시간량이 아니다

```
예측 R1 (★핵심):  R 은 앵커거리 L 에 비례한다.
    → 앵커거리 구간별로 층화해 R을 계산하면 R이 L에 선형으로 증가해야 한다.
    → 이건 아직 관측되지 않았다. 새 예측이다.

예측 R2:  R ≈ L̄ / (h·√n_j) 가 자릿수 수준에서 맞는다.
    → h(노드 간격), n_j(실측 평균 7.5), L̄(조건별 평균 앵커거리)를 넣어 계산값과 실측 R을 비교.
    → ★계수가 2~3배 어긋나도 기각하지 않는다. 국소 적합의 실제 공간 span이 h와
      정확히 같지 않기 때문이다. 판정은 자릿수와 R1의 선형성으로 한다.

예측 R3:  R 은 τ 에 무관하다.
    → ★이건 이미 관측된 것이므로 검정이 아니라 정합성 확인일 뿐이다.
      새 증거로 세지 않는다. (사후 적합 금지)
```

**기각 조건:** R1에서 R이 L에 대해 **평평하거나 감소**하면 이 유도는 틀린 것이다. 그대로 기록한다.

### 4-4. 이게 맞으면 무슨 뜻인가 (미리 적어둔다)

**ETA 오차는 시간 오차가 아니라 기하 오차다.** 센서 지연이 얼마든, ETA 성능을 결정하는 것은 **앵커거리 / 노드간격**이라는 무차원 비다. 그렇다면 **ETA를 개선하는 유일한 지렛대는 노드를 촘촘히 배치하는 것**이고, τ 개선이나 추정기 개선은 ETA에 거의 효과가 없다.

> **★이건 배치 설계 지침으로 직결되고, 보고서 §6(활용성)에서 "얼마나 촘촘히 깔아야 하는가"에 정량적 답을 준다.** 반증되면 이 문단은 통째로 버린다.

## 5. 명세 §11 — 오류 유형 ③ 추가 (지적 수용)

**③ 명세가 "코드가 하지 않는 일"을 한다고 주장하는 것** — 유형 추가에 동의한다. ②(죽은 필드)보다 위험하다는 논거도 맞다.

**한 겹 더 붙일 것:**

| 유형 | 성질 | 탐지 방법 |
|---|---|---|
| ① 코드에 있는데 명세에 없음 | 누락 | 코드→명세 심볼 대조 |
| ② 명세에 있는데 코드가 안 씀 | 사문화 | **명세의 각 심볼을 읽는 코드 지점이 존재하는가** |
| **③ 없는 인과를 있다고 주장** | **날조** | **심볼 대조로는 못 잡는다** — 심볼은 양쪽에 다 있고 **관계**가 거짓이기 때문 |

**→ ③은 별도의 검사가 필요하다. 강령 §A-9로 신설 제안:**

```
A-9. 명세에 "A가 바뀌면 B가 바뀐다" 형태의 인과 문장을 쓸 때는,
     코드에서 A를 수정하는 지점부터 B에 도달하는 경로를 실제로 따라간 뒤에 쓴다.
     경로를 따라가지 않았으면 그 문장을 쓰지 않는다.
     (심볼이 양쪽에 존재한다는 것은 인과 경로의 존재를 뜻하지 않는다.)
```

이번 건(`apply_dropouts` → `neighbors`)이 정확히 이 검사로 잡혔을 사안이다. `_active`와 `neighbors`는 둘 다 존재하지만 **둘을 잇는 경로가 없었다.**
