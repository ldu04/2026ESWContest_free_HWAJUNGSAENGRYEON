## ★ 정정 2 — **가열 τ와 냉각 τ는 같은 양이 아니다** (v1 §3의 물리 오류)

v1 §3에 이렇게 썼다:

> "한 번의 시행에서 가열 곡선과 냉각 곡선이 둘 다 나온다. **둘 다 τ 산출에 쓸 수 있다.**"

**이 문장은 틀렸다.** 1차 지연의 시상수는

```
τ = m·c / (h·A)
```

이고 **h(열전달계수)는 센서 주변 유속에 의존한다.** 그런데 v1 절차에서

- **가열** = 센서를 **제트 안에** 넣음 → 유속 u = 제트 속도 → h 큼 → **τ 작음**
- **냉각** = 센서를 **제트 밖으로** 뺌 → 유속 ≈ 실내 → h 작음 → **τ 큼**

**서로 다른 조건의 서로 다른 τ다.** 이 둘을 "같은 설정의 반복 측정"으로 묶으면 τ(u) 곡선이 통째로 오염된다. 그리고 τ(u) 곡선은 지금 **폐기된 자유도-0 추정치를 대체할 유일한 근거**다 — 여기가 오염되면 H1 세션의 목적 자체가 사라진다.

### 대신 이렇게 한다

| 곡선 | 무엇을 재는가 | 신뢰도 | 용도 |
|---|---|---|---|
| **① 제트 진입(가열)** | 그 유속에서의 τ | **높음 — 깨끗한 계단 입력** | **주 측정.** τ(u) 곡선은 이것으로만 만든다 |
| **② 제트 이탈(냉각)** | **실내 공기의 τ** | 중간 | 측정 C(무풍 τ)의 **공짜 반복측정**으로 재활용 |
| **③ 제자리에서 히터만 OFF** | 오염됨 — 쓰지 말 것 | 낮음 | 아래 참조 |

**③을 쓰지 않는 이유:** 히터를 꺼도 노즐의 금속 열덩어리가 계속 열을 뱉으므로 **공기 온도가 계단이 아니라 자기 시상수로 서서히 내려간다.** 그러면 측정되는 건 "노즐 냉각 + 센서 지연"의 **직렬 연결**이고, 직렬 지연은 **겉보기 63.2% 시간을 항상 늘린다.** 즉 ③은 **τ를 과대평가하는 방향으로 치우친다** — 그리고 τ 과대평가는 우리 프로젝트에서 **위험 쪽으로 틀리는 방향**이 아니라 안전 쪽으로 틀리는 방향이라 눈치채기 어렵다. 그래서 더 위험하다.

> **②의 단서:** 열풍기가 돌아가는 방 안은 주변 공기가 끌려들어가(entrainment) 완전한 무풍이 아니다. ②로 얻은 값은 "무풍의 상한"이 아니라 **"약한 실내 기류에서의 τ"**로 라벨링할 것. 진짜 무풍은 v1 §4(측정 C, 열풍기 끄고 문 닫고)로만 얻는다.

**→ 결론: 각 풍량 설정에서 필요한 반복은 "진입 3회"다.** 이탈 곡선은 버리지 말고 따로 모아 두되 **다른 상자에 담는다.**

## ★ 정정 3 — 상온을 손으로 적지 말 것

v1 §3은 매 시행마다 상온을 수기로 기록하라고 했다. 그건 빠뜨리기 쉽고, 빠뜨리면 그 파일은 못 쓴다.

**대신: 센서를 넣기 전에 로깅을 먼저 시작한다.**

```
로깅 시작  →  10~15초 그냥 둠(상온 기록됨)  →  제트 진입  →  평평해질 때까지
→  이탈  →  10초 더  →  로깅 정지
```

이러면 **모든 파일이 자기 상온을 안에 갖고 있다.** 메타 항목이 하나 줄고, 게다가 그 10초는 **센서 노이즈 수준(σ)도 같이 재준다** — τ 적합의 R² 해석에 필요한 값이다. 공짜로 얻는다.

## 배너 검증 — 열풍기 켜기 전 마지막 관문

```
# === DS18B20 TAU LOGGER ===
# devices=1              ← 0이면 즉시 중단 (배선: DAT→GPIO4 / VCC→3V3 / GND)
# resolution_bits=9      ← 12면 즉시 중단 (τ 곡선 못 씀)
# period_ms=100
millis,temp_C
```

`resolution_bits`는 스케치가 센서에서 **되읽어** 출력하므로 자기검증이 된다. 좋은 설계다.

### ★ 추가로 봐야 하는 것 — 배너만으로는 안 잡히는 두 가지

DS18B20은 배선이 나빠도 **그럴듯한 숫자를 뱉는다.** 다음 두 값이 나오면 배너가 정상이어도 중단한다.

| 읽힌 값 | 의미 | 조치 |
|---|---|---|
| **85.0 ℃가 계속** | DS18B20의 **전원투입 기본값**. 변환이 한 번도 완료되지 않았다는 뜻 (전원 부족 / 기생전원 오배선) | VCC를 3V3에 직결, 4.7kΩ 풀업 확인 |
| **−127.0 ℃** | 라이브러리의 `DEVICE_DISCONNECTED_C`. 버스에서 응답 없음 | 배선·납땜 확인 |

**손으로 센서를 쥐어 값이 오르는지**까지 확인해야 "살아있다"가 확정된다. 배너 `devices=1`은 **버스에 뭔가 있다**까지만 말해준다.

## USB가 안 잡힐 때 — 세션을 놀리지 않는 방법

**★측정 A(풍속 표)는 보드가 전혀 필요 없다.** 히터 끄고 팬만 돌리며 풍속계로 읽는 작업이라 ESP32와 무관하다.

> **→ USB 문제를 푸는 동안 측정 A를 먼저 끝낸다.** 이러면 보드가 늦게 잡혀도 세션의 1/3은 이미 확보된다. v1의 A→B→C→D 순서는 어차피 A가 먼저였으니 순서를 바꾸는 것도 아니다.

**USB 점검 순서 (효과 큰 것부터):**

1. **케이블 교체** — ESP32 개발보드 사고의 최다 원인이 **충전 전용 케이블**이다. 데이터선이 없는 케이블은 전원 LED는 켜지지만 열거가 안 된다. 폰 데이터 전송에 써본 적 있는 케이블로 바꿔볼 것.
2. **허브 거치지 말고 PC 본체 포트에 직결**
3. **장치 관리자** — "포트(COM & LPT)"에 노란 느낌표가 있는지. 있으면 드라이버 문제.
4. **CP210x VCP 드라이버** 재설치 (Silicon Labs). 레지스트리에 COM3 이름만 남고 열거가 안 되는 건 드라이버가 반쯤 등록된 전형적 증상이기도 하다.
5. 그래도 안 되면 **다른 PC나 다른 ESP32 보드**로 케이블/보드/PC 중 어느 쪽인지 가른다.

## 라벨 규약 — `-Label`에 조건을 다 박는다

`log_tau.ps1 -Label`이 파일명이 되므로, **여기에 안 적은 조건은 영원히 복원되지 않는다.**

```
tau_<유형>_<노즐>_<풍량설정>_<거리cm>_<온도설정>_<센서ID>_<회차>

예)
tau_jet_nzA_s3_d05_T150_n01_r1      제트 진입, 노즐A, 풍량3, 5cm, 150℃, 센서01, 1회차
tau_room_nzA_s3_d05_T150_n01_r1     같은 시행의 이탈(=실내) 곡선
tau_calm_______n01_r1               측정C, 진짜 무풍
```

**한글·공백을 라벨에 넣지 말 것.** 콘솔 코드페이지가 지금은 65001이라 괜찮지만, 파일명 인코딩 사고는 데이터를 통째로 날리는 유형이고 예방 비용이 0이다.

## 세션 후 Claude Code에게 넘길 분석 요청 (v1 §8 대체)

```
H1 τ 실측 원자료 분석.

★대전제: 파일명 접두사로 곡선 종류를 구분할 것.
  tau_jet_*  = 제트 진입(가열). 이것만으로 τ(u) 곡선을 만든다.
  tau_room_* = 제트 이탈(실내 냉각). 별도 집계. τ(u)에 섞지 말 것.
  tau_calm_* = 진짜 무풍.
  세 종류를 한 표에 섞으면 분석 전체가 무효다.

1) 각 파일에서 앞 10~15초 구간을 상온 및 센서 노이즈 σ로 산출.
   (수기 상온값은 쓰지 않는다 — 파일 내부 값이 원본이다)
2) τ를 두 방법으로 산출하고 둘 다 보고:
   (a) (초기→최종)의 63.2% 도달시간
   (b) 1차 지연 exp fit의 시상수 + R²
   두 값이 크게 어긋나면 1차 모델이 안 맞는다는 신호이므로 플래그.
3) tau_jet_* 만으로 풍량설정별 τ 표 → 측정A의 풍속 표를 붙여 τ vs u.
   ★풍속은 상온 측정값이며 고온 운전 시 절대온도비 보정이 필요함을 명시.
   ★기존 τ(u)=24.6·u^-0.5는 자유도 0의 미검증 곡선이므로
     "비교 대상"으로만 쓰고 근거로 인용하지 말 것.
   자유도가 확보되는지(설정 수 ≥ 3) 먼저 보고할 것.
4) 측정D 센서별 τ의 평균·표준편차 → σ_τ 실측치.
   시뮬 가정 σ=30%와 비교. 실측이 작으면 2.J-A 지터 결과가 완화됨.
5) tau_calm_* 과 기존 78.48s(에어컨 ON)를 비교 — 진짜 하한 확정.
6) 시뮬이 시험한 τ 범위 {0,2,5,10}s 대비 실측 범위를 표로.

결론 문장은 쓰지 말고 원자료·표·플래그만. 해석은 Cowork.
```
