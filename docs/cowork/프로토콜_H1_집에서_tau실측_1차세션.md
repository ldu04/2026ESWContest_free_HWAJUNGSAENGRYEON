# H1 프로토콜 — 집에서 하는 τ 실측 1차 세션
### 「불사」· 열풍기·변압기·풍속계 확보 후 첫 실물 측정

> **이 세션의 목표:** τ(센서 열시상수)를 **풍속별·무풍·노드별**로 재서, 지금 프로젝트 최대 미지수를 측정치로 바꾼다. **16노드 배열이나 데모는 이번에 하지 않는다** — 노드 하나면 된다.
>
> **필요한 것:** 변압기, 8858 IV, 풍속계, ESP32 1개 + DS18B20(9비트 고속 모드 펌웨어), 노트북(시리얼 로깅), 상자나 책(열풍기 받침), 알루미늄 포일, 자, 장갑, 나무젓가락 1개, 여분 센서 5개 이상.
>
> **소요:** 대략 1.5~2시간. 서두르지 말 것 — 안정화 대기가 측정 품질을 좌우한다.

---

## 0. 안전 — 순서를 지킬 것

1. **변압기 명판 재확인** — `입력 220V / 출력 110V / 2KVA`. 강압 방향 맞는지 눈으로.
2. **변압기만 콘센트에 꽂고 아무것도 연결하지 않은 채 1~2분** — 탄내·과열·심한 진동 없는지. 약한 웅웅거림은 정상.
3. 이상 없으면 **열풍기를 변압기의 110V 출구에** 연결.
4. **최저 온도·최저 풍량**으로 먼저 켜본다.
5. **창문 열기.** 반경 50cm 안 종이·비닐·커튼 제거. 노즐이 향하는 방향에 아무것도 없게.
6. **열풍기는 상자/책 위에 플라스틱 몸통만 얹고 금속 노즐은 모서리 밖으로 돌출.** 접촉면에 포일.
7. **켜놓고 자리 비우지 말 것.** 끈 뒤에도 노즐은 몇 분간 뜨겁다.

---

## 1. 세팅 고정 — 이게 제일 중요하다

**측정 결과가 의미를 가지려면 "같은 조건"을 재현할 수 있어야 한다.** 아래 넷을 정하고 **테이프로 위치를 표시**한 뒤 세션 내내 바꾸지 말 것.

| 항목 | 정하고 기록 |
|---|---|
| 노즐 | 어느 노즐을 끼웠는지 (2개 중) |
| 거리 | 노즐 끝 ~ 센서까지 몇 cm |
| 정렬 | 제트 중심축에 센서를 맞췄는지 |
| 센서 높이 | 받침 기준 몇 cm |

**센서는 나무젓가락 끝에 캡톤테이프로 고정**해서 쓴다 — 손을 열풍에 넣지 않고 넣었다 뺄 수 있다. (이게 계단 입력을 만드는 방법이다.)

**펌웨어는 9비트 고속 모드(~10Hz)로.** 12비트(750ms)면 τ 곡선이 너무 성겨서 못 쓴다. 시리얼이 `millis, temp_C` CSV로 쏟아지는지 먼저 확인.

---

## 2. 측정 A — 풍속 표 (히터 OFF, 팬만)

**τ 측정과 완전히 분리해서 먼저 끝낸다.** 팬 설정별 유속은 기계의 고정 성질이라 나중에 붙여 쓰면 된다.

1. **히터를 끄고 팬만 도는 상태**로 만든다(전원 끈 뒤 냉각 모드 활용, 또는 온도 최저·팬만 도는 설정).
2. **센서가 놓일 바로 그 자리**에 풍속계를 넣는다.
3. **풍량 설정을 하나씩 바꿔가며 MAX 값을 읽는다.**
4. **★풍속계 온도 표시가 40℃ 근처로 오르면 즉시 뺀다** (기기 정격 45℃).

**기록 예:**
```
노즐A / 거리 5cm / 축정렬
설정1 → 0.8 m/s
설정2 → 1.6 m/s
설정3 → 2.4 m/s
...
(상온 측정값. 고온 운전 시엔 절대온도비만큼 커짐 — 보정은 나중에)
```

---

## 3. 측정 B — τ (풍량별) ★이번 세션의 핵심

**각 풍량 설정마다 아래를 반복한다. 최소 3회씩** (재현성 확인용).

1. 히터 ON, **온도 설정을 하나로 고정**(예: 150℃). **팬과 히터가 안정될 때까지 1~2분 대기** — 예열 중엔 출력이 변한다.
2. 시리얼 로깅 시작.
3. **센서(젓가락에 고정)를 열풍 안으로 빠르게 진입** → 그 자리에 고정 → 온도가 평평해질 때까지 대기 → **빠르게 이탈**.
4. 로깅 정지, 파일 저장.
5. **센서가 상온으로 돌아올 때까지 대기.** (선풍기 있으면 쓰면 훨씬 빠름.)
6. 다음 풍량 설정으로.

**한 번의 시행에서 가열 곡선과 냉각 곡선이 둘 다 나온다.** 둘 다 τ 산출에 쓸 수 있다.

**매 시행마다 함께 기록:** 풍량 설정 / 온도 설정 / 거리 / 센서 ID / **그때의 상온** / 파일명.

> **상온을 매번 적는 이유:** 세션이 길어지면 방 온도가 올라가고, 그러면 (초기→최종)의 기준이 달라져 τ 계산이 흔들린다. 창문 열고 진행하되 값은 기록해둘 것.

---

## 4. 측정 C — 무풍 τ (느린 쪽 끝 확정)

**기존 78.48초는 에어컨 켠 상태에서 나온 값이라 진짜 무풍이 아니다.** 이번에 하한을 확정한다.

1. **에어컨·선풍기·환기 전부 정지.** 문 닫고 **몇 분간 공기가 가라앉기를 기다린다.**
2. 센서를 열풍기로 데운 뒤 **열원을 완전히 치우고 자연 냉각 곡선만 기록.**
3. **오래 걸린다**(τ가 80초 이상이면 완전히 식는 데 7분+). 끊지 말고 끝까지 받을 것.
4. 최소 2회 반복.

**주의:** 이때 창문을 닫으므로 **열풍기는 미리 끄고 충분히 식힌 뒤**에 진행한다.

---

## 5. 측정 D — 노드별 τ 편차 (τ-4)

**시뮬이 σ=30%로 가정한 값을 실측으로 바꾸는 작업.** 이 가정 하나가 방향 추정 결과를 통째로 좌우한다는 게 확인됐으므로 우선순위가 높다.

1. **측정 B와 완전히 동일한 조건**(같은 풍량 설정·거리·정렬·온도 설정)을 유지.
2. **센서만 바꿔가며** 같은 시행을 반복. **최소 5개, 가능하면 8개 이상.**
3. 각 센서 개체를 구분할 수 있게 **번호를 붙여둘 것**(마스킹테이프).

**산출:** τ의 평균과 표준편차 → σ_τ 실측치.

tau_s3_n02_01.csv  노즐A/설정3/거리5cm/온도150/센서02/상온26.6/에어컨OFF/가열+냉각

**메타를 안 적으면 나중에 어느 파일이 무슨 조건인지 알 수 없어 데이터가 통째로 못 쓰게 된다.** 파일명에 조건을 박아두는 게 제일 안전하다.

## 7. 흔한 함정 (미리 알고 가면 안 겪는다)

- **예열 부족** — 켜자마자 재면 출력이 변하는 중이라 곡선이 지저분해진다. 1~2분 기다릴 것.
- **센서 위치가 조금씩 달라짐** — 제트는 좁아서 1cm만 어긋나도 유속이 크게 달라진다. **테이프로 위치 표시 필수.**
- **상온 상승** — 세션 후반에 방이 더워지면 기준이 밀린다. 매번 기록 + 환기.
- **냉각 대기 부족** — 완전히 안 식은 상태에서 다음 시행을 하면 초기값이 틀어진다. 급하면 선풍기.
- **풍속계를 뜨거운 바람에 넣기** — 날개가 변형된다. 히터 OFF 상태에서만.

## 8. 세션 후 — Claude Code에게 넘길 것

원자료(CSV)와 메타를 넘기면서 요청할 분석:

```
H1 τ 실측 원자료 분석. 각 시행에서:
1) 가열/냉각 각각의 τ를 (초기→최종)의 63.2% 도달시간으로 산출
2) 1차 지연 모델 exp fit의 R²도 함께 (모델 적합도 확인)
3) 풍속 표(측정A)를 붙여 τ vs 풍속 곡선 산출
   ★풍속은 상온 측정값이며 고온 운전 시엔 절대온도비 보정이 필요하다는 것을 명시.
   기존 τ(u)=24.6·u^-0.5(자유도 0, 미검증)와 비교해 그 관계가 성립하는지 판정.
4) 측정D에서 센서별 τ의 평균·표준편차 → σ_τ 실측치.
   시뮬이 쓰던 σ=30% 가정과 비교. 실측이 더 작으면 2.J-A의 지터 결과가 완화됨.
5) 무풍 τ(측정C)를 기존 78.48s(에어컨 ON)와 비교 — 진짜 하한이 얼마인지.
결론 문장은 쓰지 말고 원자료·표·플래그만. 해석은 Cowork.
```

_H1 = 프로젝트 최대 미지수를 측정치로 바꾸는 세션. 16노드도 데모도 필요 없고 노드 하나면 된다. 세팅 고정과 메타 기록이 결과 품질의 전부다._
