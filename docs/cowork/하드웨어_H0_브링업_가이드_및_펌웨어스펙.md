# 하드웨어 H0 — 브링업 가이드 + 펌웨어 스펙
### 「불사」 실물 단계 첫 수 · 단일 노드 → 3노드 메시 → 게이트웨이

> **H0의 목표:** "끝에서 끝까지"가 3노드로 도는 걸 확인해 자신감을 만든다. **불도 열원도 필요 없다.** 배선 + 펌웨어 + 게이트웨이 로깅만.
> **역할:** 물리 배선·플래싱 = 당신 / 펌웨어·게이트웨이 코드 = Claude Code(맨 아래 복붙 블록) / 프로토콜·검증 = 나.
> **정직성:** 이건 벤치에서 알고리즘·파이프라인을 실물로 세우는 것. 야외 화재 시험 아님(문서·영상에 그대로 표기).

---

## 1. 준비물 확인 (H0용)
- ESP32 개발보드 1~3개, USB 케이블
- DS18B20 온도센서 1~3개
- **4.7 kΩ 저항**(DS18B20 데이터 풀업용) 노드당 1개 — 없으면 이것부터 확보(제일 흔한 브링업 실패 원인)
- WS2812(NeoPixel) LED 1~3개(또는 스트립 일부)
- 라즈베리파이(게이트웨이)
- (H1에서 쓸) 드라이기 — H0엔 불필요. **열풍기는 주문만 걸어두기.**

---

## 2. 단일 노드 배선 (먼저 1개만)

**DS18B20 (1-Wire = *선 하나로 통신하는 디지털 온도센서 방식*):**

| DS18B20 핀 | 연결 |
|---|---|
| VDD (빨강) | ESP32 3V3 |
| GND (검정) | ESP32 GND |
| DATA (노랑) | ESP32 GPIO4 |
| **풀업** | DATA ↔ 3V3 사이 **4.7 kΩ** (필수) |

**WS2812 LED:**

| WS2812 | 연결 |
|---|---|
| VCC | ESP32 5V(VIN) |
| GND | ESP32 GND(공통) |
| DIN | ESP32 GPIO5 (필요시 300~470 Ω 직렬) |

> ⚠ WS2812는 5V 로직을 기대하는데 ESP32는 3.3V라, LED 몇 개는 대개 그냥 되지만 불안정하면 레벨시프터 또는 데이터 직렬저항. GND는 반드시 ESP32와 공통.

---

## 3. 펌웨어 스펙 (Claude Code가 생성 — 요구사항)

**단일 노드 v0 (먼저):**
- 라이브러리: `OneWire` + `DallasTemperature`(DS18B20), `Adafruit_NeoPixel` 또는 `FastLED`(WS2812).
- **온도 읽기 — 두 모드 지원(중요, τ 측정 때문):**
  - **정상 모드:** 12비트(0.0625℃ 분해능, 변환 ~750ms) → 보고 주기 1s.
  - **★특성화(고속) 모드:** **9비트(0.5℃, 변환 ~94ms → 약 10 Hz)** — τ 계단응답 곡선을 촘촘히 뜨기 위함. `#define`로 전환.
  - _근거: DS18B20 변환시간(12비트 750ms)이 우리 1s 하트비트와 맞먹어서, 2.H의 "1s라 미분이 거칠다"는 상당 부분 이 하드웨어 한계다. 9비트로 떨어뜨리면 10 Hz까지 나옴 — τ·재구성 품질에 직접 도움._
- **LED 상태(생사 2색):** `ALIVE` 초록 / `DYING`·`DEAD` 빨강. 경보는 LED 가 아니라 **대시보드**에만 있다.
> ※ [2026-08-31] LED 서술을 현행 구현으로 맞췄다. 온도 밴드 3색(초록/호박/빨강)은 **구현되지 않은 옛 스펙**이었다 — 실제 `node.ino:155-159` 는 상태 2색이고, 온도 밴드용 중간 상태(WARN)가 상태 머신에 없다.

- **시리얼 출력(특성화 로깅용):** `millis(), temp_C` CSV 한 줄씩. **이게 H1 τ 측정의 원자료.**
- 코드는 **모듈화** — mesh/게이트웨이를 뒤에 얹기 쉽게(온도읽기·LED·보고를 분리).

**메시 v1 (노드 2~3개):**
- `painlessMesh` 연결, 각 노드가 `{node_id, node_time(getNodeTime), temp_C, seq}` 브로드캐스트.
- **★사망시각 규약:** 보고에 **노드 자기 각인 시각(getNodeTime 동기)**을 실어라 — 게이트웨이 수신 시각이 아니라(우리 D#1 확인 항목과 직결; 통신 지연이 도착시각장을 오염하지 않게).
- 시간동기 동작 확인(두 노드의 node_time이 수십 ms 내로 맞나).

**게이트웨이 v1 (라즈베리파이, 파이썬):**
- 메시 수신 → `(recv_wall_time, node_id, node_time, temp)` **CSV 로깅**(나중에 시뮬 estimator가 그대로 먹을 형식).
- 간단 실시간 표시(노드별 최신 온도·LED 상태)면 충분. 대시보드는 H2에서 확장.

---

## 4. 브링업 순서 (하나씩, 각 단계 통과 후 다음)
1. **1노드:** 플래시 → 시리얼에 온도 뜸 → 손으로 센서 만지면 값 오름 → 임계를 넘기면 LED 가 초록에서 빨강으로 바뀜.
2. **9비트 고속 모드:** 시리얼이 ~10 Hz로 쏟아지나 확인(τ 측정 준비).
3. **2노드 메시:** 둘이 서로 보이고 node_time이 맞나.
4. **3노드 + 파이:** 파이 CSV에 3노드 (node_time, temp)가 쌓이나.
5. 통과하면 H0 끝 — H1(센서 특성화)로.

---

## 5. 스모크 테스트 체크리스트 (H0 완료 기준)
- [ ] 단일 노드 온도 정상(상온 ~25℃ 근처), 손대면 상승
- [ ] LED 전환(초록 → 빨강) 육안 확인 — 임계 통과 시 1회
- [ ] 9비트 모드 ~10 Hz 로깅
- [ ] 2노드 메시 형성 + node_time 동기(수십 ms)
- [ ] 파이 게이트웨이가 (node_time, node_id, temp) CSV 축적
- [ ] 사망시각이 **노드 각인 시각**으로 기록됨(수신 시각 아님)

---

## 6. 다음(H1-τ) 예고 — 열원 없이도 곧 가능
1노드가 9비트 고속 로깅되면, **드라이기로 τ 측정** 바로 가능:
- 드라이기를 켜서 온도·바람 안정 → **빠르게 센서에 갖다 대(계단 입력)** → 시리얼 CSV 기록 → 센서 값이 (초기→최종)의 **63.2% 도달 시간 = τ.**
- **맨몸 센서 vs 외피/피복 씌운 센서** 각각 측정(외피가 τ를 키우는 2차 거동 확인 = B2).
- 여러 노드 τ 분포(제조 편차) → 시뮬의 "변동 τ" 실측 근거.
- 상세 프로토콜은 H0 통과 후 별도로 드림.

---

## 7. Claude Code 복붙 블록 (펌웨어·게이트웨이 생성 요청)

```
「불사」 하드웨어 브링업(H0) 펌웨어를 단계적으로 생성해줘. 보드 ESP32, 센서 DS18B20(1-Wire, GPIO4, 4.7k 풀업),
LED WS2812(GPIO5). 컴파일·라이브러리 설치까지 도와줘.

v0 단일 노드:
- OneWire+DallasTemperature로 DS18B20 읽기. 두 모드: 정상=12비트(보고 1s), 특성화=9비트(~10Hz). #define로 전환.
- WS2812를 온도밴드로: <50℃ 초록 / 50~60 호박 / ≥60 빨강 / 사망판정 소등. (임계는 상수로 빼서 조정 가능하게)
- 시리얼에 'millis(),temp_C' CSV 한 줄씩(특성화 로깅 원자료). 코드는 온도읽기/LED/보고 분리해 모듈화.

v1 메시(노드 2~3개):
- painlessMesh로 각 노드가 {node_id, node_time=getNodeTime(), temp_C, seq} 브로드캐스트.
- ★사망/보고 시각은 반드시 노드 각인 getNodeTime 값(게이트웨이 수신 시각 아님).
- 두 노드 node_time 동기가 수십 ms 내인지 확인용 로그.

v1 게이트웨이(라즈베리파이 파이썬):
- 메시 수신 → (recv_wall_time, node_id, node_time, temp) CSV 로깅(시뮬 estimator가 그대로 먹을 형식).
- 노드별 최신 온도·LED상태 간단 실시간 표시.

한 번에 다 말고 v0부터 컴파일·플래시 되게 주고, 내가 1노드 확인하면 v1 메시, 그다음 게이트웨이 순서로.
9비트 변환시간(~94ms)·12비트(~750ms) 차이도 코드 주석에 명시해줘(τ 측정·재구성 품질과 직결).
```

_H0 = 파이프라인을 3노드로 세우는 것. 통과하면 H1(센서 특성화)에서 τ·warm_scale·death를 실측해 우리 밴드 주장을 '시뮬 전제'에서 '측정 검증'으로 바꾼다._
