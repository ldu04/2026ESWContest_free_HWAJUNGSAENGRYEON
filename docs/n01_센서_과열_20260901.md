# n01 온도센서 과열 — 극성 반대 (2026-09-01)

## 증상
새 DS18B20 을 n01 에 꽂고 만졌더니 **화상 직전까지 뜨거웠다.** 외부 열원 없음.
사용자가 즉시 점퍼선을 분리했다.

## 원인 — **DAT 와 VCC 가 서로 바뀌어 있었다** (사용자 확인)

    잘못된 배선            맞는 배선
      DAT → 3.3V            DAT → GPIO4
      VCC → GPIO4           VCC → 3.3V
      GND → GND             GND → GND   (이건 맞았다)

이 한 가지가 **두 증상을 동시에** 설명한다.
- **과열**: 데이터 핀이 3.3V 에 직결되어 내부 보호소자로 전류가 계속 흐른다. 게다가
  전원을 GPIO4 에서 받는데 GPIO 는 그만한 전류를 공급하지 못해 비정상 동작한다.
- **25.00 고정**: 1-Wire 통신선(GPIO4)이 데이터 핀에 연결되어 있지 않다. 대화 자체가
  성립하지 않으므로 읽기는 항상 실패하고, `readTemp()` 가 초기값 25.0f 를 계속 돌려준다.

풀업 4.7kΩ 은 **GPIO4 ↔ 3.3V** 사이에 놓는다.

이게 앞선 모든 증상을 설명한다:
- 원래 센서도 같은 자리에서 이미 타서 죽었다 → 읽기 실패 → `readTemp()` 가 직전값을
  돌려주고 초기값이 25.0f → **정확히 25.00℃ 로 영구 고정**(표본 37개, 변화 0.00).
- 그래서 임계 80℃ 에 영영 도달하지 못했고, LED 도 안 빨개졌고, 노드도 안 죽었다.
- 리허설 1회차가 S4 로 무산된 근본 원인이 이것이다.

## DS18B20 (TO-92) 핀 배열 — **평평한 면을 보고, 다리를 아래로**

    평평한 면이 나를 향할 때, 왼쪽부터:
      1: GND        2: DQ(데이터)      3: VDD(3.3V)

**둥근 면을 보고 꽂으면 좌우가 뒤집혀 GND 와 VDD 가 정확히 바뀐다.** 이번 사고의 형태다.
브레드보드에서 **한 칸 밀려 꽂아도** 같은 결과가 난다.

## 재연결 전 확인 (순서대로)
1. 전원을 뺀 상태에서 **평평한 면 기준** 핀 순서를 다시 확인한다.
2. DQ ↔ VDD 사이 **풀업 4.7kΩ**.
3. VDD 는 **3.3V**(5V 아님), 데이터는 **GPIO4**.
4. 꽂은 직후 **손대지 말고** `scripts/temp_voice.py --ports <n01포트>` 로 값을 먼저 본다.
   정상이면 실온 값이 나오고 **패키지는 미지근하지도 않다.**
5. 5초 안에 값이 안 나오거나 뜨거워지면 **즉시 분리**한다.

## 파급
- 방금 꽂은 **예비 센서 1개가 손상됐을 가능성이 높다.** 예비 재고 0.
- n01 의 **ESP32 3.3V 레귤레이터**가 과전류를 겪었다 — 재연결 후 다른 동작도 확인한다.
- **전 노드의 센서 극성을 눈으로 확인해야 한다.** 같은 실수가 다른 보드에 있으면
  그 노드도 25.00 고정이고, 리허설에서 또 안 죽는다.
