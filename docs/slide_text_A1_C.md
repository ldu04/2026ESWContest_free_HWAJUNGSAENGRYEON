## A1 — 슬라이드 5 「개발 환경 ① 시스템 구성」 전원 항목 교체

### 지금 (틀림)
```
· 전원: 배터리 / 승압 모듈
```

### 교체
```
· 전원(데모)  : USB 5V 급전 — 12분 연속 구동과 회차 간 재현성 확보
· 전원(배치)  : 배터리 + 승압 모듈(MT3608) — 노드 소비전류 [추정 — 데이터시트 기준, 실측 미실시] 기준 용량 산정 (§6)
```

### 같은 슬라이드 하단 주석에 한 줄 추가
```
※ 데모는 판 위 16노드를 12분간 같은 조건으로 반복 구동해야 하므로 USB로 급전한다.
   전원 방식은 사망 판정·메시 동작과 독립이며, 실전 배치 전원은 §6에서 다룬다.
```

### 슬라이드 19 「파급력·기대효과 ② 시장성·발전」에 항목 추가
```
배치 전원 설계
· 노드는 대부분의 시간을 대기 상태로 보내고, 화선 통과 시에만 고빈도 샘플링한다.
· 소비전류 [추정 — 데이터시트 기준, 실측 미실시] × 목표 운용기간 → 배터리 용량. 승압 모듈로 단일 셀에서 5V 확보.
· 저가 소모형 전제상 배터리는 회수하지 않는다 — 단가에 포함되는 소모 부품이다.
```

> **왜 이렇게 쓰나:** 감추면 영상의 USB 케이블 16가닥과 정면으로 어긋난다.
> 「데모 조건」과 「배치 조건」을 나눠 쓰면, 둘의 차이를 아는 팀이 된다.

## C — 슬라이드 17 「성능·강건성」 표의 한 줄 교체

### 지금 (자랑이 결함으로 뒤집힐 수 있음)
```
타원 측면 · 노드 희소 | ★ 자기 차단 — 값을 내지 않음 | 오답 대신 침묵. 정보 부족을 스스로 판정
```

### 교체
```
타원 측면 · 노드 희소 | 자기 차단(값 미출력) | 정보 부족과 표본 굶주림을 분리해야 성립 — §4-E
```

### 표 아래 각주 한 줄
```
※ 자기 차단은 유효한 기능이지만, 초기 보고에서 '정보 부족'으로 해석한 것 중 일부는
   우리가 설정한 창 크기가 만든 표본 굶주림이었다. 원인 분해와 재발 방지는 §4-E.
```

## C — 신규 슬라이드 「4-E」 (4장 마지막에 추가)

### 제목줄
```
장애요인·해결 ⑤ ★ 자랑하던 것을 의심하다  |  공학 성숙도
'자기 차단'은 정보 부족이었나, 우리 상수였나
```

### 본문 1 — 증상
```
우리는 「정보가 없으면 값을 내지 않는다」를 강점으로 보고했다.
그런데 알고리즘을 20cm 실물 격자로 옮겨 다시 재보니, 16노드 전부가 값을 내지 못했다.
자랑하던 기능이 전면 작동한 것인지, 아니면 무언가 잘못된 것인지 구분해야 했다.
```

### 본문 2 — 원인 (박스)
```
dt_window = 8.0 s

이 값은 시뮬 전선 속도 1.5 m/s 기준으로 잡혀 있었다.
20cm 벤치의 전선은 1.1 mm/s — 1,360배 느리다.

  이웃 간격 0.20 m 통과 시간   182 s
  통신 반경 0.36 m 통과 시간   327 s
  설정된 창                      8 s   ← 이웃이 한 명도 창에 못 들어온다

모든 국소 집합이 자기 자신 하나뿐이 되어, 최소 표본 조건에서 전부 기각됐다.
```

### 본문 3 — 창 크기 스윕 (표)
```
dt_window(s) | 산출 성공 | 전역 방향 | 참값 55.48° 대비 | 실패 원인
     60      |   2 / 16  |  31.64°  |   −24.03°       | 전부 표본 부족
    120      |  12 / 16  |  51.12°  |    −4.55°       | 전부 표본 부족
    173      |  15 / 16  |  55.76°  |    +0.09°       | 표본 부족 1건
    240      |  16 / 16  |  55.89°  |    +0.22°       | 없음
    327      |  16 / 16  |  55.92°  |    +0.25°       | 없음  ← 유도값
```
```
★ 실패 원인은 전부 '표본 부족'이었고, 기하 조건(공선·조건수) 실패는 0건이었다.
   → 기하가 나쁜 게 아니라, 볼 표본 자체가 없었다.
```

### 본문 4 — 과거 기록에서도 같은 일 (박스)
```
같은 증상이 이미 기록돼 있었다.
타원 측면 조건에서 82~86° 였던 방향오차는, 창을 넓히자 1.55~5.96° 로 드러났다.
즉 그 82°는 '정보가 없어서'가 아니라 '표본이 굶어서' 나온 가짜 오차였다.

다만 창을 넓히면 대가도 있다 — 먼 시간대 이웃이 섞여 곡률 오차가 들어온다.
(정면 조건 일부에서 2.12° → 33.03° 로 악화)
표본 적정성과 정확도는 단조 대응이 아니다.
```

### 본문 5 — 재발 방지
```
값을 새로 고르는 대신, 상수를 물리에서 유도하도록 구조를 바꿨다.

    dt_window = radio_range / v_front_expected

전선 속도가 바뀌면 창이 따라 움직인다. 오늘 t80 재측정으로 체류시간이 바뀌어도
같은 사고가 되풀이되지 않는다.

그리고 같은 병이 하나일 리 없다고 보고, 규모 의존 상수를 전수 감사했다 — 4건이 나왔다.
  dt_window · residual_gate_s · alert_horizon · speed_true
전부 시뮬 규모(10 m 간격 · 1.5 m/s)에서 온 값이고, 벤치(0.20 m · 1.1 mm/s)에서는
27.3배 어긋나 있었다. 하나씩 부딪히는 대신 한 번에 유도식으로 전환했다.

시작 로그에 유도식과 계산값을 함께 찍어, 물리와 안 맞으면 로그만 봐도 드러나게 했다.
```

### 마무리 한 줄 (슬라이드 하단 강조)
```
자기 강점을 스스로 의심해서 잡아낸 결함이다. 지표를 고친 게 아니라 구조를 고쳤다.
```

## 배치 지침

- 4-E는 기존 4장 슬라이드(4-A ~ 4-D)와 같은 템플릿을 쓴다. 표는 슬라이드 17의 표 스타일 재사용.
- 4장이 5슬라이드가 되면 10P 배분 안에서 3장(개발 프로그램 설명)과 균형을 다시 볼 것.
  20P 초과분은 평가 미반영이므로, 넘치면 3장에서 한 장을 줄인다.
- 표 안의 숫자는 **Claude Code가 저장소의 스윕 결과와 대조해 검증할 것.**
  내가 대화에서 받은 값을 옮긴 것이므로, 다르면 저장소 값이 맞다.
