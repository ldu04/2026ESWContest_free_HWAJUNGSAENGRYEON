# 강령 — 위험 작업 고지

> 이 문서는 사람과 Claude(대화·Code) 모두에게 적용된다.
> **답하기 전에 읽는다.** 아래 목록에 해당하는 작업을 제안하거나 실행하기 전에는,
> 반드시 (1) 무엇이 (2) 어떤 방식으로 망가질 수 있는지 (3) 되돌릴 수단이 있는지를
> **먼저 말한다.** 되돌릴 수단이 없으면 자동화하지 않고 사람이 직접 한다.

---

## 1. 자동화하지 않는다 — 사람이 직접

| 작업 | 망가지는 방식 |
|---|---|
| **디스크·SD카드 이미지 쓰기, 파티션 조작** | 대상 디스크를 한 글자 잘못 고르면 시스템 드라이브가 통째로 지워진다. 저장소·덱·사진이 전부 사라진다. GUI 도구는 시스템 디스크를 목록에서 빼주지만 스크립트는 안 그런다. |
| **저장소 Public 전환** | 되돌릴 수 없다. 공개된 순간 크롤러·포크가 사본을 갖는다. 비공개로 되돌려도 유출된 값은 유출된 값이다. |
| **강제 삭제·대량 이동** (`rm -rf`, 대량 `mv`) | 대상 경로를 잘못 쓰면 복구 불가. 특히 와일드카드. |

## 2. 실행 전에 백업하고, 백업 위치를 먼저 말한다

| 작업 | 망가지는 방식 |
|---|---|
| **git filter-repo, force push, `reset --hard`** | 커밋 히스토리가 재작성된다. 되돌리려면 백업뿐이다. |
| **원본 파일 in-place 수정** | 원본이 사라진다. 변환·정리 결과는 **새 파일로** 만들고 원본을 남긴다. |

## 3. 실행 전에 "되돌릴 수 있는지"를 먼저 확인한다

| 작업 | 망가지는 방식 |
|---|---|
| **외부 서비스에 무언가 생성** (저장소, 릴리스, 업로드) | 만들 권한과 **지울 권한은 다르다**. 2026-08-30에 확인용 임시 저장소를 만들었다가 토큰에 `delete_repo` 스코프가 없어 못 지웠다. 만들기 전에 지울 수 있는지 확인한다. |
| **펌웨어 굽기** | 잘못된 보드에 구우면 그 보드의 설정이 사라진다. 2026-08-30에 COM 번호 재배정으로 엉뚱한 보드에 브리지(99)를 구웠다. 굽기 전에 **그 포트가 방금 꽂은 보드가 맞는지** 잠근다(포트 증분 / MAC / mid). |

## 4. 측정을 오염시키지 않는다

- 측정 런 도중 개입하지 않는다. 촬영을 위해 런을 멈추면 그 데이터는 실측이 아니다.
- 결과를 기대값에 맞추려고 파라미터·기대값을 고치지 않는다.
- 실패한 회차도 지우지 않는다.

## 5. 되돌리기 어려운 **판단**도 같은 급이다

범위 축소·기능 포기·전면 재작업을 권하기 전에는 **계측을 먼저 본다.**

계기: 2026-08-31, LED 8/11이 흰색인 것을 "납땜 불량"으로 보고 LED 포기를 권했으나,
시리얼 로그를 읽자 **그 보드들에 node.ino가 안 구워져 있던 것**이었다. 납땜은 멀쩡했다.
로그는 처음부터 읽을 수 있었고 30초짜리였다.

## 고지 형식

위 작업을 제안할 때는 이 세 줄을 먼저 쓴다.

```
무엇이 위험한가 : (예) 디스크를 잘못 지정하면 시스템 드라이브가 지워진다
되돌릴 수 있나  : 없음 / 백업 위치 <경로>
그래서 어떻게   : GUI로 사람이 직접 / 백업 후 진행 / 확인 절차 <무엇>
```
