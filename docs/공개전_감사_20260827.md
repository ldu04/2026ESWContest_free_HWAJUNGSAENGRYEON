## ★ 처리 방안 (실행 안 함 — 안만)

문제 파일은 **전부 커밋 `49fa494` 하나에** 들어갔다. 그 뒤로 커밋 7개.
전체 34커밋 · `.git` 8.7 MB.

### 방안 1 — `git rm` 후 새 커밋 ❌ 무효

```bash
git rm docs/cowork/*.pdf && git commit
```
작업트리에서만 사라진다. **`49fa494` 를 체크아웃하면 그대로 나온다.** GitHub UI에서도 히스토리로 접근 가능.
**push 후에는 이걸로 못 막는다.**

### 방안 2 — `git filter-repo` (권장) ⭐

```bash
pip install git-filter-repo
git filter-repo --invert-paths \
  --path docs/cowork/공모전_작품개발지원_신청서.pdf \
  --path docs/cowork/자기계발지원_신청서_세부계획서.pdf \
  --path docs/cowork/면담자료_교수님.pdf \
  --path docs/cowork/작품개발계획서_재료비.pdf \
  --path docs/cowork/작품개발개요서_16노드.pdf \
  --path docs/cowork/_archive/재료비명세_초안_자가치유메시.md \
  --path docs/cowork/_archive/재료비명세_최종_자가치유메시.md
```

| 항목 | 값 |
|---|---|
| 작업량 | **5~10분** |
| 히스토리 | **34커밋 전부 보존** — 메시지·순서·날짜 그대로 |
| 바뀌는 것 | `49fa494` 이후 **7개 커밋의 해시** (내용 변경이므로 불가피) |
| 위험도 | **낮음** — 아직 push 안 했으므로 협업자 충돌 없음. 로컬 단독 |
| 주의 | 실행 전 `.git` 통째 백업. filter-repo 는 `origin` 을 자동 제거함 |

**이 방안이 맞는 이유:** 커밋 이력 34개가 measure-first 규율의 증거다(유도를 구현 전에 커밋한
`0d03c98` 같은 것). 그걸 버리면 5장 차별성의 근거 하나가 사라진다. **파일만 빼고 이력은 살린다.**

### 방안 3 — 히스토리 버리고 새로 시작 ❌ 권장 안 함

```bash
rm -rf .git && git init && git add -A && git commit -m "initial"
```
30초에 끝나고 완벽히 안전하지만, **개발 규율의 증거가 통째로 사라진다.**
"유도를 측정 전에 커밋했다"는 주장이 검증 불가능해진다. **이번 건에서는 손실이 더 크다.**

### 방안 4 — 두 저장소 분리

공개용에는 `docs/cowork/` 를 아예 제외. 간단하지만 보고서 원본·실측기록까지 빠져
심사위원이 근거를 못 본다. **비권장.**
