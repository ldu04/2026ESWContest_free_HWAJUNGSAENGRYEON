# 구현지시서 2.J — 실측 τ 방향 강건성 재검증 + 미탐지율 피크온도 스윕
### 「불사」 · τ 실측(11s/78.5s) 이후 두 개의 정직성 검증 · 전부 시뮬(열원 불필요)

> **왜 지금 이걸 하나:** H1 τ 실측에서 τ가 우리가 검증해둔 울타리({0,2,5,10}s)를 벗어났다(강제대류 11s, AC-on "정지" 78.5s). 그래서 **두 가지를 아직 실제로는 모른다**: (A) 실측 τ에서도 우리 왕관 보석인 **방향 2.1°가 버티나?** (B) 2.I-a의 "τ 크면 미탐지" 걱정이 **현실 불 피크온도에서도 그대로인가?** 둘 다 사용자(팀장)가 대화에서 직접 제기한 정당한 의심이고, "안 흔들린다"를 **측정으로** 답해야 한다. 드라이기 없이 돌아가는 순수 시뮬 작업.
>
> **역할:** 시뮬 구현·실행 = Claude Code / 사전등록 예측·해석·정직성 감사 = Cowork / 결과 판정·다음 수 = 사용자.
>
> **강령(필수 준수):** ① 측정 우선 — 예측이 틀리면 **틀렸다고 기록**하고 넘어간다(§5.6·P4a 전례). ② **자기채점 금지** — "시뮬 생성기를 그대로 뒤집어 맞추는" 동어반복(tautology)은 점수로 세지 않는다. ③ **체리피킹 금지** — 우리에게 유리한 피크/조건만 고르지 않고 **표면 전체**를 보고한다. ④ 결과가 우리 주장에 불리하게 나와도 **그대로** 올린다.

## 파트 A — 검증①: 실측 τ에서 방향(direction) 강건성

### A-0. 배경 (왜 방향이 구조적으로 강한가 — 하지만 아직 안 쟀다)
방향은 죽음시각들의 **기울기(gradient = 공간에 걸친 death time의 차이)**에서 나온다. τ가 모든 노드에 **균일한 상수 지연**만 준다면, 그건 모든 death time에 같은 값을 더하는 것 → 차이(기울기)에서 상수가 상쇄되어 방향은 원리적으로 불변이다.

**그러나** 지난 P4a 교훈(내가 틀렸던 건): **균일 τ도 곡선 전선(curved front)에서는 노드마다 온도상승률(dT/dt)이 달라, threshold 교차 지연이 노드별로 불균일해진다** → 기울기 오염 → 방향 열화. 작은 τ({0,2,5,10}s)에선 그 열화가 작아 2.1°가 버텼다. **τ=78.5s에서도 버티는지는 한 번도 안 쟀다.** 이 파트가 그걸 잰다.

### A-1. 사전등록 예측 (틀리면 틀렸다고 기록)
- **예측 A1:** τ가 커질수록 방향오차는 **단조 증가**한다(P4a 메커니즘). 하지만 **붕괴(예: >10°)하지 않고**, τ=78.5s에서도 대략 **한 자릿수 도 이내**에 머문다 — 왜냐하면 오염은 "dT/dt 불균일"이라는 **2차 효과**일 뿐, 상수 지연 성분은 여전히 기울기에서 상쇄되기 때문.
- **예측 A2:** **노드별 지터 τ**(제조 편차)가 **균일 τ보다 방향을 더 많이** 망친다 — 지터는 상수 상쇄가 안 되는 진짜 랜덤 오염이므로.
- **정직성 경고:** 이건 어디까지나 예측이다. §5.6·P4a에서 부호·방향을 두 번 틀렸다. **직관 믿지 말고 측정치를 그대로 보고하라.** A1이 깨지면(예: τ=78s에서 방향이 실제로 붕괴하면) 그건 프로젝트 코어에 대한 **진짜 경고**이므로 절대 숨기지 말 것.

### A-2. 실행 스펙
1. **기존 방향 estimator 재사용**: 평면 최소자승 적합 → ∇T → direction = ∇T/|∇T|. 손대지 말 것.
2. **센서 지연 τ 주입**: 각 노드의 참 공기온도 시계열에 1차 지연을 씌운 뒤 threshold 교차로 death time.
   `T_sensor += (T_air − T_sensor)·(dt/τ)` (τ→0이면 즉시).
   - death 판정 threshold는 **현재 시뮬이 쓰는 값 그대로**(바꾸지 말 것).
3. **τ 스윕(두 계열):**
   - **균일 τ**: `{0, 2, 5, 10, 11, 20, 30, 50, 78.5, 100}` s. (실측 두 점 11, 78.5 필수 포함.)
   - **노드별 지터 τ**: μ ∈ `{11, 30, 78.5}` s, τ_i ~ μ·(1 + N(0, 0.3)), 하한 0.5s 클립. 시드 평균.
4. **전선 조건**: **곡선 전선 반드시 포함**(직선만 쓰면 P4a 효과가 숨어 낙관 편향). 직선 전선도 대조군.
5. **출력:** `τ vs 방향오차(도)` 곡선(균일/지터, 곡선/직선), 각 τ의 **미탐지 노드 수**, 판정선 **방향오차 ≤ 5°**를 τ가 어디서 넘는지.

### A-3. 정직성 체크
- [ ] threshold·전선·노드배치를 A에서 바꾸지 않았나?
- [ ] 실측 두 점(11, 78.5)이 스윕에 들어갔나?
- [ ] 예측 A1/A2와 실제 결과가 어긋난 지점을 본문에 그대로 적었나?
- [ ] 곡선 전선을 뺐거나 직선만 써서 결과를 좋게 만든 건 아닌가?

## 파트 B — 검증②: 미탐지율 × 불 피크온도 스윕

### B-0. 배경
2.I-a의 "τ/펄스폭 > 1.2배부터 미탐지, 3.5배에서 100%"는 **어떤 특정 피크온도**를 가정한 숫자다.
1차 지연에서 임계 교차 시각 `t = −τ·ln(1−f)`, `f = (임계−상온)/(피크−상온)`. 피크 300℃·임계 80℃·상온 25℃ → f=0.2 → t=0.22τ. 피크 120℃면 f=0.58 → t=0.87τ. **뜨거운 불이 같은 선을 ~4배 빨리 밟는다.**

### B-1. 사전등록 예측
- **B1:** 피크온도↑ → 미탐지율↓ (단조). τ=78.5s라도 피크가 충분히 높으면 미탐지율이 크게 떨어진다.
- **B2:** 하지만 노드가 겪는 피크는 화염 온도가 아니라 **warm_scale 감쇠로 낮아진 센서 위치 공기온도**다. 멀리 스치는 노드는 피크가 낮아 미탐지 걱정이 되살아난다. **단일 피크로 "안전" 결론 금지.**

### B-2. 실행 스펙
1. 2.I-a 미탐지 시뮬 재사용 + **피크온도 축 추가**: peak ∈ `{100,150,200,300,500}` ℃.
2. **τ축** `{11,30,50,78.5,100}` s. **임계 80℃ 고정**. 펄스폭/형태는 2.I-a 그대로.
3. **출력**: `(peak, τ) → 미탐지율(%)` 히트맵 + 각 셀의 도달최고온/80℃ 마진.
4. **★현실 운영점 오버레이**: warm_scale 감쇠로 노드-불 거리별 유효 피크 분포를 계산해 표면에 오버레이. **분포 전체**가 위험구역에 얼마나 걸치나 보고.
5. **판정**: 미탐지율 ≤ 5%를 지키는 τ 상한을 피크별 표로.

### B-3. 정직성 체크
- [ ] 임계·펄스폭·펄스형태를 2.I-a에서 안 바꿨나?
- [ ] 유리한 피크만 강조하고 낮은 피크를 숨기지 않았나?
- [ ] warm_scale 감쇠로 유효 피크가 화염온도보다 훨씬 낮다는 걸 명시했나?
- [ ] "그러니 안전"이 아니라 **조건부 서술**했나?
