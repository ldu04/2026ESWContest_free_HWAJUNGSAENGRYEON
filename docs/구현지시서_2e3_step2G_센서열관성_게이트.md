# 구현 지시서 #2e-3 **Step 2.G** — 센서 열관성 τ 게이트 + 실물 실측 프로토콜
### 화중생련 「불사」 / E3x 밴드의 두 번째 캘리브레이션 의존 변수를 정면으로

> **왜 이 단계인가.** 외부 검토에서 **DS18B20 센서의 열관성(thermal inertia)** 이 지적됐다. 이건 우리 2.F가 다룬 warm_scale과 **같은 종류의 문제** — *시뮬에는 없지만 실물에는 있는, 우리가 정확히 모르는 캘리브레이션 변수*다. 2.F는 warm_scale만 게이트했고 **τ는 아직 게이트 밖**이다. 이 단계는 2.F 기계를 τ로 확장한다.

**용어(이 지시서에서 쓰는 것):**
- **열관성 τ (thermal inertia / time constant):** 센서 내부 온도가 주변 온도를 즉시 따라가지 못하고 **시상수 τ로 지연 추종**하는 것. 1차 저역통과(*first-order low-pass = 입력 변화를 dT_sensor/dt = (T_air − T_sensor)/τ 로 뒤늦게 따라가는 필터*)로 모델링. τ가 클수록 느림. 외부 추정 τ≈2~10s.
- **breach_early(위험측):** 참 도착이 밴드의 가장 이른 끝보다 더 이름 = 불이 최조기 예측보다 먼저 옴 = 위험.
- **W0:** 시뮬 warm_scale 기준값(6m).

## 1. 핵심 물리 (착수 전 이해하고, 예측을 코드에 먼저 적을 것)

현재 시뮬은 **노드 주변 공기 온도가 임계(80℃)에 닿는 즉시** 사망 보고를 낸다. 실물 DS18B20은 열관성 때문에 **센서 체적 내부 온도**가 80℃에 닿아야 보고하고, 그건 공기가 80℃ 된 시점보다 **τ만큼 늦다** → **사망시각 t_i가 뒤로 밀린다.**

**★ 부호 예측 — 착수 전 스크립트 docstring에 먼저 적고, 측정으로 확정하라(§5.6 교훈: 부호를 직관으로 건너뛰지 말고 끝까지 밀 것).**
- 무보정 원 추정에서 사망시각은 참 도착보다 **6.44초 이르다**(노드가 죽을 때 불은 아직 d=9.657m 앞, §1d의 −6.4초 선행).
- τ는 사망시각을 **뒤로** 밀어 이 6.44초 선행 마진을 갉아먹는다. τ가 6.44초를 넘으면 사망시각이 참 도착보다 **늦어진다.**
- E3 편향 항은 "원 추정이 6.44초 이르다"고 **가정하고** 그만큼 뒤로 민다. τ 때문에 원 추정이 덜 이르면(또는 늦으면) E3는 **과대보정**(참값을 지나쳐 너무 뒤로) → 밴드가 참값보다 **늦게** 놓임 → **breach_early(위험측) 증가.**
- **⇒ 예측: τ가 클수록 위험측이 오른다. 그리고 이 위험 방향은 2.F의 "warm_scale 과소"와 같은 종류(둘 다 과대보정 → 밴드 늦음 → 위험).** 즉 **worst case = warm_scale 과소 AND τ 과대**가 겹치는 지점.
- (부수 예측) **균일 τ**(모든 노드 동일)는 사망시각을 일괄 시프트 → 기울기 불변 → **방향·속도는 불변, ETA 오프셋만 이동.** **노드별 변동 τ**(±)는 사망시각에 노이즈를 더해 **속도 노이즈 floor에 기여.** 둘 다 측정으로 확인.

## 2. Part A — 시뮬 τ 게이트 (지금, estimator·E3x 편향항 고정. 재적합 아닌 강건성 시험)

**2.F 게이트 기계를 그대로 확장한다.** warm_scale 미스매치 축에 **τ 축을 추가.**

### A-1. τ 센서 모델 추가
- node/network의 온도 보고 경로에 **1차 저역통과**를 삽입: `T_sensor(t+dt) = T_sensor(t) + (T_air(t) − T_sensor(t))·(dt/τ)`. 사망 판정(임계 80℃)은 **T_sensor** 기준으로. τ=0이면 기존과 **비트 동일**해야 함(세기0 회귀로 확인).
- 이 모델은 **평가 세계에만** 넣는다. E3/E3x의 편향 항은 **여전히 S1·W0·τ=0에서 도출한 값으로 고정**(τ를 안다고 가정하지 않는다 — 실물에서 모르는 게 핵심).

### A-2. τ 스윕 (물리 범위, 테스트 점수 아님)
- τ ∈ {0, 2, 5, 10} s. **이 범위는 DS18B20의 물리적 응답 근거지 결과를 보고 고른 게 아님을 docstring에 명시.**
- **균일 τ**(전 노드 동일)와 **변동 τ**(노드별 τ ~ 기준±30% 등, 제조·피복·기류 편차 모사) 두 모드 각각.

### A-3. 측정 (2.F와 같은 지표)
- τ별로 S2~S11에서 30/60/100m **커버리지 + breach_early(위험측).**
- **결합 최악:** warm_scale ×0.5(2.F 최악) **AND** τ=10s를 동시에 준 세계의 위험측. (예측: 여기가 제일 위험.)
- **방향·속도 비열화 확인:** 균일 τ에서 방향/속도가 정말 불변인지(예측 검증), 변동 τ에서 속도 노이즈가 얼마나 오르는지.

### A-4. 판정/처리 (2.F 형식)
- **(A)** E3x(현행 1.43배)가 τ까지 이미 흡수 → breach_early가 τ=10s·결합최악에서도 낮게(예 ≤10%) → 추가 조치 불요. 주장: **"warm_scale ±50% + τ ≤ __s까지 강건."**
- **(B)** τ에서 저하 → E3x를 더 팽창(E3x2 배율 산출)해 흡수 → 새 배율·폭 정직 보고. 주장: **"warm_scale ±50% + τ ≤ __s까지 강건, 구간 폭 __배."**
- **(C)** τ가 6.44초 선행을 구조적으로 넘겨 어떤 팽창으로도 위험측 지배 → **"τ 실측·보정 없이는 실물 ETA 밴드 주장 불가"** 명시. 이 경우 **τ 보정을 편향 항에 넣는 건 Part B(실측) 이후에만**(τ를 지금 시뮬 값으로 보정하면 tautology = 자기채점 함정).

**measure-first 규율:** E3x 편향항 고정(재적합 금지) · τ 범위는 물리에서 · 평가 전부 S2~S11 · 세기0(τ=0) 회귀 동일성 · pytest · 방향 나빠지면 그 사실 그대로 기록.

## 3. Part B — 실물 실측 프로토콜 (부품 도착 후. 지금은 문서로만 확정)

Part A의 τ·warm_scale **범위**를 실물 **실측 분포**로 교체하기 위한 절차. 부품 도착 즉시 이 순서로.

### B-1. τ 측정 (센서 계단응답)
- DS18B20를 상온에 두었다가 **계단 온도 입력**(항온조 급투입 또는 핫에어건 정속 노출)에 노출.
- 센서 출력이 최종값의 **63.2%(=1−1/e)** 에 도달하는 시간 = **τ**. (1차 저역통과의 정의.)
- **실사용 조건 그대로**(피복/캡슐 유무, 거치 방식) 여러 개 측정 → **τ 분포**(평균·편차). 노드 간 편차가 곧 Part A의 "변동 τ" 실측 근거.
- 추가로 **80℃ 임계 도달 지연**을 직접 스톱워치로도 기록(모델 검증용).

### B-2. warm_scale 측정 (화선 거리별 온도 감쇠)
- 통제 화염(가스 토치/알코올 트레이 등 안전 확보된 소규모)에서 **화선으로부터 거리 d별 정상상태 온도** T(d) 측정.
- `T(d) = T_amb + ΔT·exp(−d/warm_scale)` 에 적합 → **warm_scale.** 연료·습도 조건 2~3개로 **범위** 확보(실물 warm_scale이 조건 의존이라 단일값 아님).

### B-3. 실측 반영 → 게이트 재실행
- Part A의 τ·warm_scale 스윕 범위를 **B-1·B-2 실측 분포로 교체** → 게이트 재실행 → **실물 대비 밴드 주장 확정**(또는 필요한 추가 팽창 산출).
- 이때 비로소 τ 보정을 편향 항에 넣을지 판단(실측 τ 기반이므로 tautology 아님). 단 **넣더라도 warm_scale과 동일하게 미스매치 강건성 재확인.**
