# 구현 지시서 #2e-3 — 속도/ETA 추정 개선 (시간적 추적 + dT/dt 물리 역산)
### 화중생련 「불사」 / 남은 마지막 약점을, 하드웨어 없이 정면으로

> **현재 상태 정리(정직하게):** #2e-1·#2e-2·Fix A로 해결된 것은 **비화재 사망 누수(COOL 86.4%→0%)와 오탐 breakpoint 소멸**이다.
> **속도/ETA는 아직 해결되지 않았다.** S2a(바람) 29.9%, S6(9노드) 34.5%, S7(복합최악) 26%.
> 방향은 2.1°로 자랑할 수 있는 수준인데, **속도만 남아 있다.** 이 문서는 그 하나를 겨냥한다.

---

## 0. 왜 "고칠 수 있다"고 보는가 (근거 3개)

1. **역수 구조가 문제일 가능성.** 현재 속도 = `1/|∇T|`. 도착시각 평면의 기울기 크기를 **역수**로 뒤집기 때문에, |∇T|의 작은 오차가 속도에서 증폭된다. **방향(∇T/|∇T|)은 역수를 쓰지 않아서 2.1°로 멀쩡하다** — 즉 오차의 상당 부분이 "정보 부족"이 아니라 **연산 구조** 탓일 수 있다.
2. **같은 데이터로 역수를 피하는 경로가 있다.** 화선이 방향 û로 등속 이동하면, 각 노드의 축좌표 `s_i = p_i·û` 와 사망시각 `t_i` 사이에 `s_i = s_0 + v·t_i` 가 성립한다. → **`s` 를 `t` 에 회귀하면 기울기가 곧 v** (역수 없음, 나눗셈 한 번 없음).
3. **아직 안 쓰고 버리는 신호가 있다.** 지금은 온도 계열에서 **사망시각만** 뽑아 쓰고 곡선 모양은 버린다. 예열 구간의 **온도 상승률 dT/dt** 는 속도의 독립 증거다(아래 3-C에 닫힌 형태 도출).

**단, 미리 인정할 것:** 실제 산불 속도는 시간에 따라 진짜로 변한다. 단일 숫자로 요약하는 한 **환원 불가능한 하한**이 존재한다. 그래서 **Step 1(진단)에서 그 하한을 먼저 측정**하고, 하한이 관측 오차의 대부분이면 **거기서 멈춘다.**

---

## 공통 규율 (이전 단계와 동일 — 이게 우리 무기다)

1. **원 estimator를 baseline으로 보존.** 새 방식은 항상 **병행**, 항상 **나란히 비교**. 헤드라인 조용히 갈아치우기 금지.
2. **파라미터는 물리 또는 baseline(S1) 분포에서 도출.** 스트레스 시나리오 점수를 보고 스윕하는 것 = overfit = 금지.
   - 도출용 데이터와 평가용 데이터를 **분리**해서 명시(예: 도출은 S1 시드, 평가는 S2~S11).
3. **방향 비열화 증명이 통과 조건.** 속도가 좋아져도 **방향이 나빠지면 채택하지 않는다**(방향이 우리 헤드라인).
4. **S1~S11 전체 재실행 + 세기0 회귀 동일성 + pytest.**
5. **null 결과도 그대로 보고.** 개선 없으면 "속도는 보수적, 시간적 추적은 발전방향"으로 기록하고 끝낸다.
6. 실물/펌웨어 손대지 않음. **각 Step 끝나면 보고하고 멈춘다.**

## Step 1 · 진단 (측정만, estimator 불변) — **먼저, 반드시**

지금 29.9%가 **어디서 오는지 모르는 상태**다. 고치기 전에 분해한다.

**1a. 부호 있는 오차 분포.** 현재 지표는 절대/상대 오차뿐. `(v̂ − v_true)/v_true` 의 **부호 포함 분포**(평균·중앙값·분위)를 시나리오별로. → **계통 편향(bias)** 인지 **산포(variance)** 인지 판정. (편향이면 구조 문제, 산포면 노이즈 문제 — 처방이 다르다.)

**1b. 환원 불가 하한(floor) 측정.** 각 런에서 **참 화선 속도의 시간 변동**을 기록하고, "그 런을 단일 상수 속도로 요약할 때 최선의 값"이 갖는 오차를 계산. → 이게 **어떤 알고리즘도 못 넘는 하한**.
- S1/S2a/S6/S7 각각의 floor를 표로. **floor가 관측 오차의 대부분(예: 70%↑)이면 Step 2로 가지 말고 여기서 멈추고 보고.**

**1c. 오라클 절단(ablation).** 노이즈 원인별 기여도:
- (i) 사망시각 노이즈 제거(클럭 지터·보고 지연·틱 양자화 없음) → 속도 오차 얼마?
- (ii) 노드 배치 오차 제거 → 얼마?
- (iii) 둘 다 제거(순수 기하) → 남는 오차 = 모델 미스매치(곡률/시간변동) 몫.
→ 어느 항이 지배적인지로 처방이 결정된다.

**1d. 지표를 실제 용도로 재정의 — ETA 오차(초).** 우리가 파는 것은 "속도 %"가 아니라 **"불이 P 지점에 언제 닿는가"**다.
- 화선 전방 **30m / 60m / 100m** 목표점에 대해 **ETA 오차를 초 단위**로, **그리고 부호 포함**으로 측정.
- **보수성 비율**도 측정: ETA를 실제보다 **빠르게(=위험하게) 예측한 비율**. 안전 논거는 이 숫자로만 쓴다.
- 이 표는 보고서·영상에서 "ETA 4:12" 같은 **점 추정 숫자를 쓸지, 구간으로 바꿀지**를 결정하는 근거가 된다.

**Step 1 DoD:** 1a~1d CSV·표 + "오차의 주된 출처는 X" 한 줄 결론 + **계속할지/멈출지 권고.** estimator 완전 불변. DECISIONS(D-037) 기록.

## Step 2 · 후보 구현 (baseline 병행) — Step 1이 "계속" 판정일 때만

### A. 역수 제거 — 1D 직접 회귀 (`s`-vs-`t`)
- 방향 û 는 **기존 평면적합 결과 재사용**(2.1°, 이미 튼튼함 — 손대지 않는다).
- 각 채택된 사망 노드에 대해 `s_i = p_i·û` 계산 → **`s_i` 를 `t_i` 에 회귀**한 기울기 = v.
- **로버스트 회귀**(Theil–Sen 또는 Huber)로 이상치 사망시각 영향 축소. 하이퍼파라미터는 기본값 사용(스윕 금지).
- 기대: `1/|∇T|` 의 역수 증폭이 사라짐. **가장 값싸고 가장 먼저 시도할 것.**

### B. 시간적 추적 (windowed front tracking)
- 시간창 `[t_k, t_k+W]` 별로 그 구간 사망 노드들의 `s` 대표값(중앙값)을 구해 **화선 위치 궤적** `s̄(t_k)` 를 만든다.
- 속도 = 궤적의 시간 미분(이동평균 또는 1차 칼만). → **시간 가변 속도**를 얻음.
- W 는 물리에서 도출: "창 하나에 최소 3개 이상 사망이 들어오는 최소 폭"을 **S1 사망률 분포**에서 계산(테스트 점수 아님).
- 추가 산출물: **가속도(추세)** 와 **"현재 속도"**. ETA에는 평균속도보다 **현재 속도**가 맞다 → 1d의 ETA 오차로 검증.
- 노드 수가 적으면(S6 9노드) 창당 표본이 부족해 열화 가능 → **그 한계를 그대로 측정·보고.**

### C. dT/dt 물리 역산 — 독립 신호 (핵심 아이디어)
예열 구간의 온도장이 `T(d) = T_amb + ΔT·exp(−d/L)` (d = 화선까지 거리, L = warm_scale) 이고 화선이 속도 v로 접근하면 `d(t) = d₀ − v·t` 이므로

```
dT/dt = (v/L)·(T − T_amb)        ⟹        v = L · (dT/dt) / (T − T_amb)
```

- **노드 하나가 자기 온도 계열만으로 속도를 추정한다.** 평면적합·역수·이웃 불필요 → **A/B와 통계적으로 독립** → 융합 정당성 확보.
- **적용 구간:** 지수 근사가 성립하는 **예열 밴드**에서만 계산(예: T가 `T_amb+10 ~ warn_temp(60)` 사이). **사망 직전(점화 근방)은 포화·비선형이라 제외** — 이 선택은 물리 근거이며 점수 튜닝이 아님.
- **신호 출처 규율:** god-view 금지. **메시가 실제로 수신한 보고 온도 계열**에서만 계산(#2d `rep_peak` 원칙 계승).
- 노드별 v 추정치를 **중앙값**으로 집계(로버스트).

> **⚠ 반드시 정직하게 다룰 위험 — 시뮬레이터 역산(tautology) 문제.**
> 이 식은 시뮬레이터가 온도를 만들 때 쓴 형태를 그대로 뒤집는 것에 가깝다. 그러면 시뮬에서는 부당하게 잘 나오고 **실물에서는 무너진다.**
> 그래서 **아래 미스매치 시험을 통과해야만 채택**한다:
> - **L 미스매치 민감도:** estimator가 쓰는 L을 참값의 ±20/±30/±50%로 틀리게 준 상태에서 속도 오차. (실물에서 L은 연료·습도 의존 → 캘리브레이션 필요)
> - **센서 현실성:** S9 온도 지터 + **센서 응답 지연(1차 저역통과)** 을 넣은 상태에서의 성능.
> - **모델 미스매치:** 온도 감쇠를 지수가 아닌 다른 형태(예: 선형/거듭제곱)로 바꾼 변형 시나리오에서의 열화.
> - 결과가 "L을 정확히 알 때만 좋다"로 나오면 → **보고서에는 '캘리브레이션 전제 하의 발전방향'으로만 기재.** 헤드라인 금지.

### D. 융합
- A(또는 B)와 C가 독립이므로 **역분산 가중 결합**. 가중치는 **S1 baseline 잔차 분산에서 도출**(테스트 점수로 조정 금지).
- 한쪽이 표본 부족으로 무효일 때의 폴백 규칙 명시.

### E. 실패해도 건지는 결과 — **속도 구간(밴드)**
점 추정이 안 좋아져도, **검증된 신뢰구간**은 실무적으로 더 유용하고 더 정직하다.
- 잔차 통계에서 `[v_lo, v_hi]` 를 산출하고 **실제 커버리지(참값이 구간에 들어간 비율)** 를 측정. 목표는 명목 90%와 실측 커버리지의 일치.
- 그러면 보고서/영상에서 **"ETA 4~6분(90% 구간)"** 처럼 쓸 수 있다 — 점 숫자보다 방어 가능. **이건 개선 실패 시에도 남는 산출물이다.**

## Step 3 · 검증 및 완료 기준(DoD)

1. **속도 오차 비교표:** `baseline(1/|∇T|)` / `A` / `B` / `C` / `D(융합)` × `S1·S2a·S2b·S3·S4·S6(9/25)·S7` — **부호 포함**, floor(1b) 병기.
2. **ETA 오차표(초):** 30/60/100m, 부호 포함 + 위험측 예측 비율. baseline 대비 전/후.
3. **방향 비열화 증명:** 모든 시나리오에서 방향 오차 변화 없음(또는 개선). 나빠지면 **불채택**.
4. **S1~S11 전체 재실행**, fp 0% 유지, 커버리지 변화 명시, **세기0 회귀 동일성**, pytest 통과.
5. **파라미터 도출 근거 문서화** — W, 예열 밴드, 융합 가중치 각각 "무엇에서 도출했나" + 테스트 스윕 아님 명시.
6. **C의 미스매치 시험 결과**(L ±%, 센서 지연, 모델 변형) — 통과 못 하면 채택하지 않고 그 사실을 기록.
7. **밴드 커버리지 표**(2-E).
8. **권고 1개**: 무엇을 기본값으로, 어떤 트레이드오프로. 개선폭 과장 없이.
9. DECISIONS(D-037~)·PROGRESS·STRESS_REPORT(§1g 신설 + §4) 갱신.

## 정지 조건 (시간 대신 조건으로 관리)

- **Step 1에서 floor가 지배적**(관측 오차의 70%↑) → 멈춤. 기록: "속도는 물리적 하한에 근접, 보수적 사용 + 밴드 제시."
- **A가 개선 없음 + 1c에서 사망시각 노이즈가 지배적** → B/C 중 **C만** 시도(B는 표본을 더 잘게 쪼개므로 노이즈 지배 상황에서 불리).
- **C가 미스매치 시험 실패** → 채택하지 않고 발전방향 기재로 종료.
- **어느 조합도 유의한 개선 없음** → 2-E(밴드)만 채택하고 종료. **이것도 정상적인 성공적 종료다.**

## 보너스 (Step 2-C 성공 시 자동으로 열리는 것)

#2e-2에서 만들었지만 **`dtdt_gate=False` 로 잠가 둔 Fix B**(dT/dt 증거 게이트)는 "dT/dt ∝ 속도라서 속도 ≥0.8 m/s에서만 유효"라는 한계 때문에 기본값이 아니었다.
**속도 추정치가 생기면 임계를 속도로 정규화**할 수 있어 그 한계가 사라진다 → 저속 상황까지 커버하는 2차 방어선으로 승격 가능. Step 2-C가 통과하면 **이것도 같이 측정**해 볼 것(별건으로 분리 보고).
