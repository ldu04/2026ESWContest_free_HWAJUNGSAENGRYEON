# 구현지시서 #2e — 속도 수학 · 바람 융합 · 비화재 해악 재측정 (순차 검증)
### 화중생련 「불사」 / 사용자가 짚은 3가지를 순서대로, 정직하게 검증

> 배경: 리뷰 중 세 가지 타당한 문제제기가 나옴.
> ① 비화재 사망 "오염률 88%"는 **실제 해악을 과장**했을 수 있다(뜨거운 구역 비화재는 불이 실제 있는 자리라 무해할 수 있음).
> ② 속도는 방향보다 구조적으로 어렵지만 **더 나은 수학(시간적 추적·온도 상승률)**으로 개선 여지가 있다.
> ③ 바람은 확산의 주 동력·선행 지표라 **풍향/풍속을 사전(prior)으로 융합**하면 속도가 안정될 수 있다.
> → 셋 다 하드웨어 없이 시뮬로 검증 가능. **순서대로 하나씩 측정→보고→다음.**

---

## 공통 규율 (매우 중요)

- **#2e-1(측정만):** estimator·방어 로직 **불변**. 지표만 추가. 완전한 measure-first.
- **#2e-2·#2e-3(실질 개선):** estimator에 손을 대는 진짜 개선이므로, 다음을 반드시 지킨다.
  1. **원 estimator를 baseline으로 보존** — 항상 개선 전/후를 나란히.
  2. **파라미터·모델은 물리/baseline 통계에서 도출** — 테스트 점수 보고 스윕 금지(overfit 방지).
  3. **S1~S11 전체 재실행** — 방향·baseline 비열화 증명 + 세기0 회귀 유지.
  4. **정직 보고** — 개선 없거나 트레이드오프 생기면 그대로(null 결과도 가치).
- 실물/펌웨어 손대지 않음(전부 시뮬 계층). 각 단계 **끝나면 보고하고 멈춘다**(다음 단계 지시 대기).

## #2e-1 · 비화재 사망 "해악" 재측정 (찬/뜨거운 구역 분리) — 먼저

**문제의식:** 기존 지표 `nonfire_pollution_rate`(오분류율)는 "화재사망으로 분류됐나"만 세는데, **뜨거운 구역에서 죽은 비화재 노드는 그 자리에 불이 실제로 와 있어** 도착시각 평면에 대체로 맞아, 오분류돼도 추정 해악이 작을 수 있다. 반대로 **찬 구역 비화재**(불에서 먼데 배터리로 죽음)는 엉뚱한 화선을 만드는 진짜 위험이다.

**할 것 (측정만, 로직 불변):**
1. 주입한 각 비화재 사망 노드를 **사망 시점 국소 온도로 분류**: `COOL`(warn_temp 대비 뚜렷이 낮음, 예: < warn−Δ) vs `HOT`(warn 근처/이상 = 접근 중인 불에 이미 가열).
2. 각 그룹별로 측정:
   - (a) **통과율**(교차검증을 통과해 화재사망으로 확정된 비율),
   - (b) **실제 해악** = 그 그룹을 포함/제외했을 때 **방향·속도 오차 차이**,
   - (c) **공간 변위** = 추정 화선이 참 화선에서 얼마나 밀렸나(가짜 화선이 실제와 얼마나 떨어졌나).
3. **주입 개수(1/2/4/8)별로** 해악이 어떻게 스케일하는지(현실적 저비율에서 해악이 작은지 확인).

**검증 가설:** `COOL` 비화재는 (i) 통과율 낮고(온도 검증이 걸러냄) (ii) 통과 시 해악 큼(참 화선에서 먼 가짜) → **위험하지만 방어됨**. `HOT` 비화재는 (i) 통과율 높지만 (ii) 해악 작음(참 화선과 일치) → **못 막지만 대체로 무해**.

> **반증 규율(사용자 추가):** 위 가설이 틀리게 나와도 **결과 그대로 보고**한다. 특히 **HOT 해악이 크거나 COOL 통과율이 낮지 않으면 그대로 명시**한다. 원하는 결론에 맞춰 서술하지 않는다.
> **헤드라인 규율(사용자 추가):** **COOL 통과율**을 결과에서 가장 눈에 띄게 보고한다 — 이것이 "위험한 찬-구역은 방어된다"는 안전 주장의 핵심 근거이며, 높게 나오면 **방어 누수로 명시**한다.
> **현실성 맥락(사용자 추가):** 해악 곡선에 **16노드 중 8개(50%)는 적대적 스트레스이고 현실적으로는 1~2개 수준**임을 STRESS_REPORT에 명시한다.

**완료 기준(DoD):**
1. COOL vs HOT 각각 통과율·방향/속도 오차 기여·공간 변위 CSV·표.
2. 주입 개수별 해악 곡선.
3. STRESS_REPORT §4 항목5를 **정직하게 재서술**: "온도로 완전 구분은 불가하나, **위험한 찬-구역 비화재는 방어**되고, **못 막는 뜨거운-구역 비화재는 참 화선과 일치해 해악이 작다**(수치)." — 단, 측정이 이를 반증하면 반증된 대로 재서술.
4. estimator·방어 **완전 불변**(측정만). 세기0 회귀 유지. DECISIONS(D-032)·PROGRESS 갱신.

## #2e-2 · 속도 추정 개선 (시간적 추적 + 온도 상승률) — #2e-1 확인 후

**목표:** 우리 약점인 속도 오차를, 방향·baseline을 해치지 않고 더 나은 수학으로 줄인다.

**할 것 (원 estimator는 baseline 보존, 새 방식 병행):**
1. **시간적 추적(temporal tracking):** 한 시점 평면기울기(1/|∇T|) 대신, **여러 시간창에서 화선 위치를 구하고 위치 변화(이동거리/시간)로 속도**를 추정. 칼만/이동평균으로 평활.
2. **온도 상승률(dT/dt):** 노드가 죽기 전 온도 상승 속도를 **독립적 속도 신호**로 추가(현재는 사망시각만 쓰고 버림). 추적치와 융합.
3. (선택) **로버스트 회귀**로 이상치 죽은시각 영향 축소.

**완료 기준(DoD):**
1. 원 estimator vs 새 방식 **속도 오차 전/후** — 정상 + 바람/스트레스(S2a 등)에서 나란히.
2. **방향 오차 비열화 없음** 증명, S1~S11 재실행, 세기0 회귀 유지.
3. 파라미터는 물리/baseline에서 도출(테스트 스윕 금지). 개선 없으면 **null 결과 정직 보고**.
4. DECISIONS(D-033~)·PROGRESS·STRESS_REPORT 갱신.

## #2e-3 · 바람 융합 (풍향/풍속 prior) — #2e-2 확인 후

**목표:** 바람을 사전(prior)으로 융합해 특히 **바람 조건에서** 속도/방향을 안정화.

**할 것:**
1. 시뮬에 **바람 필드**(방향·속도) 추가하되 **현실적 노이즈**(관측소↔국소 미기후 편차)를 넣어 "완벽한 바람"으로 치팅 금지.
2. estimator가 바람을 **예측/사전**으로, 죽은-패턴을 **실측**으로 놓고 **칼만식 융합**(가중 결합). (물리 사전: 간단 Rothermel식 rate-of-spread 또는 단순 downwind 사전)
3. 바람-스트레스 시나리오(S2a)에서 **융합 전/후** 속도·방향 오차 비교.

**완료 기준(DoD):**
1. 융합 전/후 속도·방향 오차(특히 바람 조건).
2. 바람 노이즈를 넣은 상태의 정직한 이득(관측소 바람은 오라클 아님을 명시).
3. baseline 비열화·회귀 유지. 개선/트레이드오프 정직 보고.
4. DECISIONS·PROGRESS·STRESS_REPORT 갱신.
