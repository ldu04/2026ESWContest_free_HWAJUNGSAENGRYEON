## 0. 아키텍처 분담 (실물)

```
[ESP32 노드 ×16 (C/C++)]  ── WiFi 메시 ──▶  [루트 노드 ESP32]
```

- **대시보드:** 지시서 #3의 자체완결 플레이어에 **실시간 스냅샷**을 먹인다(같은 Snapshot 스키마).

## 1. 노드 펌웨어 (C/C++)

- **개발환경:** Arduino-ESP32 (초보 친화). 라이브러리:
  - **메시:** `painlessMesh` (자동 조직·자동 재라우팅 = 자가치유 기반). ※ESP-MESH(esp-idf)보다 API 쉬움 → painlessMesh 권장.
  - **온도:** `OneWire` + `DallasTemperature` (DS18B20).
  - **LED:** `Adafruit_NeoPixel` 또는 `FastLED` (WS2812).
- **노드 모듈(시뮬 대응):**
  1. **하트비트/센싱:** 주기적으로 (id, 좌표, 온도, t) 브로드캐스트.
  2. **Last-Gasp:** `temp ≥ temp_threshold(80℃)` → 임종 패킷 1회 송신 후 송신 중단.
  3. **교차검증/자가치유:** 이웃의 하트비트 침묵(K회 누락) + 온도 정황 → 사망 확정 이벤트 생성. 메시 라우팅은 painlessMesh가 자동 우회, 그 위에 **죽음=1급 이벤트** 계층을 얹어 루트로 전파.
  4. **LED:** ALIVE=초록 / DYING·DEAD=빨강.
  5. **노드 좌표:** 각 노드에 격자 좌표(x,y)를 플래시 시 주입(노드별 `#define NODE_ID/NODE_X/NODE_Y` 또는 EEPROM). → **16개 보드를 ID만 바꿔 굽는 절차 문서화.**
- **파라미터:** 시뮬 config 값 계승(temp_threshold·K_confirm·silence_timeout 등). DECISIONS에 매핑 기록.

## 2. 게이트웨이 (라즈베리파이, Python)

- **루트 노드 ESP32 ↔ 파이:** USB 시리얼로 연결. 루트가 수신한 모든 패킷을 **JSON 라인**으로 파이에 전달.
- **파이 프로그램:** 시리얼 읽기 → 사망 이벤트 축적 → **시뮬 `estimator.py` 재사용**(도착시각→방향·속도·ETA) → Snapshot(dict) 생성 → 웹 대시보드 서빙.
- **재사용 원칙:** estimator·verification 로직은 시뮬 코드를 **최대한 그대로**. 실물 차이(좌표 단위·시간 동기)만 어댑터로 흡수.

---

## 3. Phase 계획 (Phase A는 지금 착수)

- **Phase A — 하드웨어 없이 지금 (부품 대기 중):**
  - 노드 펌웨어 **코드 구조·컴파일** 작성(Arduino-ESP32). **Wokwi 시뮬레이터**로 ESP32+DS18B20 기본 로직(센싱·하트비트·Last-Gasp·LED) 검증.
  - 게이트웨이 Python: 시뮬 estimator 재사용 + **가짜 시리얼(모의 JSON 스트림)**으로 대시보드까지 end-to-end 연결 테스트.
  - → 부품 도착 시 곧바로 실물 플래시만 하면 되게 준비.
- **Phase B — 부품 도착 후:** 실물 2~3노드로 메시 형성·하트비트·Last-Gasp를 **실제 RF에서** 검증 → 16노드로 확장.
- **Phase C — 통합:** 게이트웨이 estimator+대시보드 실시간 + 데모 트리거(열원) + 정량지표 측정.

---

## 4. 실물 주의 (앞서 합의)
- 실제 WiFi 메시는 지저분함(패킷 유실·재연결) → painlessMesh 자동복구 + 교차검증으로 흡수.
- MT3608는 **5V로 조정 후** 배터리 노드에 연결. WS2812 데이터 3.3V는 LED 1개라 보통 OK(문제 시 레벨시프트).
- 16보드 플래시: ID/좌표만 바꿔 순차 굽기(절차 스크립트화).
- 재라우팅 실지연은 **여기서 처음 실측**(시뮬 100ms는 틱값이었음).
