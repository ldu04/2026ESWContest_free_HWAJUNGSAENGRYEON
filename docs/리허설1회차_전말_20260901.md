## 2. 원인 ① — n01 온도센서 배선이 바뀌어 있었다

    잘못된 배선            맞는 배선
      DAT → 3.3V            DAT → GPIO4
      VCC → GPIO4           VCC → 3.3V
      GND → GND             GND → GND   (이건 맞았다)

**한 가지가 세 증상을 전부 설명한다.**
- **안 죽었다**: 1-Wire 통신선이 데이터 핀에 연결돼 있지 않아 읽기가 항상 실패했다.
- **LED 가 안 빨개졌다**: 상태가 ALIVE 에서 바뀌지 않았으니 LED 도 초록 그대로다.
- **새 센서가 탔다**: 데이터 핀이 3.3V 에 직결돼 내부 보호소자로 전류가 계속 흘렀다.

### 왜 화면으로는 못 봤나 — 펌웨어가 고장을 은폐한다
```c
// node.ino:54-55
float curTemp = 25.0f;
float lastTemp = 25.0f;
// node.ino:79-80
float t = sensors.getTempCByIndex(0);
return (t <= -100.0f) ? lastTemp : t;   // 읽기 실패 시 직전값 유지
```
센서가 죽으면 **정확히 25.00℃ 로 영구 고정**된다. 실온과 값이 같아서
**기동 점검으로는 절대 구별되지 않는다.** 구별하는 유일한 방법은 열을 넣어 보는 것이다.

실측 증거: 손으로 15초 잡는 동안 n01 은 **37 표본 전부 25.00, 변화 0.00℃**.
같은 시각 정상인 n07 은 25.50~26.00 으로 흔들렸다.

## 3. 원인 ② — 브리지 USB 케이블 불량 (시리얼 재생 고장)

브리지 포트에서 **직전 줄의 꼬리가 무한 반복**됐다.

    b'"fake":0,"nt":867.843125}'  × 1918회 / 20초   (nt 가 얼어붙어 있다)
    b'5b4'                        × 5289회          (부팅 메시지 `entry 0x400805b4` 의 꼬리)

**펌웨어가 아니라는 증명**: 6초에 **445 kB** 가 나왔다. 115200 baud 의 물리 한계는
6초에 69 kB 다. 전송이 아니라 재생이다. 반복되는 내용이 「직전 조각의 꼬리」라는 점도
펌웨어가 만들 수 있는 출력이 아니다.

| 조치 | 결과 |
|---|---|
| 포트 재개방 / `stty` / 드라이버 재바인딩 / USB 재삽입 / 파이 재부팅 | 전부 실패(또는 20초만 지속) |
| 브리지를 노트북으로 이전 | 일시 개선 — **그러나 재발**(리셋 없이 60초에 깨진 줄 16,270) |
| **USB 케이블 교체** | **★ 해결 — 60초에 깨진 줄 0** |

### 이것이 1회차를 어떻게 망쳤나
게이트웨이는 23분간 **유효 프레임 0건**이었는데 **아무 경고도 내지 않았다.**
하트비트는 반복되니 손실을 견디지만 **사망 신호는 단발**이라 유실되면 끝이다.
