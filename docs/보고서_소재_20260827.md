> 비대칭도 = 각 이웃까지의 단위벡터 합의 크기 / 이웃 수. 0 = 사방 대칭, 1 = 한쪽 완전 치우침.

### 상관

| 인자 | Pearson | Spearman |
|---|---|---|
| 이웃 수 | −0.530 | −0.594 |
| 비대칭도 | +0.530 | +0.576 |
| 1/r (곡률) | +0.828 | +0.500 |
| **비대칭도 × 1/r** | **+0.867** | **+0.903** |

**곱이 모든 단일 인자를 이긴다.** 특히 순위상관에서 격차가 크다(0.903 vs 최대 0.576).
→ **오차는 "이웃이 한쪽에만 있다"와 "곡률이 급하다"가 동시에 성립할 때만 커진다.**

### 사용자 예시 검증 — 4건 전부 맞음

| 예상 | 실제 |
|---|---|
| 이웃 8개는 r과 무관하게 1° 내외 | id 5·6·9·10 = **1.17 / 0.39 / 0.77 / 0.33°** (id 5만 1.17로 1° 살짝 초과) |
| id 15는 이웃 3개지만 r=0.917로 곡률 약함 → 작은 오차 | **0.96°** |
| id 0은 이웃 3개 + r=0.112(곡률 최대) | **33.20°** |
| id 2는 이웃 5개지만 변에 치우침 + r=0.396 | **15.12°** |

### ★ 정직하게 남길 단서 — 이 격자에서는 두 인자를 분리할 수 없다

이웃 수와 비대칭도가 **일대일 대응**한다(3→0.805, 5→0.483, 8→0.000).
정규 격자라 모서리·변·내부가 이웃 수와 기하 대칭성을 동시에 결정하기 때문이다.
따라서 **"이웃이 적어서"와 "한쪽으로 치우쳐서"를 이 데이터로는 구분할 수 없다.**
곱 모형이 잘 맞는다는 것은 확인했지만, 두 인자의 개별 기여를 주장하려면
불규칙 배치(placement jitter) 조건이 따로 필요하다.

> **쓸 수 있는 서술(구조):**
> "가장자리 노드의 오차는 '가장자리라서'가 아니다. **이웃이 한쪽에만 있고(비대칭) 곡률이 급한(작은 r)
> 두 조건이 겹칠 때만** 커진다. 실제로 모서리 노드 id 15는 이웃이 3개뿐이지만 점화점에서 멀어
> 곡률이 완만해 0.96°다. 반대로 내부 노드는 곡률과 무관하게 1° 내외를 유지한다.
> 곱 지표(비대칭도 × 곡률)가 순위상관 0.903으로 단일 인자(최대 0.576)를 크게 앞선다."
>
> → 대시보드에서 노드별 신뢰도를 이 지표로 표시할 근거가 된다.

| LED | WS2812 1픽셀, 저휘도 | 펌웨어가 `Color(0,60,0)` 수준으로만 구동 |
| 전압 | 5 V USB 급전 | 데모 조건 |

### 항목별 (ESP32-WROOM-32D 데이터시트 · 부품 데이터시트)

| 항목 | 전류 | 비고 |
|---|---|---|
| ESP32 WiFi TX 피크 | 180 ~ 240 mA | 802.11n, 순간 |
| ESP32 modem-active 평균 | **80 ~ 120 mA** | 지배 항목 |
| DS18B20 변환 중 | 1.0 ~ 1.5 mA | 듀티 ~94 % → 평균 약 1.4 mA |
| DS18B20 대기 | 1 µA | 무시 가능 |
| WS2812 1픽셀 저휘도 | 5 ~ 10 mA | 정지 전류 약 1 mA 포함 |

```
노드 1개 평균  ≈  90 ~ 130 mA @ 5 V   (0.45 ~ 0.65 W)
순간 피크      ≈  250 mA @ 5 V
16노드 합계    ≈  1.4 ~ 2.1 A @ 5 V   (7 ~ 10 W)
```

### 배터리 용량 산정 예시

18650 단일 셀 2,500 mAh (3.7 V) + MT3608 승압(효율 85 % 가정):
```
5 V 환산 유효 용량 ≈ 2500 × 3.7 / 5 × 0.85 ≈ 1,570 mAh
운용 시간 ≈ 1,570 / 110 ≈ 14 시간
```

### ★ A1 서술과 충돌하는 점 — 반드시 반영할 것

A1 초안은 *"노드는 대부분의 시간을 대기 상태로 보내고, 화선 통과 시에만 고빈도 샘플링한다"* 로
전력 절감을 설명한다. **그런데 이 구조에서는 그 절감이 거의 없다.**

```
샘플링을 10 Hz -> 1 Hz 로 낮춰도 줄어드는 것은 DS18B20 몫 약 1.4 mA 뿐이다.
전류의 90 % 이상은 무선이고, painlessMesh 는 AP+STA 상시라 끌 수 없다.
```

절감은 **무선 듀티**에서만 나온다. 실제로 하려면 painlessMesh 를 버리고
스케줄 기반 깨어남(예: ESP-NOW + 동기 슬립)으로 바꿔야 하며, 그러면 자가치유 라우팅이
사라진다. **트레이드오프를 밝히는 편이 낫다** — "상시 메시를 택했고, 그 대가가 전력이다".
