## ★ n04 (NODE_ID 3) — LED 데이터 핀이 **GPIO18** 이다

**n04 만 다르다. 다른 15대는 GPIO5 다.**

    굽기 명령:  flash_node.ps1 -Index 3 -Port <포트> -ExtraFlags "-DPIN_NEOPIXEL=18"

**★ 플래그 없이 다시 구우면 LED 가 또 안 켜진다.** GPIO5 가 불량이라 18 로 옮겼다
(사유: `docs/DECISIONS.md` D-072). 부팅 배너의 `led_pin` 필드로 실제 값을 확인할 수 있다:

    {"type":"MESHID","id":3,...,"led_pin":18}

배선도 GPIO5 가 아니라 **GPIO18 에 DIN 이 물려 있다.** 보드를 교체하면 배선도 같이 옮겨야 한다.


## ★ n01 (NODE_ID 0) — **보드를 교체했다** (2026-08-31)

**옛 보드는 5V–GND 단락으로 폐기했다.** 보조배터리에 물리는 순간 보호회로가 걸려
출력이 통째로 끊겼고, WS2812·DS18B20 을 전부 떼도 재현됐다.

| | 옛 보드 (폐기) | **새 보드 (현행)** |
|---|---|---|
| MAC | `20:50:0d:d0:80:6c` | **`58:2a:bd:7d:46:a4`** |
| mid | 231768173 | **3179103909** |

**★ 옛 MAC·mid 로 보드를 찾지 말 것.** `results/hw/burn_map.csv` 의 옛 행은
`REPLACED_BOARD_FAULT` 로 표시해 뒀다.

### 어떻게 좁혔나 (다음에 같은 증상이 나오면 이 순서로)

1. **점퍼 교차 교체** — n01 의 LED 점퍼를 n02 에 꽂으니 n02 는 켜졌다 → **점퍼는 정상**
2. **WS2812 분리** → 배터리 오류 여전 → LED 모듈 아님
3. **DS18B20 까지 분리(보드 단독)** → **여전히 오류** → **보드 확정**
4. 보드 교체 후 정상

**핵심:** 「LED 안 켜짐」과 「배터리 오류」가 **한 원인**이었다.
데이터 핀 불량(n04 의 GPIO5)은 배터리 오류를 **설명하지 못한다** — 그게 두 고장을 가른 기준이다.
