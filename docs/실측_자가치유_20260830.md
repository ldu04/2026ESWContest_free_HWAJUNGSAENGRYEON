### ★ 부수 발견 — 합류 직후 첫 HB 의 `nt` 는 메시 시각이 아니다

    30.1s  id=3  "ms":3000  "nt":3.000113      <- 자기 부팅시간. 메시 동기 전
    31.1s  id=3  "ms":4000  "nt":782.857631    <- 메시 시각으로 동기됨

메시 시각 동기는 합류 후 **약 1초** 안에 끝난다. 그러나 그 1초 동안 노드가 내보내는 `nt` 는
**메시 공통 시각이 아니라 자기 부팅 경과시간**이다.
제약③(사망시각은 죽는 노드 자신이 찍은 `nt` 여야 한다)에 걸리는 구멍이다 —
합류 직후 1초 안에 죽은 노드는 `nt≈3` 같은 값을 사망시각으로 보고하게 되고,
추정기는 그걸 정상값으로 받아 도달시간장 T(x,y) 를 망가뜨린다.
데모에서 일어날 확률은 낮지만 **침묵하는 실패**에 해당하므로 게이트웨이에서 걸러야 한다.
→ 조치는 `docs/침묵실패_사전점검.md` 및 fw_adapter 점검 항목으로 넘긴다.

## (d) 직전에 잡은 정적 결함 — 사망확정이 구조적으로 불가능했다

`firmware/node/config.h` 의 `WARN_TEMP_C` 가 **60.0f 고정**이었다.

- 데모용으로 `-DTEMP_THRESHOLD_C=40.0f` 를 주입해 굽는다 → 노드는 40℃에서 DYING → 300ms → DEAD.
- DEAD 가 되면 송신을 끊는다 → **이웃이 관측할 수 있는 온도의 상한이 40℃ 근처**다.
- 그런데 사망 투표 조건(`node.ino` 교차검증)은 `n.peakTemp >= WARN_TEMP_C` = 60℃.
- → 투표가 영원히 안 나오고 `K_CONFIRM`(3)도 영원히 안 찬다 → **DC 미발신**.
- 게이트웨이가 소비하는 유일한 타입이 DC 이므로, 화면에는 **아무 징후도 안 뜬다.**

전형적인 침묵 실패다. (d) 를 그냥 돌렸으면 "사망 감지가 안 된다" 로만 보이고 원인은 안 보였을 것이다.
`flash_node.ps1` 은 `TEMP_THRESHOLD_C` 만 주입하고 `WARN_TEMP_C` 는 건드리지 않으므로,
임계값을 낮출 때마다 이 불변식이 조용히 깨진다.

### 조치 — 값을 유도하고, 컴파일 때 강제한다

    #ifndef WARN_TEMP_C
    #define WARN_TEMP_C  (TEMP_THRESHOLD_C * 0.75f)
    #endif
    static_assert(WARN_TEMP_C < TEMP_THRESHOLD_C, "...");

비율 0.75 는 원설계(60/80)를 그대로 옮긴 것이다. 새 상수를 만들지 않았다.
기본값 80.0f 에서는 0.75×80 = 60.0f 로 **종전과 완전히 같다** — 기존 설계값은 안 바뀐다.
임계값 40℃ 에서는 WARN = 30℃ 가 된다. 실내 24~27℃ 보다 위이고, 투표에는 `silent`(3초 무응답)가
반드시 함께 필요하므로 살아있는 노드가 오검출되지 않는다.

### (d) 를 이 상태로도 할 수 있다 — 단, 죽일 노드는 **반드시 id 2** 여야 한다

`WARN` 수정이 없는 노드는 **관측자로서 투표를 못 한다**. 4노드에서 한 대가 죽으면 생존 관측자는 3대뿐이고
`K_CONFIRM`=3 이므로 **3대 전원이 투표해야** DC 가 나온다.
→ id 2 가 관측자 쪽에 있으면 어떤 노드를 죽여도 DC 가 안 나온다.
→ id 2 를 **희생 노드**로 쓰면 관측자는 99·1·3 (전부 수정본) 이므로 정확히 3표가 모인다.

### 물리 식별 방법 (COM 포트 없이)

브리지 HB 스트림에 각 노드의 `temp` 가 실려 온다. 사용자가 센서 하나를 손으로 감싸면
**어느 id 의 온도가 오르는지로 보드를 특정**할 수 있다. 손 온도(약 34~36℃)는 임계 40℃ 미만이라
식별 중에 사망하지 않는다.
