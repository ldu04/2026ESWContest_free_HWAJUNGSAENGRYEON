## (2) ★ 사람이 정해야 할 것

### ★★★ 결정 1 — 임종신호를 어떻게 도달시킬 것인가 (리허설 가능 여부를 정한다)

**지금 상태로 리허설을 돌리면 노드는 죽는데 산출물에 안 남는다.** 작품의 핵심 주장이
그대로 안 찍힌다. 촬영 20분을 날리는 정도의 문제가 아니다.

| | 무엇 | 도달률(계산) | 비용 |
|---|---|---|---|
| **(가)** | `config.h` `HEARTBEAT_MS` **1000 → 5000** | 유실 91.3% → **56.7%** | 한 줄 + **17대 재굽기** |
| **(나)** | `sendLastGasp()` 를 **1초 간격 5회** | (가) 없이는 63.6% 유실 — 부족 | 몇 줄 + 재굽기 |
| **(다) = (가)+(나)** | 둘 다 | **유실 5.8%** ← 목표(7%) 달성 | 위와 같음 |
| **(가′)+(나)** | `HEARTBEAT_MS` **10000** + LG 3회 | **유실 0.2%** | 위와 같음 |
| (라) | 브리지 loop() 가 왜 0.5초인지 계측 | 근본 해결. 처리량 자체가 올라간다 | 시간 미확정 |

**목표가 왜 7%인가**: 합성 스윕에서 **유실 7%가 「방향오차 중앙값 1° 미만」의 경계**다
(0.05 → 0.42° / 0.08 → 1.07°). 덱의 「< 1°」 주장을 지키려면 여기까지 와야 한다.

**지금 그대로 돌리면**: 유실 0.93 에서 **800회 중 76회(9.5%)만 추정이 성립**하고,
성립해도 방향오차 **중앙값 18.85°** 다. 열 번 중 아홉 번은 **방향이 아예 안 나온다.**
→ 근거·표: `docs/n07_사망시험_판정_20260901.md` 「그래서 얼마나 나쁜가」

- **내 권고는 (다)** 다. 여유를 보려면 (가′). `HEARTBEAT_MS` 는 헌장 §1 동결값
  (80℃·20cm·4×4)에 **없고** D-069 사망 시각표와도 **무관**하다.
- ★ **같이 고쳐야 하는 것**: `SILENCE_TIMEOUT_MS(3000)` 는 하트비트 3회분을 전제한다.
  5초로 바꾸면 **살아 있는 노드를 죽었다고 투표한다.** 최소 `3 × HEARTBEAT_MS` 유지.
- ★ **구현 주의**: 반복 임종신호는 **첫 번째와 같은 `nt`** 를 실어야 한다.
  매번 다시 각인하면 3번째 사본이 도착했을 때 사망 시각이 그만큼 늦게 기록된다.
- **굽기는 사람이 한다**(강령 §3). 나는 제안까지만 한다.

### ★★ 결정 2 — 게이트웨이가 포트를 열 때 브리지를 리셋하는 문제

`serial_source.py` 가 `serial.Serial(dev, baud)` 로 연다 → **DTR/RTS 가 걸려 브리지가 재부팅**된다.
브리지는 루트이므로 **메시 시각이 0 으로 되돌아간다.** 01:12 회차가 스스로
「시각 역행 SUSPECT_NOT_WRAP · 이 회차를 그대로 쓰지 말 것」이라고 경고한 것이 이것이다.

- **기본 동작은 바꾸지 않았다.** 「런 전 전원 재인가」 절차와 얽혀 있어 사람이 정할 일이다.
- `--no-port-reset` 플래그만 추가해 두었다.
- **판단 질문**: 런 시작 절차를 「전원 재인가 → 3분 안정화 → 게이트웨이 기동」으로 두면
  게이트웨이 기동이 또 리셋을 낸다. **게이트웨이를 먼저 띄우고 안정화를 기다리는** 순서가 맞다.

### ★ 결정 3 — `dashboard/data.js` 24.5 MB 를 커밋할 것인가

지금 작업트리에 있는 24.5 MB 짜리는 **중단·시각오염된 01:12 회차의 산출물**이다.
커밋하지 않았다. 히스토리에 들어가면 되돌리는 데 filter-repo 가 필요하다(전에 그 비용을 치렀다).
**성공한 회차의 것으로 교체해서 커밋하는 편이 낫다.**

## 부록 B — 내가 밤새 틀렸던 것 (기록으로 남긴다)

| 내가 한 말 | 실제 |
|---|---|
| 「블루스크린이 났다」 (WER 로그를 보고) | **아니다.** 부팅 시각이 8/16 그대로고 미니덤프가 없다. 2024년 덤프의 재보고였다 |
| 「하트비트 도착률 34.4%」 | **5배 부풀렸다.** 하트비트는 5초가 아니라 **1초** 주기다(`config.h:88`). 바른 값은 **5~9%** |
| 「브리지 재생 고장이 지금도 진행 중」 | **아니다.** 반복 조각은 **첫 60초에만** 7,914회 나오고 그 뒤 16분간 0건이다. 포트 배수였다 |
| 「감시견 2종이 안 울린다」(첫 시험) | 그 시험이 틀렸다. 가짜 포트가 즉시 반환해 **벽시계가 안 흘렀다.** 지연을 넣자 발동했다 — **그러고 나서 진짜 결함(`--fw` 무력)이 드러났다** |
| 「DV 가 0이니 브리지 수신은 정상」 | 성립하지 않는다. 투표는 `silent` **AND** `hot` 조건이라 실온 소크에선 0건이 정상이다 |

**교훈**: 세 번 다 **계측 없이 앞선 결론**이었고, 세 번 다 **다음 계측이 뒤집었다.**
강령 §5(「되돌리기 어려운 판단은 계측 먼저」)가 값을 했다.
