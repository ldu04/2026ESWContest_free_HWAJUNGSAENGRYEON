체크리스트의 근거는 **「한글 저장소명은 GitHub 이 URL 로 옮기면서 깨진다(실제로 확인했다)」** 이다.
GitHub 저장소 이름은 ASCII 영숫자와 `-` `_` `.` 만 허용하고 나머지는 치환된다.

**그러면 요강의 「규격 고정」을 우리가 임의로 바꾼 것이 된다.** 이건 사람이 정할 문제다.

| 안 | 내용 | 위험 |
|---|---|---|
| **A** | 로마자 `2026ESWContest_free_Hwajungsaengnyeon` 로 만들고, 구글폼에는 **URL** 을 낸다 | 이름이 규격과 다르다. 다만 요강이 실제로 요구하는 것은 **URL 제출**이다(§1 표 「구글폼에 URL 입력」) |
| **B** | 한글로 만들어 GitHub 이 치환한 결과를 그대로 쓴다 | 이름이 `2026ESWContest_free_----` 같은 꼴이 될 수 있다. 더 나빠 보인다 |
| **C** | 주최 측에 문의 | 가장 안전하지만 **마감이 9/3** 이다. 답이 늦으면 못 기다린다 |

> **내 권고: A.** 다만 **덱 개요표와 구글폼에 URL 을 그대로 넣어** 이름 불일치가
> 문제되지 않게 한다. **이건 권고이지 결정이 아니다.**
> ★ `docs/덱_개요표_신설안_20260901.md` 의 링크 칸도 A 를 전제로 써 두었다 — 바뀌면 같이 고칠 것.

### (a) 커밋 author 이메일 — **여전히 미해결이고, 생각보다 넓다**

- **전 커밋의 author 가 같은 주소 하나**다(`git log --format=%ae | sort -u` → 1개).
- ★ **그리고 문서 본문에도 있었다.** 4줄(`아침보고서_20260831.md` · `야간작업_20260831.md` ·

- **그러나 히스토리에는 그대로 남아 있다.** 체크리스트의 안 B(`filter-repo --mailmap`)는
  **author 필드만** 바꾼다 — **본문 텍스트는 `--replace-text` 를 따로 걸어야 지워진다.**
  이 점이 기존 계획에 빠져 있었다.

| 안 | 내용 | 비용 | 되돌릴 수 있나 |
|---|---|---|---|
| A | 그대로 간다 (대다수 오픈소스가 이렇게 한다) | 0 | 공개 후 불가 |
| **B′** | `filter-repo --mailmap` **+ `--replace-text`**(본문까지) | 15분. **push 전인 지금이 가장 싸다** | 백업 필요 |
| C | 나중에 | 강제 푸시 + 포크·캐시에 잔존 | 사실상 불가 |

> **push 전에 정해야 한다.** 강령 §2: filter-repo 는 히스토리를 재작성하므로 **백업 먼저**.

# 4. 실행 순서 — **사람이 직접**

```
1) 백업          git bundle create ../failsafe-mesh-backup-$(date +%Y%m%d).bundle --all
2) 이름 결정     §1 의 A / B / C
3) 이메일 결정   §2(a) 의 A / B′ / C     ← B′ 면 여기서 filter-repo (백업 후)
4) 저장소 생성   gh repo create <이름> --public --source=. --remote=origin
   ★ 만들기 전에 지울 수 있는지 확인한다 — 토큰에 delete_repo 스코프가 있는가?
     (2026-08-30 에 못 지워서 남긴 저장소가 있다)
5) push          git push -u origin master
6) 덱 1장 개요표의 소스코드 링크 칸에 URL 삽입
```

> **4번 전에 반드시**: `gh auth status` 로 스코프를 확인한다.
> 「만들 권한과 지울 권한은 다르다」 — 강령 §3 이 이 실패에서 나왔다.
