## 왜 바꿨나 — 브라운아웃

버스 파워(노트북 USB)만으로 4대를 돌렸을 때:

```
STARTUP: init(): 1
E BOD: Brownout detector was triggered
rst:0x3 (SW_RESET)
```
`mesh.init()` 이 WiFi 를 켜는 순간 전압이 무너져 **0.8 초마다 무한 재부팅**했다.
증상이 소프트웨어처럼 보여(패킷이 안 옴) 버퍼·펌웨어 버전을 먼저 의심했고, **둘 다 오진이었다.**
`esp_reset_reason()` 배너가 `BROWNOUT` 을 찍어 준 것이 원인을 갈랐다.

외부 급전 후: **20초 관찰 재부팅 0회**, 이후 4대 안정.

## ★ 16노드 여유 — 최악의 경우 부족하다

| 항목 | 값 | 근거 |
|---|---|---|
| 노드 1개 평균 | 90 ~ 130 mA | ESP32 modem-active 80~120 + DS18B20 1.4 + WS2812 5~10 |
| 노드 1개 순간 피크 | ~240 mA | WiFi TX 802.11n |
| **16노드 평균** | **1.4 ~ 2.1 A** | 3 A 안 ✅ |
| **16노드 최악 동시 피크** | **약 3.8 A** | 16 × 240 mA. **3 A 초과** ⚠ |

동시 피크가 실제로 겹칠 확률은 낮다(TX 는 짧고 노드마다 시점이 다르다). 그러나
**painlessMesh 는 주기적으로 전 노드가 동시에 동기·라우팅 패킷을 주고받는 구간이 있어**
겹침이 구조적으로 가능하다.

## D1 리허설 필수 확인 — 12분 전 구간 브라운아웃 0건

```powershell
# 리허설 전체를 캡처하고 BOD/재부팅을 센다
.\mesh_watch.ps1 -Port <브리지> -Seconds 760 -Label D1_rehearsal
```

판정 기준:
```
[ ] BOD(Brownout) = 0 건
[ ] rst:0x       = 0 회
[ ] n_peers      = 15 유지 (브리지 제외)
```

**한 건이라도 나오면 급전을 나눈다.** 선택지:
1. 허브 2대로 분리 — 8노드씩, 각각 별도 PD 충전기
2. 5 V 3 A 이상 출력 허브로 교체 (5 V 4~5 A 급)
3. WS2812 밝기를 더 낮춘다 (16 × 5~10 mA = 80~160 mA 절감. 효과 작음)

**1번이 가장 확실하다.** 브리지는 노트북 데이터 포트에 두므로 노드 15대만 나누면 된다.

> 재부팅은 **조용히 틀리는 종류**다 — 노드가 되살아나면 사망이 취소된 것처럼 보이고,
> 로그만 보면 사망 판정 오류로 오인된다. 그래서 `esp_reset_reason()` 배너와
> `mesh_watch.ps1` 의 재부팅 카운트를 리허설 판정에 넣는다.

노드 자기 시각(`ms`)이 급락한 것으로 교차확인된다 — 예: id 99 `430001 → 782`, id 2 `188208 → 3763`.

### 같은 급전에서 04:16 에는 90초 무결이었다

`mesh_baseline_pd65_20260830_024918.log` — 4대 전부 90초 연속, BOD 0건.
급전(HONOR 65W PD, 5V 3A)은 그 사이 바뀌지 않았다. **부하 조건이 아니라 접촉 조건이 바뀌었다.**

### 시각 상관 — 사용자가 보드를 손으로 잡기 시작한 시점부터 나온다

BOD 최초 발생(115.6s)은 사용자가 "센서를 꽉 잡아달라"는 요청을 받고 보드를 쥔 직후다.
보드를 손으로 쥐면 USB 케이블이 당겨져 허브 접점이 순간적으로 끊기고, 그때 전압이 무너진다.
04:16 무결 구간에서는 아무도 보드를 만지지 않았다.

### 이 발견이 데모에 갖는 뜻

- **원인은 충전기 용량이 아니라 기구적 고정과 케이블 스트레인 릴리프다.**
  16노드로 늘리기 전에 먼저 이걸 잡아야 한다. 용량만 키워도 접점이 흔들리면 똑같이 무너진다.
- 촬영 중 노드를 손으로 만지는 연출(가열 등)은 **그 자체가 브라운아웃 유발 조건**이다.
  가열은 보드를 쥐지 않고 하는 방식(열원을 센서에 접근)으로 바꿔야 한다.
- D1 리허설의 "12분 전 구간 BOD 0건" 확인 항목은 **보드를 만지는 동작까지 포함해서** 해야 한다.
  만지지 않고 12분을 통과하는 것은 이 실패를 못 잡는다.

### 조치 (16노드 배치 때 같이 한다)

1. **케이블 스트레인 릴리프 — 센서에서 6~8cm 지점에 테이프를 다리처럼 걸쳐 선을 가두되 누르지 않는다.**
   테이프로 선을 바닥에 눌러 붙이면 당길 때 힘이 접점이 아니라 피복에 걸려 단선을 만든다.
   다리 형태로 걸치면 선이 테이프 안에서 움직일 여유를 갖고, 당김은 테이프가 받는다.
2. 고정 후 같은 조건(보드를 손으로 쥐고 흔들기 포함)에서 BOD 0건 재확인
3. (d) 사망 시험은 별도로 하지 않는다 — **t80 교정 3발에 합친다.**
   열풍기로 실제 임계까지 올리는 것이 진짜 사망 조건이고, 손으로 쥐는 시험은
   브라운아웃을 유발할 뿐 아니라 데모 조건과도 다르다.
   t80 측정 중 `death_watch.ps1 -Mode death` 를 같이 돌려 사망 전파 시각을 기록한다.
