# 침묵 실패 사전 점검 — 남은 고위험 4단계

> 2026-08-30. **사고가 난 뒤에 규칙을 추가하는 걸 이번만 멈추고 미리 훑는다.**
> 대상은 되돌리기 비싼 단계만. 새 기능은 만들지 않는다 — **이미 있는 출력에 한 줄 더** 수준으로만.

오늘까지 겪은 침묵 실패는 전부 같은 모양이었다:
**시스템은 멀쩡히 돌고, 오류도 안 나고, 다만 틀린 값을 낸다.**

---

## 1. 16보드 굽기

**조용히 틀릴 수 있는 것**
- COM 번호로 대상을 정하다 **다른 보드를 굽는다** → NODE_ID 중복/누락 → 좌표가 어긋나 방향이 통째로 돌아간다
  *(2026-08-30 실제로 발생. 브리지가 두 대가 됐다)*
- 임시 임계 40 ℃ 를 되돌리지 않고 굽는다 → 데모에서 손만 대도 죽는다
- 브리지 번호만 바꾸고 `NODE_IS_ROOT` 를 안 고친다 → 시리얼 중계가 통째로 멈춘다

**알아챌 수단 — 이미 있다** ✅
`flash_node.ps1` 이 배너를 읽어 4가지를 대조하고 `build_log.csv` 에 남긴다:
`index` · `is_root` · `death_threshold_c(80 아니면 FAIL)` · **`-ExpectMid`(mid 불일치면 굽지 않고 FAIL)**

**추가할 것 — 굽기 끝난 뒤 대장 1회 검산** (스크립트 아님, 명령 한 줄)
```bash
# 16개 index 가 빠짐없이 한 번씩 PASS 인가
awk -F, 'NR>1 && $12=="PASS"{print $2}' build_log.csv | sort -n | uniq -c
```
기대: `1..16` 각 1회 + `99` 1회. **중복이나 누락이 그 자리에서 보인다.**

## 2. 감지부 실측 좌표 기록

**조용히 틀릴 수 있는 것**
- 라벨(n01~n16)과 `deploy_config.json` 의 `id`(0~15) 를 **한 칸 어긋나게** 적는다 → 전체 좌표가 회전/평행이동
- x·y 를 바꿔 적는다 → 방향이 축 대칭으로 뒤집힌다
- 한 노드만 오타 → 그 노드의 국소 적합만 오염 (**전역은 멀쩡해 보인다 — 가장 안 보이는 경우**)

**알아챌 수단 — 없다** ❌ 좌표는 추정의 입력이라 **틀려도 결과가 그럴듯하게 나온다.**

**추가할 것 — `gateway.py` 시작 로그에 좌표 자기검사 3줄**
```
[cfg] nodes=16  x범위 0.00~0.60  y범위 0.00~0.60  간격 중앙값 0.200
[cfg] 격자 규칙성: 행4 열4 · 이웃수 분포 {3:4, 5:8, 8:4}
[cfg] ★ 라벨 규약: nXX -> id XX-1  (n01->id0)
```
- **간격 중앙값**이 0.20 에서 벗어나면 오타
- **이웃수 분포**가 `{3:4, 5:8, 8:4}` 가 아니면 격자가 깨진 것
- 둘 다 **한 노드만 틀려도 분포가 바뀐다**

## 3. D1 리허설

**조용히 틀릴 수 있는 것**
- 노드가 죽었는데 **사망 확정(DC)이 안 올라온다** — 화면은 그냥 조용하다
- 사망시각이 `nt`(메시 동기)가 아니라 `t`(로컬 millis)로 실려 온다 → 노드 간 비교가 깨져 방향이 틀린다
- 게이트웨이가 사망을 **비화재로 기각**한다 (3분기 선별) — 기각도 조용하다
- 브라운아웃으로 노드가 재부팅 → 사망이 아니라 부활인데 로그만 보면 구분 안 된다

**알아챌 수단 — 대부분 이미 있다** ✅
- `fw_adapter` 가 `time_source` 를 META 에 싣는다 → `local_millis` 면 경고를 쌓는다
- `gateway_deaths.csv` 에 `accepted` · `branch` · `t_source` 가 남는다
- 노드 배너에 `reset_reason` 이 찍힌다 → `BROWNOUT` 이면 전원 문제

**추가할 것 — 리허설 끝에 한 줄 요약** (`gateway.py` 종료 시)
```
[run] 사망 16 / 채택 16 / 기각 0 · t_source: last_gasp 14, last_heartbeat 2, UNRELIABLE 0
[run] time_source=mesh_nodetime · 경고 0건 · 랩어라운드 0회
```
**`UNRELIABLE` 이 1건이라도 있으면 그 노드의 사망시각은 못 쓴다** — 지금은 이게 안 보인다.

## 4. 데모 촬영

**조용히 틀릴 수 있는 것**
- 임시 임계 40 ℃ 로 촬영한다 → 영상은 멀쩡한데 **보고서의 80 ℃ 서술과 어긋난다**
- 노드 하나가 조립 불량으로 처음부터 안 붙어 있는데 **아무도 모른 채 15노드로 찍는다**
- 게이트웨이가 안 돌고 있는데 **보드 LED만 보고 잘 되는 줄 안다**
- 촬영본이 합성 모드(`FAKE_TEMP_RAMP=1`)로 구워진 보드를 포함한다

**알아챌 수단**
- `fake=0` 이 줄마다 찍힌다 ✅ (D-046)
- `TOPO` 의 `n_peers` 로 참여 노드 수를 볼 수 있다 ✅

**추가할 것 — 촬영 직전 30초 점검** (새 코드 없음, `watch_node.ps1` 로 이미 가능)
```powershell
.\watch_node.ps1 -Seconds 30 -Label precheck
```
확인 4가지:
```
[ ] n_peers = 16        (한 대라도 빠지면 여기서 보인다)
[ ] fake=1 이 0건
[ ] death_threshold_c = 80.0
[ ] BOD/rst: 0건        (촬영 중 재부팅 = 재촬영)
```
