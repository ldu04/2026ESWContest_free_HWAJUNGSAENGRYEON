## 0. 한 줄 정체성

> **본체(플랫폼):** 노드의 **고장(죽음)을 숨겨야 할 결함이 아니라, 시스템의 1급 데이터로 승격**시키는 자가치유 메시 네트워크.
> **사례(데모):** 산불 최전선 실시간 지도 — 불에 타 죽는 센서 하나하나가 마지막 신호로 "불이 여기까지 왔다"를 알리고, 파괴돼도 남은 망은 스스로 복구해 계속 전송한다.

**작품명 후보(팀에서 택1):** `PhoenixNet` · `불씨(BULSSI)` · `LastGasp` · `잿불`
> ※ 팀명 규칙: 20Byte(한글 10자) 이내 / 띄어쓰기·특수문자·"테스트/TEST" 불가 / 영문은 대문자 / 끝에 '팀' 불가.

**핵심 문장 (30초 발표용):**
"기존 재난 센서망은 불이 나면 센서가 타버려 통신이 끊기는 걸 '막아야 할 단점'으로 봅니다. 저희는 그 **죽음을 뒤집어 최전선 데이터로 씁니다.** 노드가 죽는 시점과 좌표가 곧 화재 전선의 이동 궤적이고, 노드가 파괴돼도 망은 스스로 복구해 데이터를 계속 내보냅니다."

## 1. 포지셔닝 — 왜 "산불 시스템"이 아니라 "플랫폼"인가

산불은 **사례 1**일 뿐이다. 핵심 문장은 응용이 바뀌어도 안 바뀐다:

> **"고장난 노드는 버리는 것이 아니라, 고장 자체를 시스템 정보로 활용한다."**

- 사례 1: 산불 (죽음 = 화재 전선) ← **6주 데모**
- 사례 2: 화학공장 유독가스 누출 (죽음 = 확산 경계) ← 발전 방향
- 사례 3: 홍수·침수 (물 닿는 순간 마지막 좌표) ← 발전 방향

→ 임베디드SW 대회는 SW 아키텍처의 깊이를 높게 봄. "산불 감지기"보다 **"고장을 정보로 승격하는 네트워크 플랫폼"**이 기술적으로 더 깊어 보인다.

## 2. ★ 최종 보스 방어 (반드시 발표에 내장)

> **심사위원 질문: "왜 죽을 때까지 기다려요? 살아있을 때 온도 계속 보내면 되잖아요?"**

이 질문에 "죽음은 마법 데이터"로 답하면 **죽는다.** 아래 3겹으로 답한다:

1. **규모·전력:** 수백~수천 개 *초저가 일회용* 노드는 상시 스트리밍이 불가능(전력·대역폭 한계). 그래서 **이벤트 구동** — 평소 침묵, 임계(고온) 때만 마지막 관측을 쏜다.
2. **확정성:** 살아있는 노드의 온도는 "가까워지는 중"이라는 *애매한 gradient*지만, 노드의 소실(이웃 교차검증)은 "전선이 여기를 지났다"는 **명확한 이진(binary) 마커**다. 애매한 아날로그보다 확정적이다.
3. **주인공 교체:** 그래서 핵심은 '죽음을 기다린다'가 아니라, **"고장 이벤트를 결함으로 숨기지 않고 데이터로 승격 + 그 손실을 견디는 자가치유"라는 아키텍처**다.

→ "failure-as-data 아키텍처"로 프레이밍하면 이 질문이 녹는다.

## 3. 시스템 아키텍처

```
[초저가 노드 x N (ESP32 + 열센서 + 슈퍼커패시터)]
        │  평소: 저전력 침묵 / 하트비트
        │  임계(≥80℃) 또는 전원 급강하 감지
        ▼
[Last-Gasp 패킷]  (id, 좌표, 마지막 관측, timestamp, Priority-0)
        │  ← 슈퍼커패시터 잔여 전력으로 1패킷 송신 후 사망
        ▼
[자가치유 라우팅]  이웃이 침묵 감지 + 교차검증 → 죽은 노드 우회 재라우팅(<300ms)
        │           + 죽음을 '이벤트'로 승격(토폴로지 갱신 + 마지막 데이터 보존 전파)
        ▼
[Sink/게이트웨이] → [웹 대시보드]
        ├─ 실시간 토폴로지 + 자가치유 애니메이션(노드 죽으면 경로 우회)
        └─ 죽음 좌표·시각 → 화재 전선 벡터(방향·속도) 역추정 지도
```

**4대 SW 모듈 (우리 코드의 핵심):**
1. **Last-Gasp 메커니즘** — 임계 감지 → 잔여전력 임종 패킷.
2. **Failure-as-Event 자가치유 라우팅** — 죽음을 침묵 처리(stock)가 아니라 *1급 이벤트*로 처리(우리 차별점).
3. **화재 전선 추정** — 죽음 좌표·시각 패턴 → 이동 벡터(방향·속도) 역산.
4. **실시간 대시보드** — 토폴로지·자가치유·전선 시각화.

## 4. 차별화 (심사 독창성·기술성 방어)

| 구분 | 기존 산불 WSN 연구 | 기존 재난 Mesh | **우리 (Failure-Aware Mesh)** |
|---|---|---|---|
| 노드 파괴 대응 | 방열재로 안 타게 | 통신 단절 복구에만 집중 | **파괴 자체를 1급 데이터로 수집** |
| 전선 추정 | 살아있는 온도 gradient | 단순 수신여부 | **사망 시공간 좌표 벡터 역추정** |
| 라우팅 | 고정 트리(중앙 죽으면 붕괴) | 일반 ad-hoc | **사망 노드 회피 특화 자가치유** |

> "그냥 ESP-MESH 아니냐" 방어: 우리는 stock 위에 **failure-as-first-class-event 계층**(죽음 데이터 승격 + 전선추정)을 얹음. **"우리 프로토콜 vs stock" 비교실험 수치**를 보고서에 넣는다.

## 5. 데모 설계 (6주 "국소적 성공")

- ESP32 노드 **8~10개**를 격자로 배치(축소판 = 수천 노드 개념 증명엔 충분).
- 순차 "사망" 트리거: (실기술) 헤어드라이어/열원으로 열 임계 유발 → Last-Gasp 발동, 또는 (백업) 물리 스위치.
- 대시보드에서 눈앞에 보이는 것:
  1. 불 전선이 격자를 가로질러 번짐(죽는 노드 순서).
  2. 죽은 자리를 우회해 망이 **자가치유**(경로 애니메이션).
  3. 죽음 좌표·시각 → **화재 전선 벡터** 실시간 갱신.
- **정량 지표:** "노드 N개 사망에도 전달률 X%, 재라우팅 Y ms, 전선 방향·속도 추정."

## 6. 심사 배점 매핑 (100점)

- **독창성 30:** "고장을 정보로 승격"이라는 역발상 패러다임 + 죽음→화재전선. 명확한 차별 서사.
- **기술성·완성도 30:** 자가치유 라우팅 + Last-Gasp + 전선 벡터 추정 + ESP32 실물. **SW가 주인공**(대회 최적).
- **활용성 20:** 산불 재난 사회가치 + **플랫폼이라 확장(가스누출·홍수·구조) → 발전가능성** 강함.
