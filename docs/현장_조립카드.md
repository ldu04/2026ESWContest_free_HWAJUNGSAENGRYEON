# 현장 조립 카드 — 물리 배치 확정값

> 이 파일은 대화 압축과 무관하게 남는다. 물리 배치에 관한 결정은 전부 여기에 적는다.
> 새 세션/새 대화는 이 파일부터 읽는다.

## 좌표계 (혼동 주의 — 두 개가 공존한다)

| 프레임 | 원점 | 노드 위치 | 쓰는 곳 |
|---|---|---|---|
| **시스템** | 격자 좌하단 노드(n01) | 0 / 20 / 40 / 60 cm | `gateway/deploy_config.json`, 대본 B, 추정기 |
| 판 눈금 | 판 왼쪽 아래 모서리 | 5 / 25 / 45 / 65 cm | `spec.html`, 판에 그은 5cm 눈금 |

- 두 프레임은 정확히 (5, 5) 만큼 어긋난다. 격자 간격은 둘 다 20 cm.
- 사진의 판에 적힌 `O(0,0) / 20 / 40 / 60` 은 **시스템 프레임**이다.
- 대본 B 점화점 `(0.02, -0.11) m` 도 시스템 프레임. 반경 검산 91.68 / 11.18 cm 로 확인됨.
- **실측 좌표는 시스템 프레임(n01 = 0,0)으로 기록한다.**

## 노드 하나의 배치 (확정)

기준 자세: **열풍기 쪽에 서서 판을 바라봄** (허브·라즈베리파이가 건너편).

| 무엇 | 자리 | 근거 |
|---|---|---|
| 감지부(온도센서) | 격자점, 높이 34 mm | spec 치수 정본 |
| **ESP32** | 격자점에서 **옆 3 cm**, 세로로 세움(긴 쪽이 앞뒤), USB 포트는 뒤쪽 | 다리·제트 회피 |
| ESP32 방향 | **전부 안쪽** — 1·2열은 x +3 cm, 3·4열은 x −3 cm | 아래 표 참조 (2026-08-30 확정) |
| LED | **ESP32 앞 끝에서 1 cm 앞, ESP32와 같은 x 라인** (2026-08-30 변경) | 마스트 그림자 회피 + 배선 단축 |
| 라벨 | 격자점 앞 5.5 cm | LED 자리 회피 |
| USB 케이블 | ESP32 뒤쪽 포트 → **노드 열 띠를 따라 곧게 뒤로** | 다리는 x 15/35/55 에만 선다 |
| 테이프 | 센서에서 8~10 cm 지점 하나, **터널식** | 눌러 붙이면 비틀림이 센서로 전달 |


### LED 위치 변경 (2026-08-30)

기존: 격자점 −y 3 cm → 변경: **ESP32 앞 끝에서 1 cm 앞, ESP32와 같은 x 라인**
(노드 기준 대략 x ±3 cm / y −3.75 cm)

이유:
- 격자점 바로 앞(−y 3 cm)에 두면 34 mm 감지부 마스트가 카메라(+y, 부감)와 LED 사이에 서서
  부감 49° 미만에서 가려진다. x로 3 cm 비키면 그 제약이 사라진다.
- ESP32 바로 앞이라 배선이 짧아진다.
- 제트 착탄점(센서 +y 4 cm)에서 더 멀어져 열에도 유리하다.
- 앞을 막는 건 눕힌 ESP32(높이 약 5 mm)뿐이라 45° 부감이면 넘어간다.

★ **LED 좌표는 추정에 쓰이지 않는다.** 추정기는 감지부 좌표만 쓴다.
   그래서 mm 단위로 맞출 필요가 없고, 노드마다 점퍼선이 지나가는 자리를 피해
   눈대중으로 비켜 놓아도 된다.

### ESP32 좌우 방향 — 확정 (2026-08-30)

"오른쪽/왼쪽"은 서 있는 위치에 따라 뒤집히므로 **판 좌표 x**로 쓴다.

| 열 | 노드 x | ESP32 방향 | ESP32 중심 x |
|---|---|---|---|
| 1열 n01·n05·n09·n13 | 5 | x 증가 방향 +3 | 8 |
| 2열 n02·n06·n10·n14 | 25 | x 증가 방향 +3 | 28 |
| 3열 n03·n07·n11·n15 | 45 | x 감소 방향 −3 | 42 |
| 4열 n04·n08·n12·n16 | 65 | x 감소 방향 −3 | 62 |

근거:
- **다리는 방향 선택과 무관하다.** 노드가 양쪽 다리 레인(각 10 cm)의 정중앙이라
  좌우 어느 쪽으로 빼도 다리까지 거리가 같다.
- 유일한 제약은 **판 가장자리**. 바깥쪽으로 빼면 1열(중심 2, 모서리 0.75)과
  4열(중심 68, 모서리 69.25)이 판 끝에서 0.75 cm 밖에 안 남아 둘 다 깨진다.
- 안쪽으로 통일하면 좌우 대칭이고 케이블이 가운데로 모여 허브까지 합쳐진다.
- ※ spec.html 의 「1·2·3열 +x / 4열 −x」는 이전 표기다. 여유는 동일하나
  대칭성 때문에 위 표를 따른다.

**밀지 말 것**: 다리 ↔ ESP32 여유 1.7 cm. 바깥으로도 앞으로도 안 된다(앞다리가 격자점 앞 13.5 cm).

## LED 모듈 (사진 확인 2026-08-30)

- 원형 WS2812B 브레이크아웃, **핀 헤더 없음 — 납땜 필요**.
- 뒷면 패드: `5V(+)` · `gnd(−)` · `Din` · `Dout`
- **쓰는 것은 3개: 5V, gnd, Din. Dout 은 비운다** (노드당 LED 1개, 체인 아님).
- 펌웨어: `PIN_NEOPIXEL 5` (GPIO5), `Adafruit_NeoPixel led(1, ...)`
- 전원: **3.3V 먼저 시도**. 데이터가 3.3V 로직이라 레벨이 맞고 전류도 적다.
  안 켜지거나 색이 이상하면 그때 5V.
- 총 납땜 48점 = 16 × 3.
- **판에 붙이기 전에, 판 밖에서** 납땜한다.

## ★ 받침대 운용 (2026-08-31 확정) — 체류 21초 · v 0.523 mm/s

| | |
|---|---|
| **고정 3장** | 다리 레인 **15 / 35 / 55** 앞쪽. 런 내내 그대로 둔다 |
| **유동 1세트** | **◀왼쪽 = n05 · n09 · n13** / **오른쪽▶ = n08 · n12 · n16** |

**이동 3회. 전부 여유 55초 이상.** 「그 노드 끝나고 여유 있을 때」 하면 된다.

| 시점 | 어디로 | 다음 가열까지 여유 |
|---|---|---|
| **런 전** | **◀ 왼쪽** | — |
| **13:46** (n10 사망 후) | **오른쪽 ▶** | **75 초** (n04 가열 15:01) |
| **17:35** (n08 사망 후) | **◀ 왼쪽** | **74 초** (n13 가열 18:49) |

**거치 = 가열 시작.** 미세조정은 1초면 되므로 「거치 완료 목표」를 따로 두지 않는다.

### ★ 빡빡한 곳은 하나뿐 — `n07 → n09` : **10초에 45.1 cm**

판을 가로질러 대각선. **여기만 연습하면 된다.**

> 다리 레인 15/35/55 는 **사용자 결정**이고 실측 기록이 없다. 판 위에서 대보고 확정할 것.

상세 동선표: `docs/D1_리허설_절차서.md` §1-B

## ★ LED 전수 확인 — **16/16 초록** (2026-08-31)

**판 위 16대 전부 초록.** 흰색·꺼짐 0건. 같은 시각 메시 점호도 **16/16 + 브리지**로 일치했다.

두 증거가 서로 다른 것을 보증한다:

| 증거 | 보증하는 것 |
|---|---|
| **LED 초록** | `setup()` 완주 = 부팅 · 3V3 레귤레이터 · LED 배선 정상 |
| **HB 도착** | 무선(메시 합류) 정상 |

**둘 다 통과한 것은 이번이 처음이다.** 여기까지 온 경위:
n04 는 GPIO5 불량으로 **GPIO18** 로 옮겨 구웠고(D-072), n01 은 보드가 5V–GND 단락이라
**보드를 교체**했다. 나머지 14대는 손대지 않았다.

> `TOPO n_peers` 는 같은 시각 마지막 표본에서 0 으로 찍혔다. 이는 이미 기록된
> **n_peers 요동**(16/17/7/12/5/13/11/8/0/11)이고, **HB 16/16 이 더 단단한 증거**다.
> **n_peers 를 합류 판정에 쓰지 말 것.**


## 보조배터리 — **「자동 차단」은 오진이었다** (2026-08-31 정정)

n01 · n05 의 LED 가 꺼져 있었을 때 **「보조배터리가 저전류에서 스스로 꺼진다」고 결론지었으나
그것은 틀렸다.** 진짜 원인은 **n01 보드의 5V–GND 단락**이었다.

| 관찰 | 옛 해석 (틀림) | **실제** |
|---|---|---|
| 2대 물리면 배터리가 오류 | 저전류 자동 차단 | **n01 단락에 보호회로가 걸린 것** |
| 1대만 되고 2대째에 터짐 | 2구 동시 출력 한계 | **n01 이 끼는 순간에만 발생** |
| LED 꺼짐 | 전원 차단 | 단락으로 **부팅 자체를 못 함** |

**보드를 교체한 뒤 n01 · n05 가 같은 배터리에서 정상 동작한다.**
따라서 **이 배터리를 쓰지 못할 이유가 없다.**

### 남겨 둘 것

- 저전류 자동 차단은 보조배터리 일반의 **알려진 특성**이지만, **이 제품에서 관측된 적은 없다.**
  근거 없이 위험으로 취급하지 않는다.
- 16노드 소크에서 **n13(충전기)이 마지막 28초를 못 채운 것**은 **별개이고 원인 미상**이다.
  배터리와 무관하며, 리허설에서 다시 보면 된다.

### 어떻게 오진했나 — 다음에 피할 것

증상 두 개(LED 꺼짐 · 배터리 오류)를 보고 **공통 원인을 배터리 쪽에서 먼저 찾았다.**
실제로는 **노드 쪽 단일 고장**이 두 증상을 다 만들고 있었다.
**「어느 부품을 끼는 순간에만 나는가」를 먼저 가르는 편이 빨랐다** — 실제로 사용자가
그 방법(n01만 빼기)으로 한 번에 좁혔다.

## ★ 전원 배치 — **확정** (2026-09-01, 사용자 결정)

| 전원 | 노드 |
|---|---|
| **보조배터리** | **n01 · n05** |
| **충전기** | **n04 · n08 · n13** |
| **허브 11구** (왼쪽부터 순서대로) | **n12 · n16 · n03 · n07 · n11 · n15 · n02 · n06 · n10 · n14 · n09** |
| **파이 USB** | **브리지(99)** |

합계 2 + 3 + 11 = **16 노드** + 브리지 1 = 17.

**왜 적어 두나**: 8/31 에 11구 허브 하나로 몰았다가 **브라운아웃 재부팅 44회**를 냈다
(`docs/소크_11구허브_20260831.md`). 전원을 어디서 받는지는 **산출물에 안 남으므로**
사람이 적지 않으면 다음 회차에 재현할 수 없다.

**허브 순서를 적어 둔 이유**: 어느 구멍이 약한지 나중에 가르려면 「왼쪽부터 몇 번째」가
있어야 한다. 이탈이 특정 노드에 몰리면 그 자리를 의심한다.

> ★ **브리지는 파이에 꽂는다** — 촬영 경로와 같아야 하기 때문이다.
> 노트북 게이트웨이는 **폴백으로 유지**한다. 전환 절차는 `docs/D1_리허설_절차서.md` §4-0.

## 판단 규칙 (2026-08-31 추가 — 실패에서)

**되돌리기 어려운 판단은 계측 먼저.**
범위 축소·포기·전면 재작업을 제안하기 전에는 반드시 로그나 계측을 먼저 본다.
증상만으로 원인을 정하지 않는다.

계기: LED 8/11이 흰색이던 건을 "납땜 불량"으로 보고 LED 포기를 권했으나,
시리얼 로그를 읽자 **그 보드들에 node.ino가 안 구워져 있었던 것**으로 확정됐다.
납땜은 멀쩡했다. 로그는 처음부터 읽을 수 있었고 30초짜리였다.

부수 규칙:
- "개별 문제가 아니라 공통 원인"이라고 판단했으면, 그 공통 원인을 찾기 전에는
  다음 결론으로 넘어가지 않는다.
- 사용자가 진단에 이의를 제기하면 가설을 밀지 말고 계측을 늘린다.
